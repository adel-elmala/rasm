Coordinate spaces and the view matrix

A vertex is stored in its mesh's own coordinates. Before it becomes a pixel, it passes through five more coordinate systems. Each step is one matrix or one simple formula. This page explains every space, which way its axes point, and how the camera's view matrix is built. The last part shows how RASM does it.

In short

  • The chain is object → world → view → clip → NDC → pixels. The model, view and projection matrices do the first three steps. The GPU does the last two.
  • A right-handed, Y-up world has X right, Y up and Z toward you. A camera there looks down its own −Z.
  • The model matrix is T · R · S: scale first, then rotate, then move.
  • The view matrix is the inverse of the camera's own world matrix. For a camera without scale it is RT · translate(−eye).
  • A quaternion stores a rotation in 4 numbers. Its inverse is its conjugate, and it blends smoothly (slerp).
  • Vulkan's clip space has Y down; OpenGL, Direct3D and Metal have Y up. Engines fix this with a negative viewport height or a flip in the projection.

1The chain of spaces

A space is a coordinate system: an origin and three axes. The same point has different numbers in different spaces. Rendering moves every vertex through a fixed chain of them. Each arrow below is one transform.

2Axes and handedness

Three axes at right angles can be arranged in two ways that are mirror images of each other. Point X to the right and Y up. Then Z points either toward you or away from you. The first is right-handed, the second left-handed. Curl the fingers of that hand from X to Y, and the thumb shows Z.

Neither choice is better. What matters is that every part of a program agrees. Tools and file formats chose differently:

Tool or formatHandednessUp axis
glTF 2.0right+Y (a model's front faces +Z)
OpenGL tradition, Mayaright+Y
Blender, 3ds Maxright+Z
Unityleft+Y
Unreal Engineleft+Z

Converting between two of them is a fixed matrix: a rotation for a different up axis, and a mirror (one negated axis) for a different handedness. A mirror also reverses the winding of every triangle, so it changes face culling. See Face culling and winding order.

3Object to world: the model matrix

An object is placed in the world with three parts: a scale S, a rotation R and a translation T. With column vectors (the convention of OpenGL, glm and most math books), a point is transformed as p′ = M · p, and the model matrix is

M = T · R · S        p_world = T · (R · (S · p_object))

Read it from right to left: the matrix next to the point acts first. So the object is scaled around its own pivot, then turned, then moved. The order matters:

A hierarchy (a wheel on a car, a node tree in a glTF file) multiplies the matrices of all parents: Mwheel = Mcar · Mwheel in car. A child under a parent with a non-uniform scale can end up with shear, which no single T · R · S can describe. That is why engines often store full matrices for world transforms.

Row or column vectors

Some texts (classic Direct3D, DirectXMath) write p′ = p · M, with the point as a row. Then every matrix is the transpose, and products are read left to right: M = S · R · T. It is the same math with the other notation.

Row-major or column-major

A separate question: how the 16 numbers sit in memory. glm and GLSL store columns one after the other, so m[3] is the translation column. Mixing up the storage order transposes the matrix without any error message.

5The view matrix

A camera is an object like any other. It has a position eye and a rotation R, so it has a world matrix C = T(eye) · R. That matrix takes points from the camera's space to the world. Rendering needs the opposite: points from the world into the camera's space. So the view matrix is the inverse:

V = C⁻¹ = (T · R)⁻¹ = R⁻¹ · T⁻¹ = Rᵀ · T(−eye)

Two facts make this cheap. The inverse of a translation is the translation by the negative vector. The inverse of a rotation matrix is its transpose (for a quaternion: its conjugate). No general 4×4 inverse is needed.

Building it with lookAt

Often the camera is given as "stand at eye, look at target, with up roughly up". The three axes of the camera follow from cross products:

The rows of RT are the camera's axes, and the last column is RT · (−eye):

      |  r.x   r.y   r.z   −r·eye |
V  =  |  u.x   u.y   u.z   −u·eye |
      | −f.x  −f.y  −f.z    f·eye |
      |  0     0     0      1     |

Each row asks one question about a world point p: how far is it to the right (r), up (u), and behind (−f) the camera? A point in front of the camera gets a negative z.

6Clip space, NDC and pixels

The projection matrix turns view space into clip space. Its main job is to put the distance in front of the camera into w, so that the GPU can divide by it: far things get smaller. The details are in Projection and reversed-Z depth. Here we only need the last two steps, which the GPU does after the vertex shader:

NDC:     (x_n, y_n, z_n) = (x_c, y_c, z_c) / w_c

pixels:  x_p = vx + (x_n + 1) / 2 · width
         y_p = vy + (y_n + 1) / 2 · height        (the API's own y direction)
         depth = minDepth + z_n · (maxDepth − minDepth)

The viewport rectangle (vx, vy, width, height) and the depth range come from the application. Pixel centers sit at half-integers: the top-left pixel covers 0..1 and its center is (0.5, 0.5).

Objects turn around the world origin instead of their centerThe matrix order is wrong: R · T instead of T · R.
The model is mirrored, or inside outData from a tool with the other handedness, converted with a rotation only.

10In RASM

RASM uses the glTF convention: a right-handed, Y-up world, and a camera that looks down its local −Z. Transforms are a position, a quaternion and a scale. Clip space is Y-up on every backend; the Vulkan backend flips Y with a negative viewport height (fix A).

Keep these true
  • Clip space is Y-up everywhere. Pass a normal, top-left rectangle to setViewport; the backend flips it. Do not flip again in a projection.
  • A shader that writes a clip position by hand uses Y-up (+1 is the top row).
  • Do not mirror imported data to change handedness. A mirror flips the winding, and face culling depends on it (Face culling).
  • glm config macros belong in CMake, not in a .cpp (B2).
  • Transform math is covered by tests/transformTests.cpp and tests/cameraTests.cpp.
