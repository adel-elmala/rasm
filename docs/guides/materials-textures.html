Materials and bindless textures

A material is a small CPU record: six texture handles and ten floats. The engine turns it into one 84-byte row of the GPU material table. In that row, each texture handle is replaced by a slot number in one big array of textures. The shader reads the row and samples the slots directly.

CPU work / CPU data GPU work GPU buffer / descriptors shader entry point

In short

  • rasm::Material holds textures[MAX_TEXTURE_SLOTS] (indexed by PbrSlot), texCoords[], params[MAX_PARAM_SLOTS] (indexed by PbrParam), a MaterialType and doubleSided.
  • writeMaterialRow converts it (convertToGfxMaterial, getGfxMaterialId) and writes row handle.index of the material table with GpuTable::setRow.
  • All textures live in one descriptor set: gTextures[], 1024 combined image samplers. A texture gets a slot once, from addBindlessTexture. Slots are never freed.
  • "No texture" is INVALID_TEXTURE_INDEX (0xFFFFFFFF). The shader then uses the glTF default for that slot.
  • Color and emissive textures are R8G8B8A8_SRGB. Normal, metallic-roughness and occlusion are R8G8B8A8_UNORM.
  • An entity is drawn only when all textures of its materials are loaded.

1One material, three views

writeMaterialRow runs from createMaterial, loadMaterial (glTF) and updateMaterial. It only marks the row dirty. syncGpuScene uploads dirty rows into the buffer of the current frame slot, after that slot's fence wait (see the GPU scene tables). A change made after beginFrame is visible in the next frame.

2The CPU record: slots and params

Texture slots (PbrSlot)

The slots follow the glTF textures: base color, metallic-roughness, normal, occlusion and emissive. The one metallic-roughness texture goes into both METALLIC and ROUGHNESS.

Each slot also has a texCoords[slot]: which UV set (0, 1 or 2) the texture uses. A value of MAX_VERTEX_UV_SETS (3) or more becomes 0. In the shader, selectUV picks the matching interpolated UV.

Params (PbrParam): one flat float array

createMaterial sets white albedo, metallic 0, roughness 1, normal scale 1 and occlusion strength 1, so a texture is not multiplied by zero. loadMaterial copies the glTF factors instead: baseColorFactor, metallicFactor, roughnessFactor, the normal texture's scale, the occlusion texture's strength and emissiveFactor.

3Handles become slot numbers

The GPU does not know texture handles. When convertToGfxMaterial builds the row, it asks getBindlessTextureIndex for each slot's texture. The answer is the texture's place in the gTextures[] array, or UINT32_MAX when the handle has no place (also for an invalid handle).

4The bindless descriptor set

The engine makes one descriptor set at startup, and every material uses it. The uber pipeline binds it once per drawScene call (twice with occlusion culling), and the Hi-Z build binds it to its compute pipeline.

How a slot is chosen

  • When "next" reaches 1024, updateBindlessDescriptorSet logs "Slot index exceeds maximum bindless textures." and returns UINT32_MAX.
  • Who takes slots: createMaterial (each valid texture it gets), updateMaterial (only textures without a slot), loadMaterial (each uploaded glTF texture), and createRenderTarget (each color attachment, with LINEAR_CLAMP). With occlusion culling, drawScene also adds the pass's depth texture (NEAREST_CLAMP) the first time it culls with it. A swapchain depth texture replaced by a resize takes the old one's slot.
  • loadTexture does not take a slot. The texture gets one when a material uses it.
Slots are never freed (D4)

There is no destroy API for textures or materials, so a slot stays used for the life of the engine. Note also that createMaterial calls addBindlessTexture for every valid texture, even one that already has a slot. A texture passed to two createMaterial calls takes two slots, and the map keeps the newer one. updateMaterial checks first, so it does not do this.

6Color spaces

Color data: sRGB

Base color (ALBEDO) and EMISSIVE are R8G8B8A8_SRGB. The GPU converts them to linear when the shader samples them. loadTexture uses R8G8B8A8_SRGB by default.

Non-color data: UNORM

Normal, metallic-roughness and occlusion maps are R8G8B8A8_UNORM. Their values are used as they are. Loading a normal map as sRGB bends every normal.

  1. Textures in. loadTexture accepts only R8G8B8A8_SRGB or R8G8B8A8_UNORM, and logs an error for any other format. glTF images with fewer than 4 channels are expanded to RGBA8 before upload.
  2. Shading in linear. All lighting math in pbr.slang is in linear color. Factors in params are linear too (glTF 2.0).
  3. Color out. The shader returns linear color. The swapchain is B8G8R8A8_SRGB, so the hardware encodes it to sRGB on write. A shader must never apply the sRGB curve itself.

The mip chain is made on the CPU when the texture is filled, in linear light for sRGB formats. See how data reaches the GPU for the upload path.

To add a shading path

  1. Add the value. Add it to gfx::MaterialId in src/renderer/uberMaterialTypes.h and to its mirror in shaders/lib/core.slang, with the same number.
  2. Map it. Map it in getGfxMaterialId (src/renderer/gpuScene.cpp), usually from a new MaterialType.
  3. Branch on it. Branch in fragMain (shaders/passes/rasm.slang) and put the shading function in shaders/lib/.

8updateMaterial and entities waiting for textures

An entity is drawn only once every texture of every material it uses is loaded, so nothing appears half-textured. updateMaterial can give a material a texture that is still loading. Here is what happens to entity E, which uses material M, when the app sets a new albedo texture T that is still decoding.

1. updateMaterial(M, values)

updateMaterial copies the new values over the registry record, keeps the handle, and calls writeMaterialRow. The row index does not change, so no instance row changes.

2. refreshEntitiesAfterMaterialChange

E disappears from the image until T is ready. The function also recomputes every entity's cull modes, because doubleSided picks the cull mode.

3. finishLoads: T is decoded

The flag tells syncGpuScene that it is worth checking the waiting entities again. Without a finished texture, it does not check them.

4. syncGpuScene: E comes back

From this frame on, E draws with T. Changing only factors (colors, roughness) never makes an entity wait: example 03_instances changes a material's albedo every frame.

9The default material and glTF import

The default material

The engine creates it at startup with createMaterial(MaterialType::PBR), then sets METALLIC to 1: the glTF default material (white, metallic 1, roughness 1). getMaterial returns it for an invalid handle. A glTF primitive without a material uses its entity's material, and an entity without one ends up here.

The glTF import cache

Each glTF import has a GltfImportCache. Materials are cached by glTF material index, so primitives that share a material share one MaterialHandle. Textures are cached by image, sampler and color space (below), so they share bindless slots too.

loadMaterial runs on the main thread, inside finishLoads, after the worker parsed the file (see loading assets). It creates each texture with createTexture, fills it with fillTexture at once, and gives it a slot. A glTF texture is therefore loaded before any entity can use the material. A UV set of MAX_VERTEX_UV_SETS or more logs a warning and falls back to set 0. An image that is not 8 bits per channel logs an error, and the material gets no texture in that slot.

11Rules when you change it

Keep these true
  • Normal, metallic-roughness and occlusion textures are R8G8B8A8_UNORM; color and emissive are R8G8B8A8_SRGB. Shaders output linear color.
  • Write material rows only through writeMaterialRow (which calls GpuTable::setRow). Never write a slot's buffer directly; syncGpuScene uploads it after the fence wait.
  • A new field in gfx::Material or MaterialData is a CPU↔GPU struct change: update uberMaterialTypes.h, core.slang, the static_asserts and validateRasmStructs together. See the struct contract.
  • A texture without a slot must stay INVALID_TEXTURE_INDEX in the row, so the shader takes the glTF default. Never store 0 for "none": slot 0 is a real texture.
  • A new MaterialId needs the same number on both sides, a case in getGfxMaterialId and a branch in fragMain.
Not done yet

No destroy API for textures and materials, and no slot reuse (D4). No compressed textures, and mips are made on the CPU on the main thread (P2). Limits are fixed at compile time: 256 materials, 1024 slots (D15).
