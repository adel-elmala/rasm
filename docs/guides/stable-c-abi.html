Foundations

A stable C ABI

A program compiled today should keep working with the library built next year, and a Python script should call a library written in C++. Both need a stable ABI: a binary interface whose rules do not change. C++ does not give one; C does. This page explains why, and the small set of rules a C facade over a C++ library follows. The last part shows RASM's.

In short

  • The API is what the source code sees; the ABI is what the machine code sees: symbol names, the layout of every struct, how arguments travel, who frees what.
  • C++ types (std::string, classes, exceptions, templates) have layouts and names that differ between compilers and versions. C has one plain layout per platform, which every language can call.
  • A C facade hides objects behind opaque pointers and names them by integer handles; it uses only fixed-size types.
  • A struct that may grow starts with its size, so an old program and a new library agree on what each one knows.
  • No exception crosses the line: errors become codes and a per-thread last error.
  • Memory stays with whoever made it: inputs are borrowed for the call, outputs go into the caller's buffers.
  • A version number and the rule "only add at the end" keep old binaries working.

1The problem: C++ has no stable ABI

A C++ library compiled into a shared library exposes its machine-level interface. Four parts of it change from one compiler, standard library or library version to the next.

Mangled names

C++ encodes the parameter types into the symbol name, and each compiler family encodes them its own way. A C function is just its name.

Standard library layouts

A std::string or std::vector passed across the line must have the same layout on both sides. It does not between MSVC's STL, libc++ and libstdc++, or between debug and release.

Exceptions

An exception unwinds through the caller's stack frames. A C, Python or Rust caller has no handler for it, and unwinding through foreign frames is undefined.

Class layouts and vtables

A new member, a new virtual function or an inline method changes sizes and offsets that the caller compiled in. The program and the library then disagree about memory.

Rebuilding everything with one compiler hides these problems for a C++ program that links a static library. It does not help a Python script, a C# game or a program shipped last year.

2C as the common language

Every platform has one C calling convention and one C struct layout, written down in its ABI document. Every language can call it: Python's ctypes, C#'s P/Invoke, Rust's extern "C", Zig, Go, Java's FFM. So the library keeps its C++ inside, and offers a facade: a header of plain C functions and structs, compiled with extern "C", so each function's symbol is just its name.

The facade is thin: each C function checks its arguments, converts them to C++ types, calls one C++ function and converts the result back. It adds no engine features, so it stays easy to keep in step with the C++ API.

3Objects: opaque pointers and integer handles

The caller must hold the library's objects without knowing their layout. There are two ways, and a facade often uses both.

Opaque pointer

For a few big, long-lived objects with create and destroy calls. The layout can change freely.

Integer handle

For the many small objects: meshes, lights, entities. A plain 64-bit number, so any language can store, compare and hash it.

A handle is a generational handle packed into one integer. The generation must fit in its bits, so the table must stop reusing a slot before its generation passes 32 bits: retiring the slot costs one slot in four billion reuses. Wrapped in a one-field struct per object type, { uint64_t id; }, the handle is still 8 bytes in a register, but C stops you from passing a light where a mesh is wanted.

4Only fixed-size types

Enums

A C enum may be 1, 2 or 4 bytes. A uint32_t with constants has one size, and each constant a fixed value.

Booleans

C99 bool is one byte, but C# marshals a bool as four. A uint32_t is the same everywhere.

Strings and arrays

A UTF-8 const char* instead of a string class; a pointer and a count instead of a vector.

Structs hold only fixed-size fields and pointers, so their layout is the platform's C layout. A binding copies the fields in order (Python's ctypes.Structure, C#'s [StructLayout(Sequential)], Rust's #[repr(C)]) and gets the same bytes. The calling convention is fixed too: on 32-bit Windows a macro spells out __cdecl; everywhere else there is only one C convention.

5Structs that grow

A config struct gets new fields over the years. If the library simply used its new, bigger struct, an old program's smaller one would be read past its end. The fix, used by Win32 (cbSize) and Vulkan (sType), is a size field: the caller sets it to sizeof the struct its header knows.

Three kinds of call read the size differently:

  • Create: fields past the caller's size take their defaults.
  • Update: fields past it keep the object's current values, so an old program does not reset a new setting it never saw.
  • Get: the library writes only up to the caller's size.

An init function fills a struct with the library's defaults and sets the size: one call, and a binding gets the same defaults as C. In an array of sized structs, every element must have the first one's size, because the library steps through the array by it. Small value structs (a vector, a matrix) never grow: changing one would mean a new struct and new functions.

6Errors without exceptions

  1. Check every pointer, size and enum value at the line: a bad argument is a code, never a crash.
  2. Call the C++ code inside try.
  3. Catch every exception: out of memory becomes its own code, anything else an internal error.
  4. Record the message as the thread's last error, and return the code.

A function returns an integer code (0 for success, negative for an error), or a 0 handle when it creates something. The message goes into a last error string kept per thread, like errno: two threads never overwrite each other's message. A logging callback lets a binding route the library's log into its own; it may run on any thread the library logs from, so it must be thread-safe. The library must not hold a lock while it runs: a callback that calls the library back would wait for itself.

7Who owns which memory

Two sides with two allocators must never free each other's memory: a C runtime's free on memory from another runtime's malloc corrupts both heaps. So each side frees only what it allocated.

In: borrowed

Strings, arrays and structs are read during the call only. The library copies what it keeps.

Out: the caller's buffer

The snprintf rule: write what fits, return the full length. Call once with no buffer to learn the size.

Library objects

Big results (an image) live in an object with create and destroy calls. It can be refilled, so a per-frame result allocates nothing.

8One library, one set of names

A shared library for bindings is usually built from static libraries, so it holds the whole C++ engine and every dependency. Only the C functions should leave it: everything else is hidden. Windows exports only what is marked __declspec(dllexport); on macOS a linker list (-exported_symbol,_mylib_*) and on Linux --exclude-libs,ALL with hidden visibility do the same. Hidden symbols cannot clash with another copy of the same third-party library in the host process.

The library must also find its own files. A relative path resolved against the executable points beside python.exe under Python. So the library resolves relative paths against its own folder (the module that holds the code: GetModuleHandleExW with an address on Windows, dladdr on POSIX), and its data, such as shaders, is installed beside it.

9Versions

Within one major version, only add at the end
  • New functions: yes. Changing a function's parameters: no, add a new function.
  • New enum constants: yes, with new values. Renumbering: no.
  • New struct fields: only after the last one, in a struct with a size field.
  • Removing or reordering anything: only in a new major version.

The header carries its version as major << 16 | minor, and the library reports its own. The creation call takes the caller's version and refuses a different major version, or a newer minor one: that program may call functions or set fields this library does not have. An old minor version is fine; that is what the size fields are for.

10Pitfalls

A binding crashes in a call that works from C
Its struct does not match the header: a missing field, a 1-byte bool, a wrong order. Copy every field in order, and test the binding in CI.
An old program resets a new setting to zero
An update wrote the whole new struct from the old program's smaller one. Read only the caller's size, and keep the rest.
The process aborts with "terminate called"
An exception left a C function. Wrap every entry point in a try that catches everything.
A heap corruption on free
One side freed the other side's memory. Pair every create with the library's destroy.
The library finds no data files under Python
Relative paths resolved against the executable. Resolve them against the library's own folder.
Two copies of a library in one process mix their functions
Both export the same names. Link one, and export only your own prefix.

11In RASM

RASM's facade is include/rasm/rasm_c.h, one header over two shared libraries: rasm_c (the renderer, the Engine and the AssetLoader) and rasm_c_renderer (the renderer alone). The C layer is src/c/; the reference is the C API page.

Keep these true
  • Change rasm_c.h only by adding at the end, and bump RASM_C_API_VERSION_MINOR when you do.
  • A new field of a C++ config or desc that C shows goes at the end of its C struct, into the toC and toCpp conversions in src/c/cApi.cpp, and into tests/c_api/ctypes_smoke.py's copy of the struct.
  • Every entry point is a function try block that ends with RASM_C_CATCH, and uses only types from rasm_c.h in its signature.
  • A new value of a C++ enum that C shows gets a C constant and its static_assert.
