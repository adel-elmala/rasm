Morph targets: a mesh that blends between shapes

A face smiles, an eye blinks, a muscle bulges. A skeleton cannot do this well: these are changes of shape, not turns of bones. A morph target (also called a blend shape or shape key) is the same mesh in another shape. The mesh blends from its base toward each target by a weight. This page explains the deltas, the weights, the normals, how to store and read targets on the GPU, the order with skinning, the bounds and the motion vectors. The last part shows how RASM does it.

In short

  • A target stores one delta per vertex: how far the vertex moves to reach that shape.
  • The posed vertex is v′ = v + Σ wₜ · Δₜ. Weights are usually 0 to 1, but any value works.
  • Weights come from the mesh's rest weights, from a clip's weights channel, or from the application (sliders, lip sync).
  • Normals and tangents have deltas too. Add them, then make the result unit length again.
  • Store the deltas target-major (all vertices of target 0, then target 1, ...). Then the GPU reads a target for many neighbour vertices at once, and skips a target whose weight is 0.
  • Morph first, then skin: the targets are modelled in the bind pose.
  • The bound grows by Σ |wₜ| · rₜ, where rₜ is target t's longest delta.

1A target is a set of deltas

The artist makes each target from the base mesh by moving vertices. Only the change is kept: one delta per vertex. A vertex that the target does not move has a delta of 0.

Several targets add up. Each one moves the vertex along its own delta, scaled by its weight:

v′ = v + w₀ · Δ₀ + w₁ · Δ₁ + … = v + Σ wₜ · Δₜ

v
the vertex in the base shape
Δₜ
target t's delta for this vertex
wₜ
target t's weight, the same for every vertex of the mesh in this frame

0: the base

The target has no effect. Its deltas are not even needed.

1: the target

The vertex lands exactly where the artist put it.

Below 0, above 1

Allowed. The shape goes the other way, or past the target: a cartoon squash and stretch.

2Where the weights come from

The deltas are fixed at import. Only the weights change, so a mesh with 50 targets is animated by 50 numbers per frame. They come from three places, and the later one wins:

  1. Rest weights. The file gives the weights of the shape at rest. In glTF, a node's weights, else the mesh's, else 0.
  2. A clip. A channel with the path weights animates all the targets of one node at once.
  3. The application. Sliders in an editor, lip sync from audio, a face tracker: the program sets the weights each frame.

A weights channel keys every target together. Each key holds one value per target. With cubic splines each key holds three groups: the in-tangents of all targets, then the values, then the out-tangents.

3Normals and tangents blend too

When the shape changes, the surface turns, so the light on it must change too. A target can carry deltas for the normal and the tangent as well. They add up the same way. The sum is not unit length any more, so make it unit length again.

Positions only

The ramp keeps the base's normals. It is shaded like flat ground.

Normal deltas, then normalize

n′ = normalize(n + Σ wₜ · ΔNₜ). The tangent the same way; its sign (w) stays.

4Storing the deltas for the GPU

Files often store a target sparse: only the vertices it moves, as a list of indices and values (glTF sparse accessors). On the GPU a dense array is simpler: every vertex has a delta in every target, so the address of a delta is a multiply and an add. The import fills the gaps with 0.

The order of the dense array decides how the GPU reads it. One GPU thread poses one vertex, and 32 or 64 threads run together on neighbour vertices:

Each delta needs some precision. A normal delta is at most 2 long and the result is normalized, so a half float (16 bits, 11 significant bits) is plenty. A position delta is in the mesh's units, and a half float keeps about 3 digits: 0.03 m of error on a delta of 50 m. So positions stay 32-bit floats.

5Morph first, then skin

A character often has both: a skeleton for the body and targets for the face. The artist models the targets on the mesh in its bind pose, before any joint moves it. So the targets come first, and skinning moves the result:

v′ = Σ sᵢ · Jᵢ · (v + Σ wₜ · Δₜ)

sᵢ, Jᵢ
the vertex's skin weights and joint matrices (skinning)
wₜ, Δₜ
the morph weights and the vertex's deltas

Skin, then morph

The delta was modelled for the straight arm. Added after the turn, it points the wrong way.

Morph, then skin

The delta is added in the bind pose, and the joint turns it with the rest of the vertex.

Like skinning, morphing is best done once per frame, in a compute pass that writes the posed vertices. Every view (the camera and each shadow map) then draws them. Morphing in the vertex shader repeats the loop over the targets in every view.

6Bounds that grow with the weights

Culling needs a sphere that holds the mesh in this frame. The base mesh's sphere is not enough: a target can move vertices out of it. Measuring the posed vertices each frame costs a pass over them before culling. A cheaper bound needs only the weights:

radius = base radius + Σ |wₜ| · rₜ

rₜ
the longest position delta of target t, measured once at import

No vertex moves more than |wₜ| · rₜ by target t, and the moves add up at most to the sum. So the bound is always safe. It is loose when the targets move different vertices: the sum adds their longest moves anyway. With a skeleton, grow each joint's sphere by the same amount before the joint matrix moves it.

7Motion vectors of morphed vertices

TAA and motion blur need each vertex's place in the frame before. A morphed vertex moves in its object's own space, so the object's matrix of the frame before is not enough. Keep the posed vertices of the frame before too, and read the same vertex there.

When the weights jump (a new clip starts, the application sets new weights out of nowhere), the frame before shows another shape. Then use this frame's vertex for both frames, so the jump makes no long motion vector. Weights that change a little each frame are normal motion.

8Pitfalls

The shape is right, but its lighting is flat
The normal deltas were not added, or the sum was not normalized.
A target moves the wrong vertices
The base mesh's vertices were welded or reordered at import, but the deltas were not. Weld and reorder the deltas with the vertices, and compare deltas too when welding.
A face part disappears at the edge of the screen
The mesh was culled with its base sphere. Grow the bound by the weights.
A smile bulges sideways on a turned head
Skinning ran before morphing. Morph in the bind pose first.
Many targets cost as much at rest as in motion
The loop reads every target. Skip the targets at weight 0, and store the deltas target-major so a skipped target costs no memory traffic.
A large model shakes slightly as it morphs
Position deltas stored as half floats lose precision on big meshes. Keep positions as 32-bit floats.

9In RASM

RASM morphs on the GPU, once per frame, in the same Skin pass that skins. The import puts each primitive's deltas into a morph stream of the geometry pool, target-major. The Animate pass writes every posed entity's weights and grows its bounds. The Skin pass adds the deltas of the targets whose weight is not 0, then applies the joints when the mesh has a skin. Every view draws the posed vertices.

An entity of a morphed mesh plays a clip like any animated entity. To drive the weights from the application, set them each frame; clearMorphWeights gives them back to the clip:

const rasm::MeshHandle face = engine.loadGLTF("models/face.glb");
engine.waitForLoads();
const std::vector<std::string> names = engine.getMorphTargetNames(face);
std::vector<float> weights(names.size(), 0.0f);
for (size_t i = 0; i < names.size(); ++i)
{
    if (names[i] == "Smile")
        weights[i] = smile;
}
engine.setMorphWeights(entity, weights.data(), static_cast<uint32_t>(weights.size()));

Keep these true
  • The morph stream is welded and reordered with its vertices, target by target.
  • A posed sub-mesh starts on a multiple of 64 among its entity's skinned vertices: a Skin group holds one sub-mesh's weights.
  • Morph before skin, in the bind pose.
  • A weight's override is a quiet NaN's exact bits when it is not set, never a NaN test, which fast math may drop.
  • The bound uses the longest delta of each target: a new kind of delta that moves positions must be measured into it.
