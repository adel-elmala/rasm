Projection and reversed-Z depth

The projection matrix turns the 3D view into a flat image, and it decides the depth value of every pixel. This page derives the perspective and orthographic matrices, explains why the usual depth mapping loses precision far away, and shows how reversed-Z fixes it. The last part shows how RASM does it.

In short

  • Perspective divides by the distance. A matrix cannot divide, so it copies the distance into w, and the GPU divides by w after the vertex shader.
  • The depth after the divide is a + b / distance: linear in 1/distance, not in distance. Most of the depth range goes to the first few meters.
  • With the usual mapping (near → 0, far → 1), far objects get values close to 1, where floats are coarse. Surfaces far away z-fight.
  • Reversed-Z maps near → 1 and far → 0. Floats are dense near 0, which balances the 1/distance crowding. With a 32-bit float depth buffer, precision becomes about equal at every distance.
  • Reversed-Z needs three changes together: the projection, a depth clear of 0, and a greater depth test.
  • An infinite far plane costs almost nothing with reversed-Z: depth = near / distance.

1Perspective: divide by the distance

A pinhole camera sees a point at height y and distance D in front of it at the image height y / D (similar triangles). Twice as far means half as big. In view space the camera looks down −Z, so D = −z.

2Why the 4th coordinate: w

A matrix can only multiply and add. It cannot divide by D. So the projection matrix puts D into a fourth coordinate, w, and the GPU divides x, y and z by it later. This is the perspective divide. The point before the divide is in clip space; after it, in NDC (see Coordinate spaces).

| x_c |   | focal/aspect   0     0   0 |   | x |
| y_c | = |      0       focal   0   0 | · | y |
| z_c |   |      0         0     A   B |   | z |
| w_c |   |      0         0    −1   0 |   | 1 |

w_c = −z = D        then   NDC = (x_c, y_c, z_c) / w_c

Keeping w until after the vertex shader has two more uses:

  • Clipping happens before the divide, against −w ≤ x, y ≤ w. A point behind the camera has w < 0; after a divide it would flip to the other side of the screen.
  • Perspective-correct interpolation. Texture coordinates and colors are not linear across a triangle on screen. The GPU interpolates value/w and 1/w, which are linear on screen, and divides.

3The depth row

The third row, (0, 0, A, B), makes the depth. After the divide:

depth = z_c / w_c = (A · z + B) / D = −A + B / D        (z = −D)

So depth is a straight line in 1/D, not in D. That is on purpose: 1/D is linear across a triangle on screen, so the GPU can interpolate depth with no divide per pixel, and compress depth tiles well. Two conditions fix A and B: the depth at the near plane n and at the far plane f.

The reversed row is the standard row with n and f swapped. So any library that builds a standard 0..1 matrix builds a reversed one when you pass the far distance as "near" and the near distance as "far".

4Orthographic projection

An orthographic camera has no perspective: parallel lines stay parallel and size does not change with distance. The view volume is a box (left, right, bottom, top, near, far), and the matrix only scales and moves it onto the NDC box. w stays 1, so depth is linear in distance.

x_ndc = (2x − (r + l)) / (r − l)
y_ndc = (2y − (t + b)) / (t − b)
depth = (D − n) / (f − n)       standard 0..1
depth = (f − D) / (f − n)       reversed: again, swap n and f

5Why depth precision is poor far away

A 32-bit float stores a number as 1.m × 2e, with 23 bits for m. So there are 223 floats between 0.5 and 1, another 223 between 0.25 and 0.5, another between 0.125 and 0.25, and so on. Floats are dense near 0 and coarse near 1: the gap between neighbors just below 1 is 2−24 ≈ 6 × 10−8, while near 0.001 it is about 10−10.

Two surfaces whose depths round to the same float cannot be ordered: the depth test picks one at random per pixel, and the picture flickers in stripes. This is z-fighting. The smallest distance step the buffer can tell apart is the float gap divided by how fast depth changes with distance:

Near 0.1, far 1000, in scene units (say meters). With standard depth, a wall at 900 m cannot be told apart from a poster 30 cm in front of it. With reversed-Z, the step stays below 0.01 mm everywhere.

A float buffer alone does not help

Standard depth in a 32-bit float buffer is no better than a 24-bit integer buffer: near 1, floats have the same 2−24 spacing as the integers. The gain comes only from reversed depth and a float buffer together.

The near plane matters most

With standard depth, the step size is about D² / n × 6 × 10−8. Moving the near plane from 0.01 to 0.1 makes every step 10 times smaller. With reversed-Z, the near plane hardly matters.

6Reversed-Z

Reversed-Z maps the near plane to depth 1 and the far plane to 0. The 1/D curve crowds far distances toward 0, and floats are densest near 0. The two effects roughly cancel: the step size becomes about D × 10−7, a constant relative precision, at every distance.

It is not one change but three, and all three must change together:

SettingStandardReversed
Projectionnear → 0, far → 1near → 1, far → 0 (swap n and f)

Depth testLESS: nearer is smallerGREATER: nearer is larger
Depth format24-bit integer is enough32-bit float, or there is no gain
Clip depth range0..1 or −1..10..1. With OpenGL's −1..1, far values sit near −1, where floats are coarse, and the gain is lost; OpenGL needs glClipControl.

7The infinite far plane

A far plane clips away distant geometry, and choosing its value is a trade-off with standard depth. With reversed-Z there is little reason to have one. Let f go to infinity in the reversed row: A → 0 and B → n.

| focal/aspect   0     0   0 |
|      0       focal   0   0 |          depth = n / D
|      0         0     0   n |
|      0         0    −1   0 |

The depth falls toward 0 but never reaches it, so nothing is ever clipped by distance. The step size stays about D × 7 × 10−8: 0.07 mm at 1 km and 0.9 mm at 10 km for n = 0.1. For frustum culling, the "far plane" of this matrix comes out as (0, 0, 0, n), which every point passes (Frustum culling).

The same limit with standard depth gives depth = 1 − n / D: the whole scene squeezed against 1, the worst case of section 5.

10In RASM

RASM uses reversed-Z everywhere, with a 32-bit float depth buffer, a 0..1 clip range, and by default an infinite far plane. The three settings of section 6 are fixed for every pass and every pipeline.

Keep these true
  • The projection, the clear value (0) and the compare op (GREATER_OR_EQUAL) are one decision. Change one, change all three.
  • A pass that writes its own depth follows reversed-Z: near is 1, far is 0. A sky at the far plane writes 0.
  • Code that reduces depth, like the Hi-Z build in hiz.slang, keeps the minimum as the farthest value.
  • Do not normalize the frustum plane with a zero-length normal: it is the infinite far plane (Frustum culling).
  • glm config macros stay in CMake (B2). Run ctest --preset x64-debug after a camera change.
