Frame stats and the overlay

The engine measures each frame: CPU time, GPU time per pass, draws and triangles before and after culling, and video memory. getFrameStats returns the numbers. With showStats on (or F1), a small shader draws them as text in the top-left corner.

CPU work GPU work GPU buffer shader entry point

In short

  • GPU numbers come from timestamp queries and from counters that cull.slang adds to with atomics.
  • They are read two frames later: a frame slot is read only after its fence wait, in updateFrameStats.
  • Nothing is measured until the overlay is shown or getFrameStats is called once.
  • The triangle count is 64-bit, kept as two 32-bit words with a carry, because not every backend has 64-bit atomics.
  • The overlay text is rebuilt every 250 ms, copied to a per-slot buffer every frame, and drawn by statsOverlay.slang with an 8x8 bitmap font kept in the shader.

2Measuring only when needed

Off (the default)

showStats is false and getFrameStats was never called. Then beginGpuTimer returns UINT32_MAX and writes no timestamp, and nothing is read back, reset or queried. Only cpuFrameMs is updated.

On

A slot is measured when showStats is true, or once getFrameStats has been called (it sets requested, which stays set). The choice is made per frame, in updateFrameStats, and stored in the slot's measuring flag.

Because the GPU numbers arrive two frames later, the first call to getFrameStats returns zeros for the GPU values. They fill in a few frames later.

3The two-frame delay

A frame that was recorded but not submitted (a failed submit) does not move the slot's fence value. updateFrameStats compares that value with readFenceValue, the one it read last time, and skips the slot when they are equal: its queries were never written.

When a frame has used its timers, the next ones are not measured, with one warning for the whole run. getTimestamps converts the raw values: each one becomes its signed distance from the first, modulo timestampValidBits, so a counter wrap inside a frame does no harm. Then it subtracts the earliest and multiplies by timestampPeriod to get nanoseconds. A query pool that could not be created only leaves the GPU times empty.

5Cull counters and the 64-bit carry

The Cull Stats Buffer of a slot is CULL_STATS_WORDS = 13 × uint. The STATS_* constants in cull.slang name the words:

WordsHoldsRead as
[0]visible drawsdrawsVisible
[1] low, [2] highvisible triangles, at the picked LODtrianglesVisible
[3] low, [4] highthe same draws' triangles at LOD 0trianglesVisibleLod0
[5] … [12]visible draws at LOD 0 … 7drawsPerLod

It is host-visible and host-readable, so the CPU reads it with readBuffer and zeroes it with fillBuffer. The last thread of each countMain group adds the group's numbers. The early and the late countMain both do it. A draw is still counted once, because the late culling keeps only draws the early one did not draw.

1. Sum the group's triangles in 64 bits

One group adds at most 64 draws, but each draw can have many triangles, so even one group may need the high word. The LOD 0 triangles are summed the same way, in the same loop. For the LOD draws, threads 0 to 7 each count the group's draws at their LOD and add that count to word 5 + LOD.

2. Add to the buffer with atomics

A group with no visible draw adds nothing. Each atomic is on a 32-bit word, which Metal and WebGPU support too. addCount64 does this for words [1, 2] and again for [3, 4].

3. Read back on the CPU

The counters keep growing in frames that are not measured. That does no harm: they are zeroed before the next measured frame in the slot.

6From numbers to a text grid

Counts use formatCount: plain up to 9999, then K with one decimal, then M with two. Timer names are cut to 8 characters. The "Culled" line is draws − drawsVisible. "LOD saved" is trianglesVisibleLod0 − trianglesVisible, with its share of trianglesVisibleLod0. "LOD draws" lists drawsPerLod from LOD 0 up to the coarsest LOD in use, and wraps when it is longer than 40 columns.

7How one pixel finds its glyph bit

The overlay is a single draw of 6 vertices. The vertex shader places two triangles over the panel. The fragment shader runs once per panel pixel and decides: background or text color. Here is one pixel on a 3840 × 2160 window, step by step.

1. The panel

Drawn at 1 SVG unit per screen pixel. Each character cell is 8 × 8 font pixels, and each font pixel is scale × scale screen pixels.

2. Screen pixel → font pixel → cell

All integer math: / drops the remainder, % keeps it. The pixel is in cell (1, 1), at column 1, row 5 inside that cell.

3. Cell → character

The text buffer is read as uints, 4 characters each. A space, or any byte outside 33 to 126, gives the background color.

4. Character → glyph bit

The font is the public-domain IBM VGA 8x8 font, characters '!' to '~', kept in the shader as FONT[188] (94 glyphs × 2 uints). There is no texture.

9When and how it is drawn

  1. At startupcreateStatsOverlay makes one host-visible text buffer per frame slot (MAX_TEXT_COLUMNS × MAX_TEXT_ROWS = 960 bytes) and builds the pipeline from passes/statsOverlay.slang with createPipeline. If the shader fails to compile, the error is logged and the overlay stays off; the engine still runs.
  2. ToggleF1 flips showStats in pollEvents (key repeats are ignored). Applications can set EngineConfig::showStats at start.
  3. Every frame, after the fence waitupdateFrameStats, then updateStatsOverlay, which sets the slot's columns and rows, or 0 rows when the overlay is off.
  4. At the end of every swapchain passendPass calls drawStatsOverlay before endRendering. Every pass clears its target, so drawing in each swapchain pass keeps the panel on the presented image.
  5. The drawIt sets a full-swapchain viewport and scissor (the panel is placed in window pixels, whatever the pass set) and CullMode::NONE (its triangles wind clockwise on screen), binds the pipeline, pushes the 16 bytes and draws 6 vertices.

The panel is opaque: BACKGROUND is near black, FOREGROUND is light grey, both linear colors. Its size follows the text, so it grows and shrinks with the number of timers.

11Rules when you change it

Keep these true
  • OverlayPushConstants (C++) and PushConstants in statsOverlay.slang change together, and stay at 16 bytes (PUSH_CONSTANTS_SIZE).
  • Read a slot's timestamps and counters only after that slot's fence wait, in updateFrameStats. Never read the slot the GPU may still be writing.
  • Keep the last timer free for culling: passes use beginGpuTimer (limit MAX_GPU_TIMERS − 1), culling uses beginCullingTimer.
  • The cull counters must stay 32-bit atomics with the carry, so other backends can run the same shader.
  • The overlay writes depth 1 (the near plane) to pass the reversed-Z test. See camera and depth.
  • A larger grid needs a larger text buffer and must still fit 8 bits per side in the push constant.
