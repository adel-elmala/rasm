Rendering

GPU frustum culling

Before the scene is drawn, a compute shader tests every draw against the camera view. Draws that are fully outside are removed. The CPU never sees which draws survive. The GPU writes the list and the count, and the draw call reads them.

CPU work GPU work GPU buffer shader entry point

In short

  • Input: the scene's draw list (one DrawInfo per sub-mesh of each entity). Output: the visible draws, packed, and one count per run.
  • Two dispatches per drawScene call: countMain tests and counts, writeMain copies the visible draws to their final place.
  • Test: a bounding sphere that is fully behind one of the 6 frustum planes is culled.
  • The visible draws keep the draw list's order, every frame. No count needs to be cleared.
  • The culling is recorded after the frame, in its own command buffer, but it runs before the frame on the GPU.

1Where culling sits in a frame

drawScene records its draws inside a render pass. Vulkan does not allow dispatches inside a render pass. So the dispatches go into a second command buffer, the cull command buffer. It is recorded last, in endFrame, but it is submitted first.

This works because drawScene does not need the results while recording. It only records "draw from this buffer, with the count in that buffer". The buffers are filled later on the GPU, before the draws run.

2The data flow

All these buffers are found through SceneData, which the push constant points to. Each drawScene call has its own SceneData, its own visible-draw buffer and its own counts. That is why two passes can draw the same scene with two cameras in one frame.

cullSlotsPtr and groupCountsPtr are not separate buffers. They sit in the same buffer as the visible draws, right after them.

3The test: sphere against plane

Every sub-mesh has a bounding sphere in the geometry table, in mesh space. countMain moves it to world space with the instance's world matrix, then tests it against the 6 planes of the camera frustum.

Two details that keep the test correct

The radius under scale

A scaled mesh has a bigger sphere. countMain multiplies the radius by the largest stretch of the world matrix. It gets an upper bound of it cheaply (Gershgorin's theorem on transpose(M) × M). The bound is exact for normal rotate + scale matrices, and never too small for odd ones.

The far plane

RASM uses reversed-Z with an infinite far plane by default. The far plane then comes out as (0, 0, 0, nearZ), so d = nearZ for every sphere and it always passes. See Camera, coordinates and depth.

4Runs and groups

The draw list is stable-sorted by cull mode into runs (NONE, then FRONT, then BACK, the order of the enum), because cull mode is set per indirect call. Culling splits each run into groups of 64 draws, one compute workgroup each. A group never crosses into the next run.

The CPU counts the groups of each call in drawScene (cullGroupCounts). recordCulling dispatches that many groups for both entry points.

2. countMain: test each draw

Green draws pass all 6 planes. Dashed draws are fully outside one plane.

3. countMain: slot in the group, and group count

A group only knows about itself. It cannot know yet where its draws go in the final list, because that depends on the groups before it. That is why there is a second dispatch.

4. writeMain: add up earlier groups, copy

The packed list has the same order as the draw list. A draw never jumps ahead of another one, so the image is the same every frame.

5. The count, and the draw

The count is written fresh each frame, so it never needs to be cleared. The places after the count may hold last frame's draws; the GPU does not read them.

6When culling is off

If cull.slang fails to compile, drawScene does not leave the screen black. It draws the whole draw list with plain drawIndexedIndirect and logs the error. It tries to build the culling pipelines again next frame, so a fixed shader on disk is picked up while the app runs.

8Rules when you change it

Keep these true
  • CULL_GROUP_SIZE is in two places: cull.slang and gpuScene.cpp. Change both.
  • The test must stay conservative. Removing a draw that is partly visible makes objects pop.
  • Do not record a dispatch inside a render pass. RenderContext::dispatch refuses it.
  • A new pointer in SceneData is a CPU↔GPU struct change: follow the struct contract.
