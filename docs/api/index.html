API reference

Getting started

RASM is a static C++20 library. Your program creates one Engine, asks it for scenes, meshes, materials, cameras and lights, and gets small handles back. Then it calls one function per frame. This page shows how to link RASM, a first program, and the three ways to run a frame.

In short

  • Link with CMake: find_package(rasm) and rasm::rasm. Ship the shaders next to your executable.
  • Include one header: rasm/rasm.h. Everything is in namespace rasm.
  • Every object is a handle. A function that fails logs an error and returns an invalid handle (isValid() is false).
  • Files load in the background. You can use a mesh or texture handle at once; the object is drawn when its data is ready.
  • Call the engine from one thread only. It has no locks.

2Build RASM and link it

  1. Install the tools. CMake 3.21 or newer, Ninja, Clang, the Vulkan SDK (1.4) and vcpkg, with the VCPKG_ROOT environment variable set to it. The step-by-step setup is in docs/build_guide.md.
  2. Build and install RASM. The presets use Ninja and clang++, and vcpkg builds the dependencies. cmake --install copies the library, the public headers and the shaders to install/ in the repo. Debug and Release share that folder, so install both if your project builds both. 
    cmake --preset x64-debug            # macOS: --preset macOS
cmake --build --preset x64-debug
cmake --install build/x64-debug
cmake --install build/x64-release   # if you built it too
  3. Find it from your project. Point CMake at the install folder with -DCMAKE_PREFIX_PATH=<repo>/install. To use a build folder without installing, set rasm_DIR to it instead (for example -Drasm_DIR=<repo>/build/x64-debug). 
    cmake_minimum_required(VERSION 3.21)
project(my_app CXX)

find_package(rasm 0.1 CONFIG REQUIRED)

add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE rasm::rasm)   # adds C++20, glm

# Shaders are compiled at runtime: copy them next to the executable.
add_custom_command(TARGET my_app POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_directory "${rasm_SHADER_DIR}" "$<TARGET_FILE_DIR:my_app>/shaders")
  4. Give your project RASM's dependencies. RASM is static, so your executable links its dependencies too. find_package(rasm) looks for them. With vcpkg, add to your manifest: vk-bootstrap, vulkan-memory-allocator, glm, sdl3[vulkan], tracy[on-demand], spdlog, tinyobjloader, meshoptimizer and shader-slang. The Vulkan SDK provides Vulkan.
Other ways to add RASM

add_subdirectory(rasm) works too and gives the same rasm::rasm target. Then examples, tests and install rules are off by default. The options are -DRASM_BUILD_EXAMPLES=ON, -DRASM_BUILD_TESTS=ON, -DRASM_INSTALL=ON, -DRASM_ENABLE_AVX2=ON (x86 only) and -DRASM_SHADER_DIR=<path> (the default shader folder, shaders beside the executable).

On Windows the executable needs the dependency DLLs next to it. The examples copy them with rasm_copy_runtime_dlls in cmake/RasmRuntimeDlls.cmake, because vcpkg's own copy misses TracyClient.dll in Debug.

3A first program

This is examples/00_hello_scene/main.cpp made shorter. It loads a mesh and a texture, puts one entity, a camera and a light into a scene, and renders until the window closes (or Esc).

#include "rasm/rasm.h"

int main()
{
    rasm::EngineConfig config = {
        .appName = "my_app",
        .windowWidth = 1280,
        .windowHeight = 720,
        .enableValidation = true,
        .assetRoot = "assets", // relative paths start beside the executable
    };

    rasm::Engine engine(config);
    if (!engine.running())
        return 1; // the reason is in the log

    rasm::SceneHandle scene = engine.createScene();

    // Both return at once. The files are read on a worker thread.
    rasm::MeshHandle mesh = engine.loadMesh("models/obj/bunny/bunny.obj");
    rasm::TextureHandle albedo = engine.loadTexture("models/obj/bunny/bunny-atlas.jpg");
    if (!mesh.isValid() || !albedo.isValid())
        return 1; // unknown format or missing file

    rasm::MaterialHandle material = engine.createMaterial(rasm::MaterialType::PBR, {albedo});
    rasm::EntityHandle bunny = engine.createEntity("bunny", mesh, material,
                                                   rasm::Transform{.position = glm::vec3(0.0f, 0.0f, -10.0f), .scale = glm::vec3(0.005f)});

    rasm::CameraHandle camera = engine.createCamera(
        rasm::CameraProjection{.type = rasm::CameraProjection::Type::PERSPECTIVE,
                               .perspective{.fovY = 45.0f, .aspect = 1280.0f / 720.0f, .nearZ = 0.1f}},
        rasm::Transform{.position = glm::vec3(0.0f, 0.0f, 4.0f)});

    const glm::vec3 sunDirection = glm::normalize(glm::vec3(-0.5f, -0.8f, -1.0f));
    rasm::LightHandle sun = engine.createLight(rasm::LightType::DIRECTIONAL, glm::vec3(1.0f),
                                               glm::vec3(0.0f), sunDirection, 3.0f);

    engine.addEntityToScene(scene, bunny);
    engine.addCameraToScene(scene, camera);
    engine.addLightToScene(scene, sun);

    while (engine.running())
        engine.render(scene, camera); // the bunny appears once its files are loaded
    return 0;
}

What you see

The first frames are empty (dark gray). The bunny appears when its mesh and its texture are both loaded. Drag with the mouse to orbit the camera, scroll to zoom. F1 shows the stats overlay.

What to check when it fails

Read the log (spdlog, on the console). Common causes: no shaders/ folder beside the executable, a wrong assetRoot, or a GPU without Vulkan 1.4. Keep enableValidation on while you develop.

4Handles

FactWhat it means for you
A handle is two numbers, index and generationCopy it freely, store it, compare it with ==. It is not a pointer.
{} is the invalid handleisValid() is false. Many functions take one as "none", for example createEntity without a material.
Errors return the invalid handleThe function logs the reason and returns {}. Check isValid() after creating or loading.
Each kind has its own typeMeshHandle and TextureHandle do not convert into each other, so you cannot pass the wrong kind.
Handles stay valid until the engine is destroyedScenes, entities, meshes, materials, cameras and lights cannot be destroyed, and entities cannot leave a scene (D4 in docs/code_review.md). Create objects once and reuse them.

All handle types are listed in Types, handles and limits, with every limit.

// B: your own frame. Inside a pass, record with the frame's command buffer.
while (engine.running())
{
    if (!engine.beginFrame(camera))
        continue; // skipped: record nothing, no endFrame
    engine.beginPass("Main");
    engine.drawScene(scene, camera);
    // engine.getRenderContext() records more draws into
    // engine.getCurrentFrameResources().commandBuffer here
    engine.endPass();
    engine.endFrame();
}
