2Create and shut down

engine setup GPU buffers and descriptor sets 
Engine(const EngineConfig& config);

Opens the main window and sets up the whole renderer. It also resolves shaderDir and assetRoot (see paths) and creates the default material. On any failure it logs an error and returns early, and running() stays false. A window width or height of 0 or less fails at once with "Window dimensions must be positive.".

config
Copied into the engine. Fields are in the EngineConfig table below (also on types.html).
rasm::Engine engine(config);
if (!engine.running())
    return 1;
~Engine();

Waits for background loads that are still running, frees every GPU resource, destroys the window and shuts SDL down. Scene objects cannot be destroyed earlier: there is no destroy function for scenes, entities, meshes, materials, cameras or lights yet (D4).

bool running() const;

True while the engine works. It becomes false when the window is closed or Esc is pressed (both handled in pollEvents, inside beginFrame), and it is false from the start when the constructor failed. Use it as the main loop condition.

3Run a frame

A frame is beginFrame, then one or more passes, then endFrame. render does all of it for one scene, through a render graph with the scene's passes. Here is what each part does inside:

engine work on the CPU uploads to GPU buffers 
void render(SceneHandle scene, CameraHandle camera);

One whole frame of the scene, drawn into the window. The engine keeps a render graph with the scene's passes (addScenePasses into a 16-bit float target, then addToneMapPass into the swapchain) and runs it with RenderGraph::execute: beginFrame(camera), the passes, endFrame. It builds the graph again only when scene or camera is not the same as in the last call, also after a failure: a view whose passes could not be added is not tried again until one of them changes. When beginFrame returns false, no pass runs.

scene
The scene to draw. Invalid: an error is logged once, and the window is only cleared.
camera
Gets this frame's input (mouse, keys) and is the view. It does not need to be in the scene.
while (engine.running())
    engine.render(scene, camera);
[[nodiscard]] bool beginFrame(CameraHandle camera);

Starts a frame (steps in the diagram above). It handles window events and moves camera with the input, finishes background loads for up to 4 ms, waits until this frame slot is free, uploads changed scene data, acquires a window image and starts the frame's command buffer.

camera
The camera that the mouse and keyboard move. Invalid: "Invalid camera handle." is logged every frame, and the frame still runs.
returns
false when the frame must be skipped: window minimized or 0 pixels wide, swapchain rebuild failed, fence wait failed, or the image could not be acquired. Then record nothing and do not call endFrame.

may block It waits for the GPU when the CPU is 2 frames ahead.

void endFrame();

Ends the frame's command buffers and sends the frame to the GPU, then shows it in the window. If no pass drew to the window this frame (for example, all passes drew to render targets), it adds a pass that clears the window first. With the stats overlay shown, it draws the overlay in a pass of its own on top. Without async compute the frame is one command buffer: culling is recorded in it as ordinary scene passes. With EngineConfig::asyncCompute it is a few batches, each one command buffer and one submit on one queue. They are all submitted here, in the order they were closed. The last graphics batch waits for all of the frame's compute work, and presents.

Call it only after a beginFrame that returned true, and after the last endPass.

void beginPass(const std::string& name = "Pass", const AttachmentOps& ops = {});

Starts rendering into the current target: the window, or the render target set with setRenderTarget. By default it clears color and depth (their old contents are dropped), sets the viewport and scissor to the whole target, and sets cull mode to none. Only between beginFrame and endFrame.

name
Label of the pass. It names the pass's GPU timer in getFrameStats and the stats overlay.
ops
Which attachments to keep instead of clearing, and whether to keep depth at the end. See AttachmentOps. A render graph sets them for you.

The window is cleared to a dark gray and has no depth: draw anything that needs a depth test into a render target. A render target is cleared to its own clearColor.

struct AttachmentOps
{
    bool loadColor      = false;
    bool loadDepth      = false;
    bool storeDepth     = false;
    bool firstWrite     = false;
};

What a pass does with its attachments. The defaults clear both and throw depth away at the end.

loadColor, loadDepth
true: keep what the attachment holds, and draw on top. false: clear it (color to the target's clear color, depth to 0).
storeDepth
true: keep depth at the end of the pass, for a later pass that loads it or samples it. Color is always kept. A render graph sets it on the pass before one that loads the target or reads its depth (readDepth).
firstWrite
true: no earlier pass drew into the target this frame. For a cube target (RenderTargetDesc::cube) a pass draws one face, but the layout change before it covers all six. Only with this set does beginPass let a clearing pass drop the whole cube's old contents; otherwise it keeps the other faces. A render graph sets it on a target's first pass of the frame. Leave it false when you draw a cube's faces by hand: every face you draw stays.
// A hand-written frame: two passes on the window, the second on top of the first
engine.beginPass("Background");
// ... draw the background
engine.endPass();
engine.beginPass("UI", {.loadColor = true});
// ... draw the UI
engine.endPass();
void endPass();

Ends the pass. On a render target, it moves the color image to the sampled layout, so later passes can sample it (see getRenderTargetTexture). The depth image stays a depth attachment; in a graph, a later pass that declares readDepth gets it moved to the sampled layout. endFrame moves the swapchain image to the present layout.

bool addScenePasses(RenderGraph& graph, SceneHandle scene, CameraHandle camera, const RenderTargetHandle& renderTarget, const SceneShadow* shadows = nullptr, uint32_t shadowCount = 0);

Adds the passes that draw scene from camera to graph. They are ordinary graph passes: the graph sorts them with your passes, records their barriers from what they declare, and times each one under its name. render calls it for you; call it yourself when you build your own graph. The culling passes and Hi-Z are async compute passes: with EngineConfig::asyncCompute they run on the compute queue.

graph
The graph to add to, before its compile. Add your own passes before or after.
scene
Invalid: logs addScenePasses needs a valid scene handle., adds nothing and returns false.
camera
The view. Its projection is fitted to the target's aspect ratio every frame; the camera itself does not change. Invalid: logs an error, adds nothing and returns false.
renderTarget
Where the scene is drawn. A target needs one color in SCENE_COLOR_FORMAT and D32_SFLOAT depth, the formats of the scene's pipeline. The color is linear light with no upper limit: draw it to the window with addToneMapPass. Invalid: logs an error, adds nothing and returns false. A target with D32_SFLOAT depth and no color is depth-only: the scene's depth is drawn and nothing else, in passes named Shadow 1, Shadow 2, … (a depth pre-pass, for example; shadows come from addShadowPasses). Make it with RenderGraph::createRenderTarget before this call.
shadows, shadowCount
Up to MAX_VIEW_SHADOWS (4) shadows (SceneShadow), of different lights, that addShadowPasses returned for the same scene and camera in this graph. Each darkens its own light. The draw passes read every map's depth, so the graph runs them after the map passes. nullptr and 0 (the default): no shadow. More than 4, two of one light, a shadow that addShadowPasses did not make for this scene and camera in this graph, a shadow that another view in the graph already reads (cascades are fitted to one view's aspect ratio), or shadows on a depth-only view, log an error, add nothing and return false. A cube render target (RenderTargetDesc::cube) is not a valid renderTarget.
returns
true when the passes were added. On false nothing was added.
scene passes, run on the GPU the target 
// From examples/01_render_graph/main.cpp: the scene into an offscreen target
const rasm::RenderTargetHandle rtHandle = graph.createRenderTarget({
    .name = "offscreen_rt",

    .colorFormats = {rasm::SCENE_COLOR_FORMAT},

    .clearColor = glm::vec4(0.0f), // alpha 0 marks the background
});

{
    return 1;
}
SceneShadow addShadowPasses(RenderGraph& graph, SceneHandle scene, CameraHandle camera, const ShadowDesc& desc);

Adds a light's shadow to graph: depth-only maps of the scene, each drawn by a scene view of camera. Give the returned SceneShadow to addScenePasses for the same scene and camera. The maps depend on the light's type:

LightMapsScene viewsGuide
DIRECTIONALcascadeCount cascades, shadow_cascade_0, …, each covering a slice of the camera's view out to distance, fitted every framecascadeCountCascaded shadow maps
SPOTone perspective map at the light along its cone, shadow_spot_<light index>1Spot and point light shadows
POINTone cube map, shadow_cube_<light index>6 (one per face)
graph
The graph to add to, before its compile. It owns the maps' targets, so they live as long as the graph.
scene
The scene whose depth the maps hold. Invalid: logs an error and returns an empty shadow.
camera
The camera you then give addScenePasses. A directional light's cascades follow its view. Every map's view takes its level of detail from this camera, so a mesh is drawn at the same level in both. Invalid: logs an error and returns an empty shadow.
desc
The light and its maps (ShadowDesc). An invalid light or a size of 0 logs an error and returns an empty shadow. So does, for a directional light, 0 or more than MAX_SHADOW_CASCADES (4) cascades, a distance not beyond the camera's near plane or a splitLambda outside 0 to 1, and for a spot or point light a distance that is not finite and above 0. So do fewer free scene views than the shadow needs: nothing is added then.
returns
The shadow, with mapCount 0 on failure. Each map's depth is maps[i], which a pass of yours can read with readDepth.

Shadows. Call addShadowPasses for each light, then addScenePasses with the shadows it returned. The order of the passes does not matter: the graph sorts them by the depth reads. Each cascade, spot map and cube face is one scene view: a sun with 4 cascades, a spot light, a point light and the shaded view take 12 of the MAX_SCENE_VIEWS (16).

engine passes targets your pass 
// From examples/06_shadows/main.cpp
const rasm::SceneShadow shadow = engine.addShadowPasses(graph, scene, camera, rasm::ShadowDesc{.light = sun, .cascadeCount = CASCADE_COUNT, .size = 2048, .distance = 60.0f, .splitLambda = 0.7f});
if (shadow.mapCount == 0 || !engine.addScenePasses(graph, scene, camera, sceneTarget, &shadow, 1))
    return 1;

// From examples/07_lights/main.cpp: three lights, each with its own shadow, read by one view.
const rasm::SceneShadow shadows[] = {
    engine.addShadowPasses(graph, scene, camera, rasm::ShadowDesc{.light = moon, .cascadeCount = 4, .size = 2048, .distance = 40.0f}),
    engine.addShadowPasses(graph, scene, camera, rasm::ShadowDesc{.light = lamp, .size = 2048, .distance = 40.0f}),
    engine.addShadowPasses(graph, scene, camera, rasm::ShadowDesc{.light = lantern, .size = 1024, .distance = 14.0f}),
};
if (!engine.addScenePasses(graph, scene, camera, sceneTarget, shadows, 3))
    return 1;

A light taken out of the scene casts no shadow, and its maps draw nothing; so does a directional light's shadow when the camera's near plane is moved to distance or beyond. Points farther than distance from the camera are lit; a directional shadow fades out over the last tenth of it. Casters up to distance toward the sun from a slice are in its map. A spot or point light shadows up to distance from the light. Every shadow uses 3x3 PCF. Each shadow darkens only its own light; lights without one and the ambient term are not shadowed. How it works: Shadow mapping, Cascaded shadow maps and Spot and point light shadows.

Scene views. Each (scene, camera, target, face, shadows) is a scene view, with its own culling buffers on the GPU; the face is a cube's, for a point light's map. A view lives while a graph holds it: graphs built for the same five share it, and when the last of them is destroyed or replaced, the view's buffers are freed. Views let one frame draw several scenes, cameras or targets. The scene's lights are read every frame. Nothing is drawn, with no error, while the scene is empty or all its entities still load: the target keeps its clear color.

Culling also picks each visible draw's level of detail from its distance to the camera and EngineConfig::lodErrorPixels. A view drawn without culling draws LOD 0.

One graph adds each scene view onceAn error, nothing added, false
A valid render target with one SCENE_COLOR_FORMAT color and D32_SFLOAT depth, or D32_SFLOAT depth onlyAn error, nothing added, false
The scene shader passes/rasm.slang must compileAn error is logged; the engine tries again next frame, so a fixed shader file is picked up while the program runs

bool addToneMapPass(RenderGraph& graph, const RenderTargetHandle& source, CameraHandle camera);

Adds a graphics pass named Tone Map that draws source into the window. It multiplies the color by the camera's exposure and maps it to the range the screen shows with AgX; the sRGB swapchain then encodes it. render calls it after the scene passes; call it yourself as the last pass of your own graph that draws the scene. How it works: Tone mapping.

graph
The graph to add to, before its compile. The pass reads source, so the graph runs it after the passes that draw it.
source
Color 0 is read, as linear light. Usually a SCENE_COLOR_FORMAT target that addScenePasses or your post passes drew. Invalid, or a depth-only target: logs an error, adds nothing and returns false.
camera
Its exposure is read each time the pass runs, so changing it needs no new graph. Invalid: logs an error, adds nothing and returns false.
returns
true when the pass was added. The pipeline is made the first time the pass runs. If passes/toneMap.slang does not compile, the pass logs an error, draws nothing (the window shows the clear color) and tries again next frame, so a fixed shader file is picked up while the program runs.
// From examples/06_shadows/main.cpp: post_rt holds the vignetted HDR image
if (!engine.addToneMapPass(graph, postTarget, camera))
    return 1;
const FrameResources& getCurrentFrameResources();

The current frame slot's FrameResources: commandBuffer (the one being recorded: record your own draws and dispatches into it), fenceValue and computeFenceValue. Fetch it every frame, because the slot changes every frame. With EngineConfig::asyncCompute fetch it inside each pass, because the command buffer changes when a pass runs on the other queue.

auto commandBuffer = engine.getCurrentFrameResources().commandBuffer;
ctx.bindPipeline(commandBuffer, pipeline);
ctx.draw(commandBuffer, 3);
bool recreateSwapchain();

Rebuilds the swapchain, the render targets sized from it, and the aspect ratio of every camera, from the window's current pixel size. beginFrame already calls it after a resize or an out-of-date swapchain, so a program does not need to.

returns
false while the window has 0 pixels, or when the rebuild failed. beginFrame then tries again next frame.

4Loading and waiting

void waitForLoads();

Finishes every pending mesh and texture load now: it waits for the worker threads and uploads the results, with no time limit. After it returns, isLoaded is true for every successful load. Entities that use them join their scenes' draw lists at the next beginFrame, so the first frame after it shows everything.

blocks the main thread Use it before the main loop to avoid objects popping in, or in tests. Do not call it every frame.

auto mesh = engine.loadGLTF("models/gltf/coffee-room/scene.gltf");
engine.waitForLoads();
bool ok = engine.isLoaded(mesh); // false if the file failed to parse

5Frame stats

GPU work CPU work 
const FrameStats& getFrameStats() const;

The latest measured frame. The first call turns measuring on for every later frame, so the values fill in a few frames later. The reference stays valid; read it every frame.

const rasm::FrameStats &stats = engine.getFrameStats();
for (uint32_t i = 0; i < stats.gpuTimerCount; ++i)
    std::printf("%s: %.2f ms\n", stats.gpuTimers[i].name.c_str(), stats.gpuTimers[i].milliseconds);
struct FrameStats
cpuFrameMs
Time between the last two frames on the CPU, in ms. Capped at 100 ms. Updated every frame, even when not measuring.
gpuFrameMs
GPU time of the frame on the graphics queue, in ms: from the frame's start to the latest end of a timer there. Timers on the compute queue are left out, because the timestamps of two queues may not share a clock. 0 on a GPU without timestamps.
gpuTimers
One GpuTimer per pass (graphics or compute, the scene passes included) and per timer of your own, in the order they were recorded. Room for MAX_GPU_TIMERS - 1 (15).
gpuTimerCount
How many entries of gpuTimers are filled.
draws
Draws of all scene views the frame drew, before culling (one per sub-mesh of each entity).
drawsVisible
Draws that passed culling: inside the view, and with occlusion culling also not hidden. Draws of a view drawn without culling all count.
triangles
Triangles before culling, at LOD 0.
trianglesVisible
Triangles of the visible draws, at the LOD culling picked for each.
trianglesVisibleLod0
Triangles of the same visible draws at LOD 0. trianglesVisibleLod0 - trianglesVisible is what LODs saved this frame.
drawsPerLod
Visible draws at each LOD, from LOD 0 to MAX_MESH_LODS - 1. They add up to drawsVisible.
lightsGlobal
Global lights (directional, or range 0) of the frame's shaded views: each one is shaded at every pixel.
lightsVisible
Lights with a range in the shaded views' frustums. A view without clusters counts all of them.
lightsDropped
Lights left out of a cluster that already held MAX_CLUSTER_LIGHTS, counted once per cluster: their pixels miss them. Above 0, the log also warns (once, then at most every 10 s).
memory
VRAMStats of that frame (see queryMemoryStats).
struct GpuTimer
name
The pass name (for the scene passes: "Cull 1", "Scene 1", "Hi-Z", "Cull 2", "Scene 2", "Transparent", or "Cull" and "Scene"; inside them "Light Clusters" and "Blend Sort"), or the name you gave beginGpuTimer.
milliseconds
GPU time between the timer's start and end, in ms.
uint32_t beginGpuTimer(const CommandBufferHandle& commandBuffer, const std::string& name);

Writes a start timestamp into the frame's command buffer. The GPU time until the matching endGpuTimer appears in getFrameStats and the overlay. Passes and render graph compute passes are already timed for you.

commandBuffer
The frame's command buffer, from getCurrentFrameResources.
name
Label in the stats.
returns
The timer id, or UINT32_MAX when nothing is measured: measuring is off, the GPU has no timestamps, or the frame used all its timers (a warning is logged once).

A frame has MAX_GPU_TIMERS (16) timers: one for the whole frame, and 15 for passes and your timers together. Begin and end a timer in the same pass, so both timestamps are on one queue.

void endGpuTimer(const CommandBufferHandle& commandBuffer, uint32_t timer);

Writes the end timestamp of timer. It does nothing for UINT32_MAX, so you can always pass what beginGpuTimer returned.

const uint32_t timer = engine.beginGpuTimer(commandBuffer, "Particles");
ctx.dispatch(commandBuffer, groupCount);
engine.endGpuTimer(commandBuffer, timer);
VRAMStats queryMemoryStats();

Asks the GPU memory allocator now. Returns vramBudget and vramUsage (device-local memory) and hostBudget and hostUsage (host-visible memory), all in bytes. See VRAMStats.

Joins path to the resolved assetRoot, as every loader does, and returns it as UTF-8 with forward slashes. Useful to check where a file is looked for, or to open your own files from the same folder.

A copy of the engine's config. shaderDir and assetRoot are the resolved paths (an empty assetRoot stays empty), and showStats is its current value (F1 changes it). Changing the copy changes nothing in the engine.

7The window

Built-in keys

Esc or closing the window: running() becomes false.
F1: shows or hides the stats overlay.
F2: cycles forcedLod: by distance, LOD 0, 1, … 7, by distance.
F3: logs the graph of the next render call (RenderGraph::dump).
Mouse and WASD: move the camera passed to beginFrame (see camera.html).

Two sizes

width, height: logical size, the unit of mouse positions.
pixelWidth, pixelHeight: the drawable size. They differ on HiDPI screens. The swapchain, the render targets sized from it and the viewports use the pixel size.

The engine owns the window and the input

Events are read inside beginFrame, and your program does not see them. You cannot render into a window you made yourself, or run without a window (D7).

const Window& getMainWindow() const;

The window the engine renders to, with its current sizes and state (minimized, resized, mouse drag). It updates in beginFrame. Use the pixel size for viewports, like examples/01_render_graph/main.cpp does. Fields are in types.html.

const auto &window = engine.getMainWindow();
const float width = static_cast<float>(window.pixelWidth);
const float height = static_cast<float>(window.pixelHeight);
const float aspect = width / height;
Window createWindow(uint32_t width, uint32_t height);

Starts SDL and opens a resizable Vulkan window titled "RASM Engine". The constructor calls it for the main window. A program has no use for it: a second window gets no rendering. Returns a Window with an invalid handle on failure (logged).

void destroyWindow(const Window& window);

Closes the window and shuts SDL down. The destructor calls it for the main window; do not call it on the main window yourself. docs/code_review.md lists both window functions among the calls that should leave the public API for a platform layer (D2, D7).

8Raw GPU resources

For your own passes you may need buffers and textures that are not part of a scene. These two functions forward to RenderContext. The descriptors (BufferDesc, TextureDesc) and how to fill, read and bind the resources are on RenderContext and resources.

BufferHandle createBuffer(const BufferDesc& desc);

Creates a new GPU buffer, every call (two equal descriptors give two buffers). Returns an invalid handle and logs an error on failure. It is device-local unless hostVisible is set. RenderContext::destroyBuffer frees it.

rasm::BufferHandle particles = engine.createBuffer({.name = "Particle Positions",
                                                    .usage = rasm::BufferUsage::STORAGE,
                                                    .size = PARTICLE_COUNT * 2 * sizeof(float)});
const uint64_t address = engine.getRenderContext().getBufferDeviceAddress(particles);

From examples/04_compute/main.cpp: a shader reads and writes the buffer through its device address.

TextureHandle createTexture(const TextureDesc& desc);

Creates a new, empty texture. Fill it with RenderContext::fillTexture, and add it to the bindless set (addBindlessTexture) to sample it in a shader. For image files use loadTexture instead. Returns an invalid handle on failure.
