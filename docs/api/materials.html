API reference

Materials and textures

A material says how a surface looks: PBR (lit) or unlit, up to six textures, and a few numbers such as base color and roughness. Every material is one row in a GPU table, and every texture gets a slot in one big bindless texture array. One shader reads both for all objects.

In short

  • createMaterial(MaterialType::PBR, {albedo}) makes a material; the vector order is PbrSlot.
  • Change a material: copy it with getMaterial, edit, updateMaterial. Every object that uses it changes in the next frame.
  • loadTexture loads in the background. Color textures are sRGB (the default); normal, metallic-roughness and occlusion maps must be R8G8B8A8_UNORM.
  • An entity waits, undrawn, until all its textures are loaded.
  • Limits: 256 materials (MAX_MATERIALS), 1024 texture slots (MAX_BINDLESS_TEXTURES). Neither is ever freed.
CPU record GPU buffer or descriptor set shader entry point

1Create a material

enum class MaterialType { PBR, UNLIT, COUNT };
PBR
Lit by the scene's lights (metallic-roughness model), tone mapped. Reads the texture slots listed in the slot table.
UNLIT
Only the base color (texture × factor), not lit and not tone mapped, so authored colors reach the screen unchanged.
COUNT
Not a type; it counts the values.
MaterialHandle createMaterial(MaterialType type, std::vector<TextureHandle> textures = {}, bool doubleSided = false);

Creates a material with the default values below and writes its row. Each valid texture is added to the bindless set. Entities that use the material can be drawn from the next frame on.

type
PBR or UNLIT.
textures
In PbrSlot order: albedo, metallic, roughness, normal, occlusion, emissive. Leave the end out, or pass {} for an empty slot. Entries after the sixth are ignored. Textures that still load are fine.
doubleSided
True: back faces are drawn too (no culling) and lit with the flipped normal.

Returns an invalid handle and logs a warning after MAX_MATERIALS materials (256; 254 are left for you and glTF files, because indices start at 1 and the default material takes one).

// examples/00_hello_scene
rasm::TextureHandle albedo = engine.loadTexture("models/obj/bunny/bunny-atlas.jpg");
rasm::MaterialHandle material =
    engine.createMaterial(rasm::MaterialType::PBR, {albedo});

// Your own normal map: data, so UNORM. It goes in slot 3 (NORMAL),
// so slots 1 and 2 stay empty.
rasm::TextureHandle normal =
    engine.loadTexture("brick_normal.png", rasm::Format::R8G8B8A8_UNORM);
std::vector<rasm::TextureHandle> textures = {albedo, {}, {}, normal};
rasm::MaterialHandle brick = engine.createMaterial(rasm::MaterialType::PBR, textures);

Default values

Entities without a material, and sub-meshes whose material is missing, use the default material that the engine makes at start. It follows glTF: white, metallic 1, roughness 1.

2The Material record

struct Material
{
    const char*    name{};
    MaterialHandle handle{};
    MaterialType   type{};
    TextureHandle  textures[MAX_TEXTURE_SLOTS];
    uint32_t       texCoords[MAX_TEXTURE_SLOTS];
    float          params[MAX_PARAM_SLOTS];
    bool           doubleSided{};
};
name
A label: "pbr", "unlit", or "default". The engine keeps only the pointer, so point it at a string that lives as long as the engine (a string literal).
handle
The material's own handle. updateMaterial keeps the right one, whatever you put here.
type
PBR or UNLIT.
textures
One texture per PbrSlot; an invalid handle means none.
texCoords
Which UV set (0, 1 or 2) each texture uses. Default 0. A value of 3 or more uses set 0.
params
The numbers, indexed by PbrParam (diagram above). All are linear values.
doubleSided
Draw back faces too.

The flat params array is easy to index wrongly; docs/code_review.md plans a typed struct (C9).

enum class PbrSlot { ALBEDO, METALLIC, ROUGHNESS, NORMAL, OCCLUSION, EMISSIVE, COUNT };

Index into textures and texCoords. MAX_TEXTURE_SLOTS = 6 (PbrSlot::COUNT).

SlotFormatWhat the shader reads
ALBEDOR8G8B8A8_SRGBRGB × albedo factor. Alpha is passed through but nothing is blended.
METALLICR8G8B8A8_UNORMThe glTF metallic-roughness texture: G × roughness factor, B × metallic factor.
ROUGHNESSR8G8B8A8_UNORMNothing: roughness comes from the METALLIC texture's G. glTF import puts the same texture in both slots.
NORMALR8G8B8A8_UNORMTangent-space normal, scaled by NORMAL_SCALE. Uses the vertex tangent, or builds one from the UVs.
OCCLUSIONR8G8B8A8_UNORMR, mixed in by OCCLUSION_STRENGTH. It darkens only the ambient light.
EMISSIVER8G8B8A8_SRGBRGB × emissive factor, added to the result. The factor alone glows without a texture.

UNLIT materials read only ALBEDO. The format column is a rule: a data texture in an sRGB format gives wrong values, and nothing checks it.

enum class PbrParam : uint32_t
{
    ALBEDO              = 0,   // vec3
    METALLIC            = 3,   // float
    ROUGHNESS           = 4,   // float
    NORMAL_SCALE        = 5,   // float
    OCCLUSION_STRENGTH  = 6,   // float
    EMISSIVE_FACTOR     = 7,   // vec3
    COUNT = 10,
};

Offsets into params. MAX_PARAM_SLOTS = 10 (PbrParam::COUNT). Roughness is clamped to 0.045 – 1 and metallic to 0 – 1 in the shader.

3Read and change a material

  1. Copy it. getMaterial returns a reference into the engine's list. Copy it into a local variable (auto values = ...): the reference can move when another material is created.
  2. Edit the copy. Change factors, textures, the type or doubleSided.
  3. Call updateMaterial. It replaces the whole record. New textures get bindless slots now, and the row is rewritten in CPU memory.
  4. Next beginFrame. The row is uploaded, so every entity that uses the material shows the change in that frame. It costs one row, however many entities use it.
  5. If a new texture still loads, the entities that use the material are not drawn until it finishes, so nothing is drawn half-loaded. A changed doubleSided rebuilds the draw lists of their scenes.
// examples/03_instances: one material; the 10 spinning cubes and up to
// 2,000 spawned cubes that use it change color every frame.
auto values = engine.getMaterial(pulse);
const auto albedo = static_cast<uint32_t>(rasm::PbrParam::ALBEDO);
values.params[albedo] = 0.5f + 0.5f * std::sin(t);
values.params[albedo + 1] = 0.5f + 0.5f * std::sin(t + 2.1f);
values.params[albedo + 2] = 0.5f + 0.5f * std::sin(t + 4.2f);
engine.updateMaterial(pulse, values);
const Material& getMaterial(const MaterialHandle& handle);

The material's current values. An invalid handle returns the default material. A handle that looks valid but is unknown logs an error and also returns the default material.

void updateMaterial(MaterialHandle material, const Material& values);

Replaces the material's values (steps above). Every entity and glTF sub-mesh that uses it changes in the next frame.

material
The material to change. Invalid: logs "Invalid material handle for updating material." and does nothing.
values
The whole new record. Its handle field is ignored.

4Textures

At the call

Reads only the image header (width, height), creates the texture with that size, and returns its handle. You can put it in a material at once.

Later

A worker decodes the pixels to RGBA8. A later beginFrame uploads them and builds all mip levels on the CPU. Then isLoaded is true and waiting entities are drawn.

TextureHandle loadTexture(const std::string& path, Format format = Format::R8G8B8A8_SRGB);

Starts loading a .png, .jpg or .jpeg image. Images with fewer channels are expanded to RGBA.

path
Relative to EngineConfig::assetRoot, or absolute. The extension is checked in lower case only.
format
R8G8B8A8_SRGB (default) for color: albedo and emissive. R8G8B8A8_UNORM for data: normal, metallic-roughness and occlusion maps. Any other format logs "loadTexture requires RGBA8 sRGB or UNORM format." and returns an invalid handle.

loads in the background The same path with the same format returns the same handle. The same file as sRGB and as UNORM gives two textures.

ProblemWhenResult
Wrong format, unknown extension, or a header that cannot be read (missing file)at the callerror logged, invalid handle
The pixels do not decodein a later beginFrameerror logged, the texture stays white; isLoaded becomes true
bool isLoaded(TextureHandle texture) const;

True when the texture's pixels are uploaded (also after a failed decode, which leaves it white). False while it loads and for an invalid handle. Textures that did not come from loadTexture (glTF textures, createTexture) are always loaded.

5Bindless textures

All textures that shaders can sample sit in one descriptor set: an array of MAX_BINDLESS_TEXTURES (1024) slots, binding 0 of set 0, seen by fragment shaders. Materials fill it for you. You need these functions only for your own shaders, like the overlay of examples/01_render_graph/main.cpp:

// Slang: the array the engine binds
[[vk::binding(0, 0)]]
Sampler2D gTextures[];

// C++: find the slot, then pass it in a push constant
const rasm::TextureHandle texture = engine.getRenderTargetTexture(rtHandle);
uint32_t textureIndex = engine.getBindlessTextureIndex(texture);
ctx.bindDescriptorSet(commandBuffer, overlayPipeline,
                      engine.getBindlessDescriptorSet(), 0);
ctx.pushConstants(commandBuffer, overlayPipeline, rasm::ShaderType::VERTEX_FRAGMENT,
                  &textureIndex, sizeof(textureIndex), 0);

uint32_t addBindlessTexture(const DescriptorSetHandle& bindlessSet, const TextureHandle& texture, SamplerType sampler = SamplerType::LINEAR_REPEAT, uint32_t slot = MAX_BINDLESS_TEXTURES);

Writes the texture into a slot of the bindless set, with one of the shared samplers. The slot is usable at once.

bindlessSet
Pass getBindlessDescriptorSet().
texture
Any texture created as sampled.
sampler
Filter and edge mode, see SamplerType.
slot
MAX_BINDLESS_TEXTURES (the default): the next free slot. A number below it: that slot, replacing what was there.
returns
The slot, or UINT32_MAX on error ("Failed to add bindless texture." is logged): all 1024 slots used, a bad slot or sampler, or an unknown texture.

Each call without a slot takes a new slot, even for a texture that already has one. Slots are never freed. getBindlessTextureIndex then returns the newest slot.

uint32_t getBindlessTextureIndex(const TextureHandle& texture);

The texture's slot in the bindless set, or UINT32_MAX if it was never added. For a render target, ask with getRenderTargetTexture every frame, because each frame slot has its own color texture.

enum class SamplerType
{
    LINEAR_REPEAT,
    LINEAR_MIRRORED_REPEAT,
    LINEAR_CLAMP,
    NEAREST_REPEAT,
    NEAREST_MIRRORED_REPEAT,
    NEAREST_CLAMP,
    COUNT,
};

The six samplers that all bindless textures share (in rasm/render/resource.h; also on low-level.html). LINEAR_* filter smoothly between pixels and mip levels, with 8× anisotropic filtering. NEAREST_* take the closest pixel (pixel art, data). The *_REPEAT samplers tile the image, *_MIRRORED_REPEAT tile it with every other copy flipped, and *_CLAMP stretch the edge pixels. COUNT is not a sampler.

6What glTF import creates

loadGLTF turns each glTF material into a Material and each image into a texture. This runs on the main thread when the file's upload starts, in beginFrame.

Every import uses up limits

Each glTF material takes one of the 254 free materials and each image one or more bindless slots, and they are never freed (D4). Two files that share a material or image create it twice. A primitive without a material uses the entity's material.
