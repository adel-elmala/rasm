API reference

Materials and textures

A material says how a surface looks: PBR (lit) or unlit, up to six textures, and a few numbers such as base color and roughness. Every material is one row in a GPU table, and every texture gets a slot in one big bindless texture array. One shader reads both for all objects.

In short

  • createMaterial(MaterialType::PBR, {albedo}) makes a material; the vector order is PbrSlot.
  • Change a material: copy it with getMaterial, edit, updateMaterial. Every object that uses it changes in the next frame.
  • loadTexture loads in the background. Its format names the slot: color textures are sRGB (the default); normal, metallic-roughness and occlusion maps must be R8G8B8A8_UNORM. A .ktx2 file stays block-compressed on the GPU (texture compression).
  • An entity waits, undrawn, until all its textures are loaded.
  • Limits: EngineConfig::maxMaterials materials alive at once (4096 by default), 1024 texture slots (MAX_BINDLESS_TEXTURES). A destroyed material's row and a destroyed texture's slot are reused.

1Create a material

enum class MaterialType { PBR, UNLIT, COUNT };
PBR
Lit by the scene's lights (metallic-roughness model). Reads the texture slots listed in the slot table.
UNLIT
Only the base color (texture × factor), not lit. It goes through the tone map like every other color (Tone mapping).
COUNT
Not a type; it counts the values.
MaterialHandle createMaterial(MaterialType type, std::vector<TextureHandle> textures = {}, bool doubleSided = false);

Creates a material with the default values below and writes its row. Each valid texture without a bindless slot gets one; a texture that already has a slot keeps it, so materials can share textures. Entities that use the material can be drawn from the next frame on.

type
PBR or UNLIT.
textures
In PbrSlot order: albedo, metallic, roughness, normal, occlusion, emissive. Leave the end out, or pass {} for an empty slot. Entries after the sixth are ignored. Textures that still load are fine.
doubleSided
True: back faces are drawn too (no culling) and lit with the flipped normal.

Returns an invalid handle and logs an error when EngineConfig::maxMaterials materials are alive (the default material is one of them); the error names the field. destroyMaterial gives a row back.

// examples/00_hello_scene
rasm::TextureHandle albedo = engine.loadTexture("models/obj/bunny/bunny-atlas.jpg");
rasm::MaterialHandle material =
    engine.createMaterial(rasm::MaterialType::PBR, {albedo});

// Your own normal map: data, so UNORM. It goes in slot 3 (NORMAL),
// so slots 1 and 2 stay empty.
rasm::TextureHandle normal =
    engine.loadTexture("brick_normal.png", rasm::Format::R8G8B8A8_UNORM);
std::vector<rasm::TextureHandle> textures = {albedo, {}, {}, normal};
rasm::MaterialHandle brick = engine.createMaterial(rasm::MaterialType::PBR, textures);

Default values

Entities without a material, and sub-meshes whose material is missing, use the default material that the engine makes at start. It follows glTF: white, metallic 1, roughness 1.

2The Material record

struct Material
{
    const char*      name{};
    MaterialHandle   handle{};
    MaterialType     type{};
    TextureHandle    textures[MAX_TEXTURE_SLOTS];
    uint32_t         texCoords[MAX_TEXTURE_SLOTS];
    TextureTransform textureTransforms[MAX_TEXTURE_SLOTS];
    float            params[MAX_PARAM_SLOTS];
    bool             doubleSided{};
    AlphaMode        alphaMode{};
    float            alphaCutoff  = 0.5f;
};
name
A label: "pbr", "unlit", or "default". The engine keeps only the pointer, so point it at a string that lives as long as the engine (a string literal).
handle
The material's own handle. updateMaterial keeps the right one, whatever you put here.
type
PBR or UNLIT.
textures
One texture per PbrSlot; an invalid handle means none.
texCoords
Which UV set (0, 1 or 2) each texture uses. Default 0. A value of 3 or more uses set 0.
textureTransforms
An offset, rotation and scale of each texture's UVs (TextureTransform). METALLIC's is the metallic-roughness texture's; ROUGHNESS's is not read.
params
The numbers, indexed by PbrParam (diagram above). All are linear values.
doubleSided
Draw back faces too.
alphaMode
Solid, cut-out or see-through (AlphaMode). Default NONE: solid.
alphaCutoff
For MASK: no pixel where alpha is below it. Default 0.5.

The flat params array is easy to index wrongly; docs/code_review.md plans a typed struct (C9).

enum class PbrSlot { ALBEDO, METALLIC, ROUGHNESS, NORMAL, OCCLUSION, EMISSIVE, COUNT };

Index into textures and texCoords. MAX_TEXTURE_SLOTS = 6 (PbrSlot::COUNT).

SlotFormatWhat the shader reads
ALBEDOR8G8B8A8_SRGBRGBA × albedo factor × the vertex color. Alpha counts only with MASK or BLEND.
METALLICR8G8B8A8_UNORMThe glTF metallic-roughness texture: G × roughness factor, B × metallic factor.
ROUGHNESSR8G8B8A8_UNORMNothing: roughness comes from the METALLIC texture's G. glTF import puts the same texture in both slots.
NORMALR8G8B8A8_UNORMTangent-space normal, scaled by NORMAL_SCALE. Uses the vertex tangent, or builds one from the UVs.
OCCLUSIONR8G8B8A8_UNORMR, mixed in by OCCLUSION_STRENGTH. It darkens only the ambient light.
EMISSIVER8G8B8A8_SRGBRGB × emissive factor × emissive strength, added to the result. The factor alone glows without a texture.

UNLIT materials read only ALBEDO. The format column is a rule: a data texture in an sRGB format gives wrong values, and nothing checks it.

enum class PbrParam : uint32_t
{
    ALBEDO              = 0,      // vec4
    METALLIC            = 4,      // float
    ROUGHNESS           = 5,      // float
    NORMAL_SCALE        = 6,      // float
    OCCLUSION_STRENGTH  = 7,      // float
    EMISSIVE_FACTOR     = 8,      // vec3
    EMISSIVE_STRENGTH   = 11,     // float

    COUNT = 12,
};

Offsets into params. MAX_PARAM_SLOTS = 12 (PbrParam::COUNT). Roughness is clamped to 0.045 – 1 and metallic to 0 – 1 in the shader. The albedo's fourth float is its alpha (glTF's base color alpha). EMISSIVE_STRENGTH multiplies the emissive factor, so a glow can pass 1 (glTF KHR_materials_emissive_strength).

enum class AlphaMode : uint32_t
{
    NONE,
    MASK,
    BLEND,
};

How a material uses its alpha (albedo factor × texture × vertex color), glTF's alphaMode. The transparency guide explains each.

NONE
Solid; alpha is ignored. This is glTF's OPAQUE (that name is a macro in <windows.h>).
MASK
A cut-out: no pixel where alpha < alphaCutoff, solid elsewhere. Leaves, fences, decals with hard edges. Its shadow has the same holes.
BLEND
See-through: drawn after everything else, sorted back to front, mixed with what is behind by its alpha, and not written to depth. Glass, smoke, water. Its shadow is as dense as its alpha.

Changing it with updateMaterial moves the material's entities to another draw run in the next frame.

struct TextureTransform
{
    glm::vec2      offset       = glm::vec2(0.0f);
    float          rotation     = 0.0f;
    glm::vec2      scale        = glm::vec2(1.0f);
};

Moves a texture on the surface (glTF KHR_texture_transform): the UVs are scaled, then turned by rotation radians, then moved by offset. The default changes nothing. Tiling a texture 4 times is a scale of 4; a texture atlas uses scale and offset to pick its part.

auto values = engine.getMaterial(floor);
values.textureTransforms[static_cast<uint32_t>(rasm::PbrSlot::ALBEDO)].scale = glm::vec2(4.0f);
engine.updateMaterial(floor, values);

3Read and change a material

  1. Copy it. getMaterial returns a reference into the engine's list. Copy it into a local variable (auto values = ...): the reference can move when another material is created.
  2. Edit the copy. Change factors, textures, the type or doubleSided.
  3. Call updateMaterial. It replaces the whole record. New textures get bindless slots now, and the row is rewritten in CPU memory.
  4. Next beginFrame. The row is uploaded, so every entity that uses the material shows the change in that frame. It costs one row, however many entities use it.
  5. If a new texture still loads, the entities that use the material are not drawn until it finishes, so nothing is drawn half-loaded. A changed doubleSided or alphaMode rebuilds the draw lists of their scenes.
// examples/03_instances: one material; the 10 spinning cubes and up to
// 2,000 spawned cubes that use it change color every frame.
auto values = engine.getMaterial(pulse);
const auto albedo = static_cast<uint32_t>(rasm::PbrParam::ALBEDO);
values.params[albedo] = 0.5f + 0.5f * std::sin(t);
values.params[albedo + 1] = 0.5f + 0.5f * std::sin(t + 2.1f);
values.params[albedo + 2] = 0.5f + 0.5f * std::sin(t + 4.2f);
engine.updateMaterial(pulse, values);
const Material& getMaterial(const MaterialHandle& handle);

The material's current values. An invalid handle returns the default material. A handle that looks valid but is unknown logs an error and also returns the default material.

void destroyMaterial(MaterialHandle material);

Destroys the material. What used it falls back from the next frame on: an entity made with it uses its mesh's material or the default one, and a glTF sub-mesh that used it uses its entity's material. Their instance rows are rewritten, and the material's row goes to the next material at once. Its textures stay: they are yours, or the mesh's that imported them. The default material is refused.

Nothing is searched when no entity uses the material (destroy the entities first); otherwise every entity is checked once.

void updateMaterial(MaterialHandle material, const Material& values);

Replaces the material's values (steps above). Every entity and glTF sub-mesh that uses it changes in the next frame.

material
The material to change. Invalid: logs "Invalid material handle for updating material." and does nothing.
values
The whole new record. Its handle field is ignored.

4Textures

At the call

Reads only the image header (width, height), creates the texture with that size, and returns its handle. You can put it in a material at once.

Later

A worker decodes the pixels to RGBA8, or reads and transcodes a .ktx2 file. A later beginFrame uploads them: an image's mip levels are built on the CPU, a KTX2 file's come from the file. Then isLoaded is true and waiting entities are drawn.

TextureHandle loadTexture(const std::string& path, Format format = Format::R8G8B8A8_SRGB);

Starts loading a .png, .jpg or .jpeg image, or a .ktx2 file. Images with fewer channels are expanded to RGBA.

path
Relative to EngineConfig::assetRoot, or absolute. The extension is checked in lower case only.
format
The slot the texture is for. R8G8B8A8_SRGB (default) for a color slot: albedo and emissive. R8G8B8A8_UNORM for a data slot: normal, metallic-roughness and occlusion maps. Any other format logs "loadTexture takes R8G8B8A8_SRGB for a color slot or R8G8B8A8_UNORM for a data slot." and returns an invalid handle.

An image is uploaded in exactly that format. A .ktx2 file gets the best GPU format the device has for the slot and the file's channels, which getTextureDesc then reports:

Slot, channels in the fileFormat, best first
color (R8G8B8A8_SRGB), anyBC7_SRGB, ASTC_4x4_SRGB, ETC2_R8G8B8A8_SRGB, R8G8B8A8_SRGB
data (R8G8B8A8_UNORM), 3 or 4BC7_UNORM, ASTC_4x4_UNORM, ETC2_R8G8B8A8_UNORM, R8G8B8A8_UNORM
data, 2 (a normal map's x and y)BC5_UNORM, EAC_R11G11_UNORM, R8G8B8A8_UNORM with z computed
data, 1BC4_UNORM, EAC_R11_UNORM, R8G8B8A8_UNORM

A Basis file (ETC1S or UASTC) is transcoded on the worker; any other KTX2 file keeps its own format, read as sRGB or UNORM by the slot, and fails if the device can't sample it. The file's mips are used. A Basis file without mips becomes RGBA8 with mips made on the worker, and logs a warning that names the file and the fix (ktx create --generate-mipmap).

loads in the background The same path with the same format returns the same handle. The same file as sRGB and as UNORM gives two textures.

bool isLoaded(TextureHandle texture) const;

True when the texture's pixels are uploaded (also after a failed decode, which leaves it white). False while it loads and for an invalid handle. Textures that did not come from loadTexture (glTF textures, createTexture) are always loaded.

5Bindless textures

All textures that shaders can sample sit in one descriptor set: an array of MAX_BINDLESS_TEXTURES (1024) slots, binding 0 of set 0, seen by every shader stage, compute included. Materials fill it for you. You need these functions only for your own shaders, like the full-screen passes of examples/01_render_graph/main.cpp:

// Slang: the array the engine binds
[[vk::binding(0, 0)]]
Sampler2D gTextures[];

// C++: find the slot, then pass it in a push constant
const rasm::TextureHandle texture = engine.getRenderTargetTexture(rtHandle);
uint32_t textureIndex = engine.getBindlessTextureIndex(texture);
ctx.bindDescriptorSet(commandBuffer, overlayPipeline,
                      engine.getBindlessDescriptorSet(), 0);
ctx.pushConstants(commandBuffer, overlayPipeline, &textureIndex, sizeof(textureIndex), 0);

uint32_t addBindlessTexture(const DescriptorSetHandle& bindlessSet, const TextureHandle& texture, SamplerType sampler = SamplerType::LINEAR_REPEAT, uint32_t slot = MAX_BINDLESS_TEXTURES);

Writes the texture into a slot of the bindless set, with one of the shared samplers. The slot is usable at once.

bindlessSet
Pass getBindlessDescriptorSet().
texture
Any texture created as sampled.
sampler
Filter and edge mode, see SamplerType.
slot
MAX_BINDLESS_TEXTURES (the default): the texture's own slot if it has one, else a free slot. A number below it: that slot, replacing what was there; the texture that held it loses it.
returns
The slot, or UINT32_MAX on error ("Failed to add bindless texture." is logged): all 1024 slots held or waiting for the GPU, a bad slot or sampler, or an unknown or destroyed texture.

A texture holds one slot: a second call without a slot returns it unchanged, since a frame in flight may sample it (a different sampler logs an error; make a second texture for it). The slot is freed with the texture (destroyTexture), once no frame in flight samples it, and then reused.

uint32_t getBindlessTextureIndex(const TextureHandle& texture);

The texture's slot in the bindless set, or UINT32_MAX if it was never added. For a render target, ask with getRenderTargetTexture (or getRenderTargetDepthTexture for its depth) every frame, because a history target has a texture per frame slot.

enum class SamplerType
{
    LINEAR_REPEAT,
    LINEAR_MIRRORED_REPEAT,
    LINEAR_CLAMP,
    NEAREST_REPEAT,
    NEAREST_MIRRORED_REPEAT,
    NEAREST_CLAMP,
    COUNT,
};

The six samplers that all bindless textures share (in rasm/render/resource.h; also on low-level.html). LINEAR_* filter smoothly between pixels and mip levels, with 8× anisotropic filtering. NEAREST_* take the closest pixel (pixel art, data). The *_REPEAT samplers tile the image, *_MIRRORED_REPEAT tile it with every other copy flipped, and *_CLAMP stretch the edge pixels. COUNT is not a sampler.

Every import uses up limits

Each glTF material takes one of the 254 free materials and each image one or more bindless slots, and they belong to the mesh: destroyMesh destroys them with it. Two files that share a material or image create it twice. A primitive without a material uses the entity's material.
