API reference

RenderContext and resources

RenderContext is the engine's thin, backend-neutral layer over the GPU. It creates buffers, textures and pipelines, and records commands into a command buffer. Inside a render graph pass you get it as the callback's argument; elsewhere from engine.getRenderContext(). Everything is addressed by handles.

CPU work GPU work GPU buffer

In short

  • Record into engine.getCurrentFrameResources().commandBuffer, between beginFrame and endFrame. The engine begins, ends and submits it.
  • Draws go inside a render pass, dispatches and barriers outside. Calls in the wrong place are refused.
  • Shaders read buffers through device addresses (getBufferDeviceAddress), passed in the 16-byte push constant. There are no vertex buffers.
  • fillBuffer writes mapped buffers at once and queues the others for the next submit.
  • Nothing is destroyed for you, and buffers and textures are never shared: each create call makes a new one.

1How errors are reported

ProblemWhat happens
Unknown handle (never created, destroyed)Logs <function>: buffer handle not found. (or texture, pipeline, …). The call does nothing and returns false, 0 or an invalid handle.
Invalid use: a wrong argument, or a call in the wrong place (a draw outside a pass, a dispatch inside one)Logs the reason. In debug builds an assert stops in the debugger; in release builds the call fails as above.
The backend fails (out of memory, device limit)Logs the backend's error and returns an invalid handle or false.

2Getting at it

RenderContext& getRenderContext();

The engine's one RenderContext. It lives as long as the engine.

const FrameResources& getCurrentFrameResources();

The resources of the current frame slot (0 or 1): the frame's commandBuffer, the swapchain-sized depthTexture and the slot's fence value. See FrameResources. Between beginFrame and endFrame the command buffer is recording; record your commands into it. The slot changes in endFrame, so fetch it every frame.

DescriptorSetHandle getBindlessDescriptorSet();

The engine's bindless texture set: MAX_BINDLESS_TEXTURES combined image samplers at set 0, binding 0, visible to every shader stage (ShaderType::ALL). Pipelines from createPipeline and createComputePipeline use its layout. Bind it with bindDescriptorSet(commandBuffer, pipeline, set, 0) before drawing or dispatching with a pipeline that samples textures. See Materials and textures for how textures get a slot.

3Recording commands

void bindPipeline(const CommandBufferHandle& commandBuffer,
                  const PipelineHandle& pipeline);

Binds a graphics or compute pipeline. A compute pipeline makes dispatch possible and leaves the graphics pipeline alone.

errors A graphics pipeline whose color or depth format differs from the current pass's attachments logs Pipeline '…' does not match the formats of the pass's attachments, so its draws are skipped. Then every draw is skipped until a matching pipeline is bound. An unknown pipeline also skips draws and dispatches.

void bindDescriptorSet(const CommandBufferHandle& commandBuffer,
                       const PipelineHandle& pipeline,
                       const DescriptorSetHandle& descriptorSet,
                       uint32_t setIndex = 0);

Binds a descriptor set for pipeline's bind point. Every pipeline has exactly one set, at index 0, so setIndex is 0. In practice the set is getBindlessDescriptorSet().

void pushConstants(const CommandBufferHandle& commandBuffer,
                   const PipelineHandle& pipeline, ShaderType stage,
                   const void* data, uint32_t size, uint32_t offset = 0);

Copies up to 16 bytes into the push constants, which the next draws or dispatches read.

stage
ShaderType::COMPUTE for a compute pipeline, ShaderType::VERTEX_FRAGMENT for a graphics pipeline. Anything else is refused.
size, offset
Bytes. offset + size must be at most PUSH_CONSTANTS_SIZE (16); a bigger push logs an error and is dropped. A typical layout is one 8-byte buffer address and two 4-byte values.
void bindIndexBuffer(const CommandBufferHandle& commandBuffer,
                     const BufferHandle& buffer, uint64_t offset,
                     Format indexType);

Binds an index buffer for drawIndexed and the indirect indexed draws. The buffer needs BufferUsage::INDEX.

offset
Bytes from the start of the buffer.
indexType
Format::U16_UINT or Format::U32_UINT.
bool setViewport(const CommandBufferHandle& commandBuffer, float x, float y,
                 float width, float height,
                 float minDepth = 0.0f, float maxDepth = 1.0f);

Sets the viewport, in pixels, with x, y at the top-left corner. RASM flips it (negative height) so that clip space is Y-up. beginPass already sets it to the whole target; change it to draw into a part of it, as examples/01_render_graph does to keep the image's shape.

The scene passes set no viewport: they draw with the one beginPass sets, over the whole target, and their Hi-Z covers the whole target too (occlusion culling).

const Viewport& getViewport() const;

The last viewport given to setViewport, on any command buffer. See Viewport. Nothing in the engine reads it.

bool setScissor(const CommandBufferHandle& commandBuffer, int32_t x,
                int32_t y, uint32_t width, uint32_t height);

Sets the scissor rectangle in pixels, top-left origin. beginPass sets it to the whole target.

bool setCullMode(const CommandBufferHandle& commandBuffer, CullMode cullMode);

Sets which faces the next draws skip. Every pipeline takes its cull mode from here. Front faces are counter-clockwise. beginPass sets CullMode::NONE, and the scene's draw passes change it for each run of draws and set it back.

void draw(const CommandBufferHandle& commandBuffer,
          const uint32_t vertexCount, uint32_t instanceCount = 1);

Draws vertexCount vertices with no vertex buffer; the vertex shader uses SV_VertexID, which counts from 0. Must be inside a render pass with a graphics pipeline bound. draw(commandBuffer, 3) with a full-screen triangle is the usual post-process pass.

void drawIndexed(const CommandBufferHandle& commandBuffer,
                 uint32_t indexCount, uint32_t instanceCount = 1,
                 uint32_t vertexOffset = 0, uint32_t firstIndex = 0,
                 uint32_t firstInstance = 0);

Draws with the bound index buffer. vertexOffset is added to each index. Inside a render pass only.

void drawIndexedIndirect(const CommandBufferHandle& commandBuffer,
                         const BufferHandle& drawInfoBuffer, uint32_t offset,
                         uint32_t drawCount, uint32_t stride);

Draws drawCount indexed draws whose parameters the GPU reads from drawInfoBuffer (usage INDIRECT). Each record starts with five 32-bit values: index count, instance count, first index, vertex offset, first instance.

offset
Byte offset of the first record.
stride
Bytes from one record to the next; at least 20.
void drawIndexedIndirectCount(const CommandBufferHandle& commandBuffer,
                              const BufferHandle& drawInfoBuffer,
                              uint64_t offset,
                              const BufferHandle& countBuffer,
                              uint64_t countOffset, uint32_t maxDrawCount,
                              uint32_t stride);

The same, but the GPU also reads the number of draws, a uint32_t at countOffset in countBuffer, and draws at most maxDrawCount. This is how the scene's draw passes draw what culling kept.

void dispatch(const CommandBufferHandle& commandBuffer, uint32_t groupCountX,
              uint32_t groupCountY = 1, uint32_t groupCountZ = 1);

Runs the bound compute pipeline on groupCountX × groupCountY × groupCountZ work groups. The group size is the shader's [numthreads], so for N items use (N + size − 1) / size groups.

errors Refused inside a render pass (dispatches must be recorded outside a render pass (use RenderGraph::addComputePass).) and when no compute pipeline is bound.

void memoryBarrier(const CommandBufferHandle& commandBuffer,
                   PipelineStage before, PipelineStage after);

Makes buffer writes of the before stages finish and become visible to the after stages. It covers every way shaders, indirect draws, index fetch and the CPU touch buffers. It does not change texture layouts (use transitionImageLayout). Outside a render pass only.

before, after
One or more PipelineStage flags, combined with |.

The render graph already puts one around compute passes. Record your own between two dependent dispatches (COMPUTE → COMPUTE), and before reading a buffer on the CPU (… → HOST).

void aliasingBarrier(const CommandBufferHandle& commandBuffer);

For textures that share memory. The attachment writes after it wait for every earlier use of any texture: attachment writes, and reads in fragment and compute shaders. A layout transition covers only its own texture, so it does not order the writes of another texture placed in the same memory. Outside a render pass only.

RenderGraph::execute records one before the first pass of each transient render target. Record your own only if you place textures in shared memory yourself.

enum class PipelineStage : uint32_t
{
    COMPUTE  = 1u << 0,
    GRAPHICS = 1u << 1,
    HOST     = 1u << 2,
};

constexpr PipelineStage operator|(PipelineStage a, PipelineStage b);
constexpr bool          hasStage(PipelineStage stages, PipelineStage stage);

Flags for memoryBarrier. operator| combines them; hasStage tests one.

COMPUTE
Compute shaders.
GRAPHICS
Indirect argument reads, index fetch, vertex and fragment shaders.
HOST
The CPU: readBuffer after the barrier, or CPU writes before it.
bool beginRendering(const CommandBufferHandle& commandBuffer,
                    const TextureHandle* colorAttachments,
                    uint32_t colorCount,
                    TextureHandle depthAttachment,
                    const glm::vec4& clearColor,
                    const AttachmentOps& ops = {});

Starts a render pass into colorCount color textures (1 to MAX_COLOR_ATTACHMENTS) and one depth texture. By default every color is cleared to clearColor and depth to 0; one load op serves all colors. Color is kept (stored) at the end of the pass; depth only with ops.storeDepth. Pass an invalid depthAttachment for a pass without depth; its pipelines must then have Format::UNKNOWN as their depth format.

ops
See AttachmentOps. loadColor / loadDepth keep what an attachment holds instead of clearing it. Use them to draw on top of an earlier pass, as the scene's Scene 2 pass does after Scene 1 and the Hi-Z build. Before a load, transition the attachment to COLOR_ATTACHMENT or DEPTH_STENCIL_ATTACHMENT without discard, even when it is already in that layout: the barrier orders the earlier writes before the load. storeDepth keeps depth for a later load or a read; without it depth may be thrown away, which saves memory bandwidth.

Engine::beginPass calls this after the layout transitions, with its ops (a render graph sets them for each pass), and also sets the viewport, scissor and cull mode, so use beginPass unless you build the whole frame yourself.

bool endRendering(const CommandBufferHandle& commandBuffer);

Ends the render pass. Engine::endPass calls it.

bool transitionImageLayout(const CommandBufferHandle& commandBuffer, TextureHandle texture, TextureUsage newUsage, bool discard = false);

Records a barrier that moves a texture from the use it is in now to newUsage. The context remembers each texture's use, so you name only the new one. The barrier waits for the old use and blocks the new one. SAMPLED covers fragment and compute shaders. The attachment usages cover reads too, for a beginRendering with load.

newUsage
COLOR_ATTACHMENT, DEPTH_STENCIL_ATTACHMENT, SAMPLED or PRESENT_SRC.
discard
true drops the contents: the barrier starts from UNKNOWN, which still waits for every earlier use. Use it before a pass that clears the texture. beginPass does it for its attachments.

The use changes when the barrier is recorded. A successful submit keeps it; for commands that will not run, call discardRecording. Command buffers that touch the same texture must be submitted in the order they were recorded.

errors Another usage logs an error, records nothing and returns false. Inside a render pass it records nothing (barriers are not allowed there). beginPass moves its attachments, endPass moves a render target's color to SAMPLED, endFrame moves the swapchain image to PRESENT_SRC, and a render graph pass that reads a texture, or a target's depth (readDepth), gets it in SAMPLED. Call it yourself only for your own textures outside those steps.

bool beginCommandBuffer(const CommandBufferHandle& commandBuffer);
bool endCommandBuffer(const CommandBufferHandle& commandBuffer);

Start and finish recording. beginFrame and endFrame do this for the frame's command buffer; call them only for a command buffer of your own. beginCommandBuffer also resets the context's recording state (in a pass or not, pipeline bound or not), which is shared by all command buffers, so record one at a time.

BufferHandle createBuffer(const BufferDesc& desc);

The Engine method: forwards to RenderContext::createBuffer. Usable at once.

BufferHandle createBuffer(const BufferDesc& desc);

Creates a new buffer every time (no sharing, B1). Every buffer has a device address and can be a copy source and destination, whatever its usage. Its contents start undefined.

errors A failed allocation logs Failed to create buffer '…' and returns an invalid handle.

struct BufferDesc
{
    std::string name;
    BufferUsage usage        = BufferUsage::STORAGE;
    uint64_t    size         = 0;
    bool        hostVisible  = false;
    bool        hostReadable = false;

    bool operator==(const BufferDesc&) const = default;
};
name
Shown in logs and GPU debuggers.
usage
See BufferUsage.
size
Bytes, greater than 0.
hostVisible
Put it in memory the CPU writes directly. For data you change often from the CPU, with one buffer per frame slot.
hostReadable
Put it in cached memory the CPU reads, for readBuffer.

{
    INDEX,
    INDIRECT,
    UNIFORM,
    STORAGE,
    DEVICE_ADDRESS,

The main use, added on top of device address and copy use, which every buffer has.

INDEX
For bindIndexBuffer.
INDIRECT
Draw records or counts for the indirect draws.
UNIFORM
A uniform buffer.
STORAGE
A storage buffer (the default). Shaders usually reach it by address anyway.
DEVICE_ADDRESS
Only the address and copies.
bool fillBuffer(const BufferHandle& buffer, const void* data, size_t size,
                size_t offset = 0);

Writes size bytes from data at offset (bytes). Your data is copied before the call returns, so you can free it. See the picture above for when the GPU sees it.

errors data null, size 0, or a range past the end of the buffer is refused and returns false.

// Upload 4096 start positions once, before the loop.
// The buffer is device-local: the data goes out with the first submit.
std::vector<glm::vec2> positions(4096);
engine.getRenderContext().fillBuffer(particles, positions.data(),
                                     positions.size() * sizeof(glm::vec2));
bool readBuffer(const BufferHandle& buffer, void* data, size_t size,
                size_t offset = 0);

Copies size bytes at offset from a hostReadable buffer into data. It does not wait for the GPU. Follow these steps so the bytes are the GPU's results:

  1. Write on the GPU A pass writes the buffer, for example with a dispatch.
  2. Barrier to the CPU Record memoryBarrier(commandBuffer, PipelineStage::COMPUTE, PipelineStage::HOST), outside a render pass.
  3. Wait Wait until that frame is done. The simplest way: read it MAX_FRAMES_IN_FLIGHT frames later, after beginFrame has waited for the same frame slot (as the frame stats do). Use one buffer per frame slot.
  4. Read Call readBuffer.

errors A buffer without hostReadable, null data, size 0 or a range past the end is refused and returns false.

uint64_t getBufferDeviceAddress(const BufferHandle& buffer);

The buffer's GPU address. Put it in a push constant (or in another buffer) and use it as a pointer in Slang, e.g. float2* positions;. The address stays the same until resizeBuffer. Returns 0 with an error for an unknown handle.

BufferDesc getBufferDesc(const BufferHandle& buffer);

The desc the buffer was created with. An unknown handle logs an error and returns BufferDesc{}.

bool resizeBuffer(const BufferHandle& buffer, uint64_t size);

Replaces the buffer with a new one of size bytes, made from the same desc, under the same handle. So whatever holds the handle stays valid, for example a render graph's read and write declarations. The scene passes grow their culling buffers this way.

  • The contents are not copied: the new buffer starts undefined.
  • The device address changes: fetch it again with getBufferDeviceAddress.
  • The old buffer is destroyed at once, with its queued uploads, so the GPU must be done with it, as for destroyBuffer.

errors An unknown handle logs resizeBuffer: buffer handle not found. and returns false. When the new buffer cannot be created it returns false, and the old buffer stays.

void destroyBuffer(const BufferHandle& buffer);

Destroys the buffer at once and drops its queued uploads. The GPU must be done with it: no frame in flight may still use it. The handle is not reused, but it is not detected as stale either (D4).

5Textures

TextureHandle createTexture(const TextureDesc& desc);

The Engine method: forwards to RenderContext::createTexture. For image files use loadTexture instead, which decodes, uploads and makes the texture bindless.

TextureHandle createTexture(const TextureDesc& desc);

Creates a new 2D texture every time (B1). A SAMPLED texture in an RGBA8 format (R8G8B8A8_UNORM, R8G8B8A8_SRGB, B8G8R8A8_SRGB) gets a full mip chain; every other texture has one level. Fill a sampled texture with fillTexture.

errors A size above the device's limit, or a failed allocation, logs an error and returns an invalid handle.

struct TextureDesc
{
    std::string  name;
    uint32_t     width  = 0;
    uint32_t     height = 0;
    Format       format = Format::UNKNOWN;
    TextureUsage usage  = TextureUsage::SAMPLED;

    bool operator==(const TextureDesc&) const = default;
};
width, height
Pixels.
format
See Format. Color data uses R8G8B8A8_SRGB; normal, metallic-roughness and occlusion data R8G8B8A8_UNORM.
usage
What the texture is created for, see TextureUsage.
enum class TextureUsage
{
    TRANSFER_SRC,
    TRANSFER_DST,
    SAMPLED,
    STORAGE,
    COLOR_ATTACHMENT,
    DEPTH_STENCIL_ATTACHMENT,
    SAMPLED_COLOR_ATTACHMENT,
    SAMPLED_DEPTH_ATTACHMENT,
    TRANSIENT_ATTACHMENT,
    INPUT_ATTACHMENT,

    UNKNOWN,
};

bool fillTexture(const TextureHandle& texture, const void* data);

Copies pixels from the CPU straight into a SAMPLED texture (host image copy), builds its whole mip chain on the CPU (sRGB-aware for sRGB formats), and leaves it ready for sampling. It finishes before it returns; there is no command buffer involved.

data
width × height × 4 bytes of RGBA8, rows top to bottom, no padding.

The texture must not be in use by a frame the GPU is still running. Returns false with an error when a copy step fails.

TextureDesc getTextureDesc(const TextureHandle& texture);

The desc the texture was created with. An unknown handle logs an error and returns TextureDesc{}.

void destroyTexture(const TextureHandle& texture);

Destroys the texture at once. The GPU must be done with it. A bindless slot that points at it is not freed or cleared, so no shader may sample that slot afterwards.

errors Swapchain images are refused: Swapchain images belong to the swapchain and can't be destroyed.

uint32_t updateBindlessDescriptorSet(
    const DescriptorSetHandle& bindlessSet,
    const TextureHandle& texture,
    SamplerType sampler = SamplerType::LINEAR_REPEAT,
    uint32_t slot = MAX_BINDLESS_TEXTURES);

Writes texture with sampler into a slot of the bindless set and returns the slot, which shaders use as the array index. The descriptor promises the sampled layout, so the texture must be in it when a shader reads it. Prefer Engine::addBindlessTexture, which calls this and also remembers the slot for getBindlessTextureIndex.

slot
MAX_BINDLESS_TEXTURES (the default) takes the next free slot. A smaller value overwrites that slot; later automatic slots go past it. Slots are never given back.

errors All slots used, or a slot above MAX_BINDLESS_TEXTURES, logs Slot index exceeds maximum bindless textures. and returns UINT32_MAX, as does an unknown set or texture.

enum class SamplerType
{
    LINEAR_REPEAT,
    LINEAR_MIRRORED_REPEAT,
    LINEAR_CLAMP,
    NEAREST_REPEAT,
    NEAREST_MIRRORED_REPEAT,
    NEAREST_CLAMP,
    COUNT,
};

One of six fixed samplers, shared by all bindless textures. LINEAR_* filters linearly between pixels and mip levels, with 8× anisotropy. NEAREST_* takes the nearest pixel and mip level. The suffix is what happens outside [0, 1]: repeat, mirror, or clamp to the edge. Render targets use LINEAR_CLAMP. COUNT is not a sampler.

6Shaders, pipelines and descriptors

Most applications use Engine::createPipeline and Engine::createComputePipeline, which compile Slang source and call the functions below. Use these directly only for a pipeline with other attachment formats or topology.

ShaderHandle createShader(const ShaderDesc& desc);

Creates a shader module from compiled code (SPIR-V for Vulkan). An equal ShaderDesc gives back the existing handle.

errors Empty code or an empty entryPoint is refused.

struct ShaderDesc
{
    std::string          name;
    ShaderType           type = ShaderType::VERTEX;
    std::string          entryPoint;
    std::vector<uint8_t> code;

    bool operator==(const ShaderDesc&) const = default;
};
type
VERTEX, FRAGMENT or COMPUTE, see ShaderType.
entryPoint
The function name inside code, e.g. vertMain.
code
The compiled bytes.
PipelineHandle createPipeline(const PipelineDesc& desc);

Creates a graphics pipeline (vertex + fragment shader) or a compute pipeline (compute shader). An equal PipelineDesc gives back the existing handle. Every pipeline has one descriptor set (the layout in the desc) and a 16-byte push constant range. A graphics pipeline has no vertex input, no blending, depth test and write with GREATER_OR_EQUAL, counter-clockwise front faces, and dynamic viewport, scissor and cull mode.

errors A desc with both a compute shader and a vertex or fragment shader is refused, as are shaders of the wrong type. An unknown layout or shader returns an invalid handle.

struct PipelineDesc
{
    std::string               name;
    ShaderHandle              vertexShader;
    ShaderHandle              fragmentShader;
    ShaderHandle              computeShader;
    DescriptorSetLayoutHandle descriptorSetLayout;
    PrimitiveTopology         topology = PrimitiveTopology::TRIANGLE_LIST;
    Format                    colorAttachmentFormats[MAX_COLOR_ATTACHMENTS] = {};
    Format                    depthStencilAttachmentFormat = Format::UNKNOWN;

    bool operator==(const PipelineDesc&) const = default;
};
computeShader
Valid for a compute pipeline; then leave the vertex and fragment shaders invalid.
descriptorSetLayout
Required. Usually the engine's bindless layout (the one Engine::createPipeline uses).
topology
See PrimitiveTopology.
colorAttachmentFormats

depthStencilAttachmentFormat
The same for the depth format.
uint32_t colorAttachmentCount(const Format* formats);

How many of the MAX_COLOR_ATTACHMENTS formats at formats come before the first UNKNOWN: the number of color attachments a PipelineDesc or RenderTargetDesc describes. A format after a gap does not count.

DescriptorSetLayoutHandle createBindlessDescriptorSetLayout(

7Render targets

RenderTargetHandle createRenderTarget(const RenderTargetDesc& desc);

What Engine::createRenderTarget calls: a color and a depth texture, or one pair per frame slot with history, the colors made bindless with LINEAR_CLAMP. See RenderTargetDesc. The copies of a history target are cleared to clearColor by clearNewHistory at the start of the next frame.

errors These stop in the debugger in a debug build and return an invalid handle: no color format (a render target needs at least one color format.), a gap in colorFormats (a render target's color formats can't have a gap.), or no depth format (a render target needs a depth format.). createTransientRenderTarget checks the same.

RenderTargetHandle createTransientRenderTarget(const RenderTargetDesc& desc);

What PassBuilder::createRenderTarget calls for a target without history. The handle and the target's size and formats exist at once; the textures only after placeTransientRenderTargets. You rarely call it yourself: the render graph does.

errors A desc with history stops in the debugger in a debug build and returns an invalid handle: a history render target lives across frames, so it can't be transient.

bool placeTransientRenderTargets(const RenderTargetHandle* renderTargets,
                                 const uint32_t* firstPasses,
                                 const uint32_t* lastPasses,
                                 uint32_t count);

Creates the textures of count transient targets in shared heaps. Target i is in use from pass position firstPasses[i] to lastPasses[i], both included. Targets whose ranges do not overlap may get the same memory (see Transient render targets). The textures keep their bindless slots, and the call logs the heap size against the size without sharing.

If one of the targets was placed before, its old group is replaced: the call first waits for the device to be idle, then frees the old heaps. RenderGraph::execute calls this after a compile that changed the targets' lifetimes. Returns false and logs an error if a heap or texture cannot be created; those targets then have no textures, and the graph tries again the next frame.

void destroyTransientRenderTargets(const RenderTargetHandle* renderTargets, uint32_t count);

Destroys transient targets: their textures, their handles, and the heaps of each group that has no target left. It waits for the device to be idle first, so call it outside the frame loop. Handles that are unknown or not transient are skipped. The RenderGraph destructor calls it for the graph's targets.

void clearNewHistory(const CommandBufferHandle& commandBuffer);

Records a clear to clearColor of every history copy made since the last call, and leaves the colors in the sampled layout. So the previous frame's copy can be read on the first frame, and after a resize. Engine::beginFrame calls it, before any pass. If the frame is not submitted, discardRecording keeps the clears for the next call.

void resizeRenderTargets();

Rebuilds every render target with a swapchainScale at the swapchain's current size, and places each transient group that holds one again. The handles and bindless slots stay the same. The engine calls it after the swapchain is created again, with the device idle. Do not call it while the GPU may use the targets.

const RenderTarget& getRenderTarget(const RenderTargetHandle& handle);

The target's textures (attachments[slot].color[i] for each of its colorCount color attachments, and .depth, per frame slot; without history every slot holds the same textures), size, formats, clear color and history. See RenderTarget. An unknown handle logs Render target handle not found. and returns an empty target with invalid handles.

8Frames, fences and the swapchain

The engine runs these for you

beginFrame and endFrame wait for the frame slot, acquire, begin and end the command buffer, submit and present. Call the functions below yourself only for extra work outside the frame, and never acquireNextImage, present or recreateSwapchain while the engine runs frames.

CommandBufferHandle createCommandBuffer(const std::string& name);

Creates a command buffer for the one graphics queue.

FenceHandle createFence(const std::string& name, uint64_t initialValue = 0);

Creates a timeline fence: a 64-bit counter that a submit sets to a value when its work is done.

bool waitForFence(FenceHandle fence, uint64_t value,
                  uint64_t timeout = UINT64_MAX);

Blocks until the fence reaches value. timeout is in nanoseconds. Returns false with an error on timeout or failure.

bool submit(const CommandBufferHandle* commandBuffers,
            uint32_t commandBufferCount, FenceHandle signalFence,
            uint64_t signalValue, bool presentsSwapchainImage);

Submits up to 8 command buffers as one submission; they run in array order. Pending fillBuffer uploads are submitted first, so these command buffers see their data.

signalFence, signalValue
The fence is set to signalValue when the work is done. An invalid handle signals nothing.
presentsSwapchainImage
true only for the frame that draws the acquired swapchain image: it waits for the acquire and signals the present.

On success the texture states the commands recorded are kept (see transitionImageLayout). On failure it returns false: call discardRecording.

void discardRecording();

Says that the commands recorded since the last successful submit will not run, a failed submit included. Every texture they moved goes back to the usage it had before them, which is still the GPU's layout. endFrame calls it for a frame it does not submit. Without it, the next barrier on such a texture would start from a layout the texture never reached.

[[nodiscard]] SwapchainStatus acquireNextImage(uint32_t& imageIndex);
[[nodiscard]] SwapchainStatus present();
[[nodiscard]] SwapchainStatus recreateSwapchain();

The swapchain steps of beginFrame, endFrame and a resize. Each returns a SwapchainStatus. recreateSwapchain sizes the swapchain from the window's pixel size; on success the swapchain image handles change. Use Engine::recreateSwapchain, which also rebuilds the depth textures.

std::vector<TextureHandle> getSwapchainImages();
Format                     getSwapchainImageFormat();
glm::uvec2                 getSwapchainExtent();

The swapchain's image handles (they change when it is re-created), its color format (RASM asks for B8G8R8A8_SRGB), and its size in pixels. Use the format for render targets and pipelines that should match the swapchain.

9GPU timestamps and memory

For timing inside a frame, beginGpuTimer is simpler: it uses the engine's own query pools and shows up in the frame stats.

QueryPoolHandle createTimestampQueryPool(const std::string& name,
                                         uint32_t count);

Creates count timestamp queries, already reset. Returns an invalid handle, with a warning, when the GPU's queue has no timestamps.

void writeTimestamp(const CommandBufferHandle& commandBuffer,
                    const QueryPoolHandle& pool, uint32_t index);

Records the GPU time into query index when the GPU reaches this point. index must be below the pool's count.

void resetQueries(const QueryPoolHandle& pool);

Resets all queries of the pool, from the CPU, at once. The GPU must be done with the pool.

bool getTimestamps(const QueryPoolHandle& pool, uint32_t count,
                   uint64_t* nanoseconds);

Reads the first count queries into nanoseconds, as nanoseconds after the earliest of them. It does not wait: it returns false if any of them has not been written since the last reset.

VRAMStats queryVRAMStats();

The memory budget and usage of the GPU heaps, from the driver, right now. See VRAMStats. Engine::queryMemoryStats returns the same.

10Lifetime

     RenderContext(Engine* owner);
     ~RenderContext();
bool initialize(Backend backend);
void cleanup();

The Engine owns its RenderContext, initializes it in its constructor and cleans it up in its destructor. Do not create another one or call these. initialize creates the device for the backend (only VULKAN exists), the swapchain and the six samplers. cleanup waits until the GPU is idle and destroys every object it still holds.

Known limits
  • Only buffers and textures can be destroyed, and only by hand; nothing waits for the GPU for you (D4).
  • Each call looks its handles up in a hash map (P4).
  • There is one queue: no async compute or transfer queue (D13).
