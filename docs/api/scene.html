API reference

Scenes, entities, meshes and lights

A scene is a list of entities, cameras and lights. An entity puts a mesh into the world with a material and a Transform. You create each object with an Engine function, then add it to one or more scenes. The engine sends the changes to the GPU at the start of the next frame.

In short

  • createScene, createEntity, createLight, then addEntityToScene and addLightToScene.
  • Meshes come from files (loadMesh, background) or from your own vertices (createMesh, at once).
  • An entity is drawn only when its mesh and all its textures are loaded. Until then it is silently skipped.
  • Move entities with updateTransform. Only the changed rows are uploaded.
  • Everything can be destroyed, and entities and lights can leave a scene; rows, ranges and indices are reused (deferred destruction).

1Scenes

CPU record GPU buffer 
SceneHandle createScene();

Creates an empty scene. Returns an invalid handle and logs a warning when MAX_SCENES is reached (15 scenes can exist, because handle indices start at 1).

void addEntityToScene(SceneHandle scene, EntityHandle entity);

Adds the entity to the scene. If the entity is ready, the scene's draw list is rebuilt at the next beginFrame and the entity is drawn in that frame. If its mesh or textures still load, it joins when they finish.

scene
Invalid: logs an error, nothing changes.
entity
Invalid or destroyed: logs an error. An entity already in the scene is not added again (a warning).

A scene holds at most MAX_ENTITIES_PER_SCENE entities (a warning is logged after that). removeEntityFromScene takes it out again.

void removeEntityFromScene(SceneHandle scene, EntityHandle entity);

The scene stops drawing the entity from the next frame on; the entity lives on, and can be added again or be in other scenes. The scene's draw list is rebuilt once, which also drops the entity from Scene::entities. An entity that is not in the scene logs a warning.

void removeLightFromScene(SceneHandle scene, LightHandle light);

The light stops lighting the scene from the next frame on, and a shadow made for it in that scene casts nothing. The light lives on. The scene's light list is rebuilt once.

void destroyScene(SceneHandle scene);

Destroys the scene: its entities and lights live on, in no scene, and its draw list and light list buffers are freed once the GPU is done with them. Its index goes to the next createScene.

errors Refused while a render graph draws a view of the scene, with an error that names the view and its camera: destroy that graph first, or let it go out of scope. The graph of render lets go by itself.

void addCameraToScene(SceneHandle scene, CameraHandle camera);

Records the camera in the scene's camera list (at most MAX_CAMERAS_PER_SCENE, 32; past it an error is logged). Drawing does not read this list today: render, its Views and addScenePasses take the camera as an argument, and any camera can draw any scene. Cameras are on camera.html.

void addLightToScene(SceneHandle scene, LightHandle light);

Adds the light to the scene. It shines from the next frame on. A scene can hold any number of lights; a light already in the scene is not added again (a warning). Adding a light rebuilds the scene's list of lights once, on the CPU; nothing walks the lights after that while they do not change.

struct ShadowDesc
{
    LightHandle light;
    uint32_t    cascadeCount = 4;
    uint32_t    size         = 2048;
    float       distance     = 50.0f;
    float       splitLambda  = 0.7f;
};

What addShadowPasses makes: a light's shadow. A directional light gets cascaded shadow maps, a spot light one perspective map along its cone, a point light a cube map (Spot and point light shadows).

light
The light to shadow, of any LightType. It must be in the scene's lights to be shadowed: one taken out of the scene casts no shadow.
cascadeCount
Directional lights only: maps, 1 to MAX_SHADOW_CASCADES (4). Each is one slice of the camera's view and one scene view. More cascades: sharper far shadows, more passes. A spot light has one map, a point light one cube of 6 faces (6 scene views).
size
Width and height of each map (each cube face) in texels. A 2048 map of 32-bit depth is 16 MiB; a 1024 cube is 24 MiB.
distance
How far the shadow reaches, in world units. Directional light: from the camera, beyond its near plane; farther points are lit, faded in over the last tenth. Spot and point light: from the light, finite and above 0; it is the map's far plane, and its near plane is distance / 200.
splitLambda
Directional lights only. Where the slices end: 0 splits the distance evenly, 1 logarithmically (each slice the same factor longer than the one before), in between a mix. Higher values give the near cascades more detail.
struct SceneShadow
{
    LightHandle        light;
    RenderTargetHandle maps[MAX_SHADOW_CASCADES] = {};
    uint32_t           mapCount                  = 0;
    float              distance                  = 0.0f;
    float              splitLambda               = 0.0f;

    bool operator==(const SceneShadow&) const = default;
};

A light's shadow, as addShadowPasses returns it, for addScenePasses. Do not build one yourself: addScenePasses takes only a shadow that addShadowPasses made for the same scene and camera in the same graph. A view reads up to MAX_VIEW_SHADOWS (4), of different lights. See Shadow mapping.

light
The light it darkens, from ShadowDesc::light.
maps
The depth-only targets (D32_SFLOAT, no color) of the first mapCount maps: a directional light's cascades, nearest first; a spot light's one map; a point light's one cube (RenderTargetDesc::cube). A pass of yours can read one with readDepth, as the inset of examples/06_shadows does with the cascades.
mapCount
0 when addShadowPasses failed.
distance, splitLambda
From the ShadowDesc; every view of the shadow builds the maps' matrices with them each frame.

EntityHandle createEntity(const std::string& name, MeshHandle mesh = MeshHandle{}, MaterialHandle material = MaterialHandle{}, Transform transform = Transform{});

Creates an entity. It appears once it is in a scene and its mesh and textures are loaded (diagram above). You can pass a mesh that is still loading.

name
A label for you; the engine only stores it.
mesh
What to draw. Without a mesh the entity is never drawn, and the mesh cannot be set later.
material
Used by every sub-mesh that has no material of its own (OBJ files, createMesh, glTF primitives without one). Invalid: the default material (white, metallic 1, roughness 1). A glTF sub-mesh's own material always wins.
transform
Position, rotation and scale in the world. Default: the origin, no rotation, scale 1. A negative scale (a mirror) works: the engine culls the other face.

Returns an invalid handle and logs a warning after 262,143 entities (MAX_ENTITIES). Each entity needs one row in the instance table per sub-mesh; when EngineConfig::maxInstances rows are used, new entities log an error and are not drawn.

// examples/03_instances: 10,000 cubes share one mesh and two materials.
for (int z = 0; z < GRID_SIZE; ++z)
{
    for (int x = 0; x < GRID_SIZE; ++x)
    {
        const auto material = (x + z) % 2 == 0 ? warm : cool;
        const auto transform = cubeTransform(gridPosition(x, z), 1.0f);
        engine.addEntityToScene(scene, engine.createEntity("grid", cube, material, transform));
    }
}
void updateTransform(EntityHandle entity, Transform transform);

Moves the entity. Its instance rows (one per sub-mesh) are marked changed and uploaded at the next beginFrame, so the next frame shows the new place. Only these rows are uploaded, so moving a few entities in a big scene is cheap. If the sign of the scale changes (mirroring on or off), the entity's scenes rebuild their draw lists.

entity
Invalid: logs "Invalid entity handle for updating transform." and does nothing.
transform
Replaces the whole transform.
rasm::Transform transform = engine.getTransform(bunny);
transform.rotate(glm::vec3(0.0f, 1.0f, 0.0f), glm::radians(0.01f));
engine.updateTransform(bunny, transform);
void destroyEntity(EntityHandle entity);

Destroys the entity. It leaves every scene from the next frame on, and its instance rows (one per sub-mesh) and, for an animated entity, its row and ranges of the animation buffers go to the next entity at once: each frame slot has its own copy of those tables. Its mesh and material stay. A destroyed handle logs an error. See Deferred destruction.

engine.destroyEntity(tile.groundEntity);
engine.destroyMesh(tile.ground);
engine.destroyMaterial(tile.material);
engine.destroyTexture(tile.texture);

From examples/17_streaming/main.cpp: a tile that leaves the view goes, entities first.

struct Transform
{
    glm::dvec3  position = glm::dvec3(0.0);
    glm::quat   rotation = glm::identity<glm::quat>();
    glm::vec3   scale    = glm::vec3(1.0f);
};

Used for entities and cameras. It is an aggregate, so designated initializers work and you can skip fields: Transform{.position = p, .scale = s}. A glm::vec3 converts to the glm::dvec3 position by itself; arithmetic that mixes the two needs a cast, for example glm::vec3(transform.position) - center. Each view draws in its camera's render space, so a scene far from the origin renders like one near it.

Transform rotate(const glm::vec3& axis, float radians);

Turns the transform by radians around axis, an axis in world space (the new turn is applied after the old rotation). It changes the transform itself and also returns the result, so it can be passed on directly. A zero axis changes nothing. The axis does not need to be normalized.

glm::dmat4 toMatrix() const;

The model matrix in doubles: scale first, then rotate, then translate (T * R * S). For a glTF sub-mesh the engine multiplies it with the sub-mesh's node matrix, in doubles: entity.toMatrix() * glm::dmat4(subMesh.transform). It converts to a glm::mat4 by itself, which keeps only float precision.

4Meshes

OBJ (loadMesh)

One sub-mesh: every shape of the file is merged. No material: the entity's material is used. Positions, normals and the first UV set are read; the UV v is flipped so textures are not upside down. The .mtl file is ignored.

glTF / GLB (loadMesh, loadGLTF)

One sub-mesh per triangle primitive of each mesh node of the default scene, with the node's world matrix. Up to 3 UV sets and tangents are read; missing normals are computed. Each glTF material becomes a Material with its textures (see materials.html).

MeshHandle loadMesh(const std::string& path);

Starts loading a .obj, .gltf or .glb file and returns its handle at once. An AssetLoader call; an Engine has it too, for its own loader. The loader's workers read and decode the file, each of its images on a worker of its own, and build its LODs when EngineConfig::meshLods is on (job systems). A later beginFrame uploads it to the geometry pool, then isLoaded becomes true and the entities that use it are drawn.

path
Relative to EngineConfig::assetRoot (see resolveAssetPath), or absolute. UTF-8. The extension is checked in lower case only.

loads in the background Loading the same path again returns the same handle; the file is read once.

MeshHandle loadGLTF(const std::string& path);

The same as loadMesh; the file extension picks the importer. It reads POSITION, NORMAL, TANGENT, TEXCOORD_0 to _2 and COLOR_0, in floats or in the integer types of KHR_mesh_quantization, skins (JOINTS_n / WEIGHTS_n, Animation), morph targets (POSITION, NORMAL and TANGENT deltas, sparse accessors too, Morph targets), and the material extensions on the materials page. A file may require KHR_materials_unlit, KHR_materials_emissive_strength, KHR_texture_transform, KHR_mesh_quantization and KHR_texture_basisu; one that requires any other extension fails to load. Other extensions it only uses are ignored.

rasm::MeshHandle room = engine.loadGLTF("models/gltf/coffee-room/scene.gltf");
if (!room.isValid())
    return 1;
rasm::Transform transform{.scale = glm::vec3(2.0f)};
rasm::EntityHandle entity = engine.createEntity("room", room, {}, transform); // {}: use the glTF materials
bool isLoaded(MeshHandle mesh) const;

True when the mesh is uploaded and ready to draw, with every texture its glTF import made filled. Those textures are filled a few per frame after the mesh is ready, so a big model is loaded a few frames after its geometry. False while it loads, after it failed, and for an invalid handle. A mesh from createMesh is loaded at once. You do not need to wait for it before creating entities.

void destroyMesh(MeshHandle mesh);

Destroys the mesh. Its ranges of the geometry pool, its rows of the geometry table and its range of the animation pool are freed once the GPU has finished the frames that may draw it, and then taken by later meshes, so map tiles or levels can stream in and out for ever.

  • What its glTF import made goes with it: the materials and textures loadMesh created for this file belong to the mesh. An entity that uses one of those materials as its own falls back as after destroyMaterial, and a material that uses one of those textures as after destroyTexture.
  • Entities that still use the mesh live on and draw nothing; their rows are freed. Destroy them first, and nothing has to be searched.
  • A load that has not finished is dropped at once: a load still in the queue never runs, and a running one gives its result up. loadMesh of the same path then loads it again, as a new mesh. A mesh whose load failed can be destroyed too, which frees its index.
MeshHandle createMesh(std::vector<Vertex> vertices, std::vector<uint32_t> indices, std::vector<uint32_t> colors = {});

Makes a mesh from your data, builds its LODs when EngineConfig::meshLods is on, and uploads it now (the copy reaches the GPU with the next frame). The mesh has one sub-mesh with no material, so its entities use their own material.

vertices
See Vertex. Set tangent to zero when you have none.
indices
A triangle list, 3 per triangle, counting from 0 in vertices. Front faces are counter-clockwise seen from outside.
colors
Optional vertex colors: empty, or one per vertex, each made with packVertexColor. They multiply the material's base color. A mesh without them uses no color memory.

Returns an invalid handle when colors is neither empty nor one per vertex, the index count is not a multiple of 3, an index is not below vertices.size(), or the geometry pool is full (all logged). A mesh that does not fit takes no handle index. A mesh with no vertices or no indices is accepted but its entities skip it with a warning.

// examples/03_instances: one quad per cube face, so each face has its own normal.
std::vector<rasm::Vertex> vertices;
std::vector<uint32_t> indices;
// ... per face: 4 vertices like this, 6 indices
vertices.push_back({.pos = corners[i] * 0.5f,
                    .normal = n,
                    .uv = {uvs[i], uvs[i], uvs[i]},
                    .tangent = glm::vec4(0.0f)});
// ...
rasm::MeshHandle cube = engine.createMesh(std::move(vertices), std::move(indices));
// examples/09_gltf_materials: the same cube with a color per vertex, dark at the bottom and light at the top.
colors.push_back(rasm::packVertexColor(glm::vec4(glm::mix(glm::vec3(0.25f), glm::vec3(1.0f), height), 1.0f)));
// ...
return engine.createMesh(std::move(vertices), std::move(indices), std::move(colors));
MeshBuild buildMesh(std::vector<Vertex> vertices, std::vector<uint32_t> indices, std::vector<uint32_t> colors = {}, const MeshBuildOptions& options = {});
MeshHandle createMesh(MeshBuild&& build);

The two halves of createMesh. buildMesh is a free function that touches no renderer, so any thread may call it: it checks the data as createMesh does (colors empty or one per vertex, whole triangles, indices in range; an error and an invalid build otherwise) and builds the LODs and meshlets the options ask for, the slow part of a big mesh. Renderer::createMesh(MeshBuild&&) then only uploads it, on the renderer's thread, and takes the build (invalid afterwards). An application that makes its tiles' meshes builds them on its own threads, and its frames only upload.

// On a worker thread:
rasm::MeshBuild build = rasm::buildMesh(std::move(vertices), std::move(indices));
// Later, on the renderer's thread:
const rasm::MeshHandle mesh = renderer.createMesh(std::move(build));
struct MeshBuildOptions
{
    bool                        lods        = true;
    bool                        meshlets    = true;
};

lods: simplified LODs. meshlets: meshlets for a sub-mesh of 1024 triangles or more. Leave both off for geometry the shader moves (vector features, which buildVectorMesh does).

A mesh's CPU data, ready to upload. Move-only. isValid is false when buildMesh refused the data, and after a createMesh took it.

struct SkinVertex
{
    uint16_t    joints[4];
    uint16_t    weights[4];
};

A skinned vertex's 4 largest influences: joints of its skin, and weights as UNORM16 that add up to 65535 exactly (the rounding's rest goes to the largest). 16 bytes, in the geometry pool's skin stream, so a vertex stays 64 bytes. The import keeps the 4 largest of JOINTS_n / WEIGHTS_n (one warning per primitive that has more), scales them to add up to 1, and drops a weight whose joint is past the skin's.

struct MorphDelta
{
    glm::vec3   position;
    uint32_t    normalTangent[3];
};

constexpr uint32_t MAX_MORPH_TARGETS = 256;

A morph target's change to one vertex: 24 bytes, in the geometry pool's morph stream. The position is 3 floats; the normal and the tangent's xyz are 6 half floats, two per uint, the first in the low half (normal x y, normal z tangent x, tangent y z). A glTF primitive keeps at most MAX_MORPH_TARGETS targets (a warning says how many it drops), because the Skin pass keeps a group's weights in shared memory. See Morph targets.

uint32_t    packVertexColor(const glm::vec4& linearColor);

Packs a linear RGBA color (each 0 to 1; values outside are clamped) into the 4 bytes of a vertex color: R in the lowest byte. RGB is stored sRGB-encoded, like a color texture, so 8 bits keep the dark shades; alpha stays linear. The shader decodes it back to linear. packVertexColor(glm::vec4(1.0f)) is white, 0xFFFFFFFF.

MeshSize getMeshByteSize(const MeshHandle& handle) const;

The bytes the mesh uses in the geometry pool: vertices × 64, plus 4 per vertex color, and indices × 4, LOD indices included, over all sub-meshes. While the mesh loads it returns zeros. Invalid handle: logs an error and returns zeros.

struct MeshSize
{
    uint64_t verticesByteSize;
    uint64_t indicesByteSize;
};

The result of getMeshByteSize, in bytes.

5Terrain

A terrain tile is an entity on a grid every tile of its size shares, lifted on the GPU by the tile's heights (Terrain from height maps). The tile carries only two textures: its heights and its image. It goes through culling, shadows, TAA and MSAA like any mesh, and is a TileStreamer tile's content like any other.

TerrainTile createTerrainTile(const TerrainTileDesc& desc);

Makes a TERRAIN material from the desc (its terrain, the imagery as base color with imageryRect as its texture transform, metallic 0, the roughness) and an entity on getTerrainMesh with getTerrainTransform. The heights' width decides the cells: width − 3. The entity is in no scene yet. Both handles are invalid, with an error, when the heights are not a live R16_UNORM or R32_SFLOAT square texture of 4 to MAX_TERRAIN_CELLS + 3 samples a side, the size is not above 0, maxHeight is below minHeight, or a pool is full. An imagery texture without a bindless slot gets one that clamps. A texture keeps the sampler of its first slot, so an image another material used first (with repeat) bleeds its opposite edge into the tile's border: give tiles images of their own.

The entity draws once its textures are loaded. List the entity, the material and both textures in a tile's content, never the grid. To change the heights' range later, update the material's terrain (updateMaterial) and the entity's transform together.

// examples/24_map_tiles: a tile's heights (35 x 35 steps of 1/16 m) and image came from the server.

                                                            .size = size,

The most cells per side of a terrain grid; a tile's heights have cells + 3 samples a side.

struct VectorPlacement

7Point clouds

A point cloud is drawn in chunks of up to 65 536 points near each other: each chunk is a mesh made by buildPointCloudChunk, drawn by an entity with a POINTS material, and placed by the entity's transform in doubles. Each point is a splat a few pixels or centimetres wide; a chunk small on screen draws only the first points of its order (Point clouds).

constexpr uint32_t MAX_POINT_CHUNK_POINTS = 1u << 16;

struct PointCloudChunkDesc
{
    const glm::vec3*    positions   = nullptr;
    const uint32_t*     colors      = nullptr;
    const float*        scalars     = nullptr;
    uint32_t            count       = 0;
    float               spacing     = 0.0f;
};
positions
Offsets from the entity's origin, in metres. Keep a chunk small (tens of metres): its points are 16-bit steps of its box, and it is culled and given a level of detail as a whole.
colors
RGBA8 with RGB sRGB-encoded (packVertexColor), one per point, for PointColorMode::COLOR; the alpha is not read (points are opaque); null: none.
scalars
A value per point (height, intensity, ...), for a colormap (PointColorMode::SCALAR); null: none. Stored as 16-bit steps of the chunk's range.
count
1 to MAX_POINT_CHUNK_POINTS.
spacing
The distance between neighbouring points, in the chunk's units, which an ADAPTIVE size grows to. 0: measured from the points, as the cell size at which they take half as many cells as there are points (1.2 times the mean spacing of a random sample, 1.4 times a grid's step).

Checks the points (a count in range, positions and scalars finite; an error and an invalid build otherwise) and builds the chunk, on any thread: the points in an order whose every prefix is an even sample (a Morton order read in bit-reversed steps), 8 B a point with no colors, 12 B with them. createMesh uploads it into the point pool (RendererConfig::geometryPoolPoints, made with the first chunk). A pick's PickHit::feature is the point's index in desc's arrays (PICK_HIT_POINT), mapped through the mesh the entity drew; a mesh destroyed before the pick's answer leaves no feature (PICK_HIT_FEATURE cleared). An entity that draws a chunk without a POINTS material draws nothing, with a warning.

rasm::MeshBuild build = rasm::buildPointCloudChunk({.positions = points.data(), .scalars = heights.data(), .count = count});
// Later, on the renderer's thread:

{

};
drawn
The share of the points its level of detail keeps that the chunk draws, 0 to 1: a prefix of a prefix, so a chunk fades in and out as an even sample. 0 draws nothing.
finer
Per octant of the entity's space (x ≥ 0 adds 1, y ≥ 0 adds 2, z ≥ 0 adds 4), the drawn share of a finer chunk over that octant, 0 to 1. An ADAPTIVE point there shrinks back toward the material's size by it, as the finer chunk fills the gaps it closed.

10Animation

A glTF model's clips move its nodes, and the GPU poses them (Keyframe animation). A skinned model's clips move its joints, and the GPU skins its vertices once per frame for every view (Skinning); it plays the same way. A morphed model's clips move its weights too (Morph targets). The application owns the clock: it calls setAnimationTime once per frame, and starts a clip on an entity with playAnimation. Nothing else runs per frame on the CPU, however many entities play.

const rasm::MeshHandle box = engine.loadGLTF("models/gltf/BoxAnimated/BoxAnimated.glb");
const rasm::EntityHandle entity = engine.createEntity("box", box);
engine.addEntityToScene(scene, entity);
engine.playAnimation(entity, rasm::AnimationPlay{.clip = 0});

double seconds = 0.0;
while (engine.running())
{
    seconds += 1.0 / 60.0;
    engine.setAnimationTime(seconds);
    engine.render(scene, camera);
}

11Morph targets

A glTF mesh with morph targets has a list of weights per entity. The GPU adds each target's deltas, times its weight, to the vertices once per frame, before the skin, for every view (Morph targets). A weight comes from the application when it set one, else from the playing clip's weights channel, else from the mesh's rest weights.

12Lights

LightType::DIRECTIONAL

Like the sun: same strength everywhere. Uses direction (the way the light travels, from the light to the surface), color and intensity. position and range are ignored.

LightType::POINT

Like a bulb: light / distance². Uses position, color, intensity and range. With range > 0 the light fades smoothly to zero at range; 0 means no limit. direction is ignored.

LightType::SPOT

Like a flashlight: a point light that shines only in a cone around direction. Full light inside innerConeAngle, a smooth fade to zero at outerConeAngle (the glTF rule).

Lights shade PBR materials. UNLIT materials ignore them. A scene without an environment also gets a small fixed ambient term, so unlit sides are not fully black; with one, the environment's light replaces it.

Local: point or spot light with a range

Sorted into clusters: only the pixels near it pay for it. Thousands are fine.

Global: directional, or range 0

Reaches every point, so every pixel shades it. Hundreds of them cost like hundreds of lights without clusters.

Shadowed

Up to MAX_VIEW_SHADOWS per view (addShadowPasses). Every other light has no shadow.

A point or spot light needs a range to be clustered; with range 0 it is global. Each cluster holds at most MAX_CLUSTER_LIGHTS lights. The guide Many lights: clustered lighting explains how it works.

Linear RGB, multiplied by intensity.

World position (point and spot lights), in doubles, like an entity's.

Direction the light travels (directional lights), or the cone's axis (spot lights). Pass a unit vector.

Strength. Point and spot lights fall off with distance², so they need larger values (the examples use 25 to 900).

13Environments

An environment is an HDR photo of the light all around a scene. It lights every PBR material from all directions (soft light from the sky, reflections on shiny surfaces) and shows behind the scene as the sky. The guide Image-based lighting explains how.

const rasm::EnvironmentHandle sunset = engine.loadEnvironment("environments/venice_sunset_2k.hdr");
engine.setSceneEnvironment(scene, rasm::SceneEnvironment{.environment = sunset, .intensity = 1.0f, .rotation = 1.15f});

// Later: back to no environment.
engine.setSceneEnvironment(scene, {});
EnvironmentHandle loadEnvironment(const std::string& path);

Loads an equirectangular (2:1 panorama) Radiance .hdr image, in the background like loadMesh. An AssetLoader call; an Engine has it too, for its own loader. A relative path starts from AssetLoaderConfig::assetRoot. The header is read at once; a missing file, another extension or an image that is not HDR logs an error and returns an invalid handle. A worker decodes the pixels. The next beginFrame after that creates the textures, and the frame after (or the same one) prepares the light on the GPU, before any pass: about 1 ms for a 2048 × 1024 image. Until then a scene that uses it looks as if it had none.

Each call loads the file again (no cache). destroyEnvironment frees one you no longer need, for example to change the sky with the time of day.

void destroyEnvironment(EnvironmentHandle environment);

Destroys the environment. Scenes that use it have none from the next frame on (a small constant ambient). Its image, its three cubes (about 17 MiB for a 2k image) and their four bindless slots are freed once the GPU is done with them. A load or a bake that has not finished is dropped.

bool isLoaded(EnvironmentHandle environment) const;

True once the environment's light is prepared, so scenes use it from this frame on. False while it loads, if it failed, and for an invalid handle.

void setSceneEnvironment(SceneHandle scene, const SceneEnvironment& environment);

Gives the scene an environment, or takes it away with an invalid handle (SceneEnvironment{}). The scene's views read it every frame, so a change shows in the next frame and needs no new render graph. An invalid scene, a handle loadEnvironment did not return, a negative or non-finite intensity, a non-finite rotation, or an orientation that is not finite logs an error and changes nothing; a zero orientation is the identity. Several scenes can share one environment.
