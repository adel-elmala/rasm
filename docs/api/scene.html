API reference

Scenes, entities, meshes and lights

A scene is a list of entities, cameras and lights. An entity puts a mesh into the world with a material and a Transform. You create each object with an Engine function, then add it to one or more scenes. The engine sends the changes to the GPU at the start of the next frame.

In short

  • createScene, createEntity, createLight, then addEntityToScene and addLightToScene.
  • Meshes come from files (loadMesh, background) or from your own vertices (createMesh, at once).
  • An entity is drawn only when its mesh and all its textures are loaded. Until then it is silently skipped.
  • Move entities with updateTransform. Only the changed rows are uploaded.
  • Nothing can be destroyed or removed from a scene yet (D4).

1Scenes

CPU record GPU buffer 
SceneHandle createScene();

Creates an empty scene. Returns an invalid handle and logs a warning when MAX_SCENES is reached (15 scenes can exist, because handle indices start at 1).

void addEntityToScene(SceneHandle scene, EntityHandle entity);

Adds the entity to the scene. If the entity is ready, the scene's draw list is rebuilt at the next beginFrame and the entity is drawn in that frame. If its mesh or textures still load, it joins when they finish.

scene
Invalid: logs an error, nothing changes.
entity
Invalid: logs an error. The same entity added twice is drawn twice.

A scene holds at most MAX_ENTITIES_PER_SCENE entities (a warning is logged after that). There is no function to remove an entity (D4).

void addCameraToScene(SceneHandle scene, CameraHandle camera);

Records the camera in the scene's camera list (at most MAX_CAMERAS_PER_SCENE, 8). Drawing does not read this list today: render and drawScene take the camera as an argument, and any camera can draw any scene. Cameras are on camera.html.

void addLightToScene(SceneHandle scene, LightHandle light);

Adds the light to the scene. Every drawScene of this scene reads the scene's lights, so the light shines from the next draw on. At most MAX_LIGHTS_PER_SCENE (8) entries; a warning is logged after that.

struct Scene
{
    SceneHandle               handle;
    std::vector<EntityHandle> entities;
    std::vector<CameraHandle> cameras;
    std::vector<LightHandle>  lights;
};

The record the engine keeps for each scene. There is no getter for it; it is in the public header because Engine stores it.

2Entities

An entity is not drawn the moment you create it. It moves through these states. Each arrow happens inside beginFrame.

your call GPU rows written drawn by the GPU 
EntityHandle createEntity(const std::string& name, MeshHandle mesh = MeshHandle{}, MaterialHandle material = MaterialHandle{}, Transform transform = Transform{});

Creates an entity. It appears once it is in a scene and its mesh and textures are loaded (diagram above). You can pass a mesh that is still loading.

name
A label for you; the engine only stores it.
mesh
What to draw. Without a mesh the entity is never drawn, and the mesh cannot be set later.
material
Used by every sub-mesh that has no material of its own (OBJ files, createMesh, glTF primitives without one). Invalid: the default material (white, metallic 1, roughness 1). A glTF sub-mesh's own material always wins.
transform
Position, rotation and scale in the world. Default: the origin, no rotation, scale 1. A negative scale (a mirror) works: the engine culls the other face.

Returns an invalid handle and logs a warning after 65,535 entities (MAX_ENTITIES). Each entity needs one row in the instance table per sub-mesh; when EngineConfig::maxInstances rows are used, new entities log an error and are not drawn.

// examples/03_instances: 10,000 cubes share one mesh and two materials.
for (int z = 0; z < GRID_SIZE; ++z)
{
    for (int x = 0; x < GRID_SIZE; ++x)
    {
        const auto material = (x + z) % 2 == 0 ? warm : cool;
        const auto transform = cubeTransform(gridPosition(x, z), 1.0f);
        engine.addEntityToScene(scene, engine.createEntity("grid", cube, material, transform));
    }
}
void updateTransform(EntityHandle entity, Transform transform);

Moves the entity. Its instance rows (one per sub-mesh) are marked changed and uploaded at the next beginFrame, so the next frame shows the new place. Only these rows are uploaded, so moving a few entities in a big scene is cheap. If the sign of the scale changes (mirroring on or off), the entity's scenes rebuild their draw lists.

entity
Invalid: logs "Invalid entity handle for updating transform." and does nothing.
transform
Replaces the whole transform.
rasm::Transform transform = engine.getTransform(bunny);
transform.rotate(glm::vec3(0.0f, 1.0f, 0.0f), glm::radians(0.01f));
engine.updateTransform(bunny, transform);
Transform getTransform(EntityHandle entity);

A copy of the entity's transform. Invalid handle: logs an error and returns a default Transform.

struct Entity
{
    EntityHandle   handle{};
    std::string    name;
    MeshHandle     mesh{};
    MaterialHandle material{};
    Transform      transform{};
};

The record the engine keeps for each entity. Read the transform with getTransform; the other fields have no getter.

3Transform

FieldDefaultMeaning
position(0, 0, 0)World position. The world is right-handed, +Y is up, and a camera looks along −Z.
rotationidentityA glm::quat. Note the constructor order glm::quat(w, x, y, z).
scale(1, 1, 1)Per axis. Negative values mirror the object.
struct Transform
{
    glm::vec3 position = glm::vec3(0.0f);
    glm::quat rotation = glm::identity<glm::quat>();
    glm::vec3 scale    = glm::vec3(1.0f);
};

Used for entities and cameras. It is an aggregate, so designated initializers work and you can skip fields: Transform{.position = p, .scale = s}.

Transform rotate(const glm::vec3& axis, float radians);

Turns the transform by radians around axis, an axis in world space (the new turn is applied after the old rotation). It changes the transform itself and also returns the result, so it can be passed on directly. A zero axis changes nothing. The axis does not need to be normalized.

glm::mat4 toMatrix() const;

The model matrix: scale first, then rotate, then translate (T * R * S). For a glTF sub-mesh the engine multiplies it with the sub-mesh's node matrix: entity.toMatrix() * subMesh.transform.

4Meshes

OBJ (loadMesh)

One sub-mesh: every shape of the file is merged. No material: the entity's material is used. Positions, normals and the first UV set are read; the UV v is flipped so textures are not upside down. The .mtl file is ignored.

glTF / GLB (loadMesh, loadGLTF)

One sub-mesh per triangle primitive of each mesh node of the default scene, with the node's world matrix. Up to 3 UV sets and tangents are read; missing normals are computed. Each glTF material becomes a Material with its textures (see materials.html).

MeshHandle loadMesh(const std::string& path);

Starts loading a .obj, .gltf or .glb file and returns its handle at once. A worker thread reads and decodes the file, and builds its LODs when EngineConfig::meshLods is on. A later beginFrame uploads it to the geometry pool, then isLoaded becomes true and the entities that use it are drawn.

path
Relative to EngineConfig::assetRoot (see resolveAssetPath), or absolute. UTF-8. The extension is checked in lower case only.

loads in the background Loading the same path again returns the same handle; the file is read once.

After a parse failure, calling loadMesh with the same path tries again on the same handle.

MeshHandle loadGLTF(const std::string& path);

The same as loadMesh; the file extension picks the importer.

rasm::MeshHandle room = engine.loadGLTF("models/gltf/coffee-room/scene.gltf");
if (!room.isValid())
    return 1;
rasm::Transform transform{.scale = glm::vec3(2.0f)};
rasm::EntityHandle entity = engine.createEntity("room", room, {}, transform); // {}: use the glTF materials
bool isLoaded(MeshHandle mesh) const;

True when the mesh is uploaded and ready to draw. False while it loads, after it failed, and for an invalid handle. A mesh from createMesh is loaded at once. You do not need to wait for it before creating entities.

MeshHandle createMesh(std::vector<Vertex> vertices, std::vector<uint32_t> indices);

Makes a mesh from your data, builds its LODs when EngineConfig::meshLods is on, and uploads it now (the copy reaches the GPU with the next frame). The mesh has one sub-mesh with no material, so its entities use their own material.

vertices
See Vertex. Set tangent to zero when you have none.
indices
A triangle list, 3 per triangle, counting from 0 in vertices. Front faces are counter-clockwise seen from outside.

Returns an invalid handle when the index count is not a multiple of 3, an index is not below vertices.size(), MAX_MESHES is reached or the geometry pool is full (all logged). A mesh with no vertices or no indices is accepted but its entities skip it with a warning.

// examples/03_instances: one quad per cube face, so each face has its own normal.
std::vector<rasm::Vertex> vertices;
std::vector<uint32_t> indices;
// ... per face: 4 vertices like this, 6 indices
vertices.push_back({.pos = corners[i] * 0.5f,
                    .normal = n,
                    .uv = {uvs[i], uvs[i], uvs[i]},
                    .tangent = glm::vec4(0.0f)});
// ...
rasm::MeshHandle cube = engine.createMesh(std::move(vertices), std::move(indices));
MeshSize getMeshByteSize(const MeshHandle& handle) const;

The bytes the mesh uses in the geometry pool: vertices × 64 and indices × 4, LOD indices included, over all sub-meshes. While the mesh loads it returns zeros. Invalid handle: logs an error and returns zeros.

struct MeshSize
{
    uint64_t verticesByteSize;
    uint64_t indicesByteSize;
};

The result of getMeshByteSize, in bytes.

The vertex

struct Vertex
{
    glm::vec3 pos;
    glm::vec3 normal;
    glm::vec2 uv[MAX_VERTEX_UV_SETS];
    glm::vec4 tangent;
};
pos
Position in mesh space.
normal
Unit normal, used for lighting.
uv
Up to MAX_VERTEX_UV_SETS (3) texture coordinate sets. A material picks a set per texture. (0, 0) when unused.
tangent
glTF tangent: xyz is the tangent, w is the bitangent sign (±1). w = 0 means "no tangent": the shader builds one from the UVs for normal mapping.

Mesh records in the public header

These types are in rasm/mesh.h because Engine stores them. No public function returns them; they are listed so you know what they are.

struct SubMesh
{
    MeshGeometry   geometry;
    glm::mat4      transform;
    MaterialHandle material;
};

One drawable part of a mesh: its place in the geometry pool, its node matrix (identity for OBJ and createMesh), and its glTF material (invalid when it has none). Each sub-mesh of an entity is one draw and one instance row.

struct Mesh
{
    MeshState            state = MeshState::LOADING;
    std::vector<SubMesh> subMeshes;
};

A mesh: its load state and its sub-meshes.

enum class MeshState { LOADING, READY, FAILED };

READY is what isLoaded checks. FAILED means the file did not parse or did not fit in the geometry pool.

struct MeshGeometry
{
    uint32_t  firstVertex   = 0;
    uint32_t  vertexCount   = 0;
    uint32_t  firstIndex    = 0;
    uint32_t  indexCount    = 0;
    uint32_t  lodIndexCount = 0;
    uint32_t  geometryIndex = 0;
    glm::vec3 boundsCenter  = glm::vec3(0.0f);
    float     boundsRadius  = 0.0f;
};

Where a sub-mesh sits in the geometry pool, its row in the geometry table (geometryIndex), and its bounding sphere in mesh space, which frustum and occlusion culling test.

firstIndex, indexCount
LOD 0, the full detail.
lodIndexCount
The indices of LOD 1 and coarser, together. They come right after LOD 0's in the pool.
struct ObjRaw
{
    std::vector<Vertex>   vertices;
    std::vector<uint32_t> indices;
    std::vector<MeshLod>  lods;
};

Decoded vertices and indices of one sub-mesh, before upload (also used for glTF).

indices
LOD 0, the full detail.
lods
LOD 1 and coarser, from fine to coarse; at most MAX_MESH_LODS − 1. Empty until the engine builds them, and for a sub-mesh under 1024 triangles.
struct MeshLod
{
    std::vector<uint32_t> indices;
    float                 error = 0.0f;
};

One coarser level of detail of a sub-mesh, with about half the triangles of the one before. The engine builds them as a mesh loads (EngineConfig::meshLods); culling picks one per draw (EngineConfig::lodErrorPixels).

indices
A triangle list into the same vertices as LOD 0. So a LOD costs only indices.
error
How far this LOD's surface may be from LOD 0, in the mesh's own units. It never gets smaller from one LOD to the next.
struct SubGLTFRaw
{
    ObjRaw    objRaw;
    glm::mat4 transform;
    int       materialIndex;
};

One decoded sub-mesh with its node matrix and its glTF material index (−1 for none).

struct GLTFRaw
{
    std::vector<SubGLTFRaw>          subGltfRaws;
    std::shared_ptr<tinygltf::Model> model;
    bool                             loaded = false;
};

What the worker thread hands back for one file: the sub-meshes, the parsed glTF model (for its materials and images; empty for OBJ) and whether the file loaded. It is freed once the mesh is uploaded.

struct GltfImportCache
{
    std::unordered_map<int, MaterialHandle>      materials;
    std::unordered_map<uint64_t, TextureHandle> imageTextures;
};

Used while one glTF file is imported, so primitives that share a material, and materials that share an image, create it only once.

5Lights

LightType::DIRECTIONAL

Like the sun: same strength everywhere. Uses direction (the way the light travels, from the light to the surface), color and intensity. position and range are ignored.

LightType::POINT

Like a bulb: light / distance². Uses position, color, intensity and range. With range > 0 the light fades smoothly to zero at range; 0 means no limit. direction is ignored.

Lights shade PBR materials. UNLIT materials ignore them. There is also a small fixed ambient term, so unlit sides are not fully black.

LightHandle createLight(LightType type, glm::vec3 color = glm::vec3(1.0f), glm::vec3 position = glm::vec3(1.0f), glm::vec3 direction = glm::vec3(0.0f, -1.0f, 0.0f), float intensity = 1.0f, float range = 10.0f);

Creates a light. Add it to a scene with addLightToScene. A light cannot be changed after creation: there is no function to update or move it.

type
DIRECTIONAL or POINT.
color
Linear RGB, multiplied by intensity.
position
World position (point lights).
direction
Direction the light travels (directional lights). Pass a unit vector.
intensity
Strength. Point lights fall off with distance², so they need larger values (the examples use 40).
range
Point lights: distance where the light reaches zero; 0 = no limit.

Returns an invalid handle and logs a warning when MAX_LIGHTS is reached: 7 lights can exist in total, because handle indices start at 1.

rasm::LightHandle lamp = engine.createLight(rasm::LightType::POINT,
                                            glm::vec3(1.0f, 0.85f, 0.65f), // color
                                            glm::vec3(0.0f, 3.0f, -7.0f),  // position
                                            glm::vec3(0.0f),               // direction (unused)
                                            40.0f, 18.0f);                 // intensity, range
engine.addLightToScene(scene, lamp);
struct Light
{
    LightHandle handle;
    LightType   type;
    float       intensity = 1.0f;
    float       range     = 10.0f;
    glm::vec3   color     = glm::vec3(1.0f);
    glm::vec3   position  = glm::vec3(1.0f);
    glm::vec3   direction = glm::vec3(0.0f, -1.0f, 0.0f);
};

The record the engine keeps for each light. drawScene copies the scene's lights into the GPU's scene data on every call.

enum class LightType { DIRECTIONAL, POINT };

The two light kinds. The order matches the shader's LightType in shaders/lib/core.slang.

Known limits

Nothing can be destroyed or removed from a scene, and pool space is never reused (D4). The fixed counts above are compile-time constants (D15). Lights have no update function, and only 7 can exist.
