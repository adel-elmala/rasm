API reference

Types, handles and limits

The small shared types: the handle that names every engine object, the enums and plain structs of rasm/types.h, the window state, the memory stats, and every compile-time limit.

1Handles

template <typename Tag>
struct Handle
{
    uint64_t index      = 0;
    uint64_t generation = 0;

    [[nodiscard]] bool isValid() const { return generation != 0; }
    bool operator==(const Handle& other) const;
};

The name of an engine object. Tag is an empty struct that makes each kind a different type, so a MeshHandle cannot be passed where a TextureHandle is expected.

index
The slot in the engine's list for that kind of object. Starts at 1.
generation
1 for every object the engine creates; 0 for a default-constructed handle.
isValid()
generation != 0. Every create function returns an invalid ({}) handle on failure, so check it.
operator==
Equal when both index and generation are equal.

isValid() does not tell you that an object still exists: handles are never reused or invalidated, and the generation is always 1 (D4).

struct HandleHash
{
    template <typename Tag>
    std::size_t operator()(const Handle<Tag>& handle) const;
};

A hash for any handle, so handles can be keys: std::unordered_map<TextureHandle, uint32_t, HandleHash>. It combines the hashes of index and generation with hashCombine.

inline std::size_t hashCombine(std::size_t seed, std::size_t value);

Mixes value into seed (the Boost formula with the 64-bit golden ratio). Used by HandleHash and the desc hashes in src/rhi/resource.cpp.

2Enums in rasm/types.h

enum class Format
{
    R8G8B8A8_UNORM, R8G8B8A8_SRGB, B8G8R8A8_SRGB, R8G8B8_UNORM,
    R16G16B16A16_SFLOAT, R32G32B32_SFLOAT, R32G32B32A32_SFLOAT,
    D24_UNORM_S8_UINT, D32_SFLOAT, D32_SFLOAT_S8_UINT,
    R32G32_SFLOAT, U16_UINT, U32_UINT, UNKNOWN
};

Texture, attachment and index formats. Each maps to the Vulkan format of the same name (R8G8B8A8_UNORM → VK_FORMAT_R8G8B8A8_UNORM), except the index types.

ValueUsed for
R8G8B8A8_SRGBcolor textures: albedo, emissive. The default of loadTexture. Gets a mip chain.
R8G8B8A8_UNORMdata textures: normal, metallic-roughness, occlusion. Gets a mip chain.
B8G8R8A8_SRGBthe swapchain format RASM asks for; use getSwapchainImageFormat() for the real one
D32_SFLOATthe engine's depth format; needed by drawScene and createPipeline
D24_UNORM_S8_UINT, D32_SFLOAT_S8_UINTdepth + stencil, for pipelines you build yourself
R8G8B8_UNORM, R16G16B16A16_SFLOAT, R32G32_SFLOAT, R32G32B32_SFLOAT, R32G32B32A32_SFLOATother texture formats; no engine path uses them. Only the RGBA8 formats get mips, and fillTexture expects 4 bytes per pixel.
U16_UINT, U32_UINTindex types for bindIndexBuffer only, not texture formats
UNKNOWNno format (the default in descs; compute pipelines have no attachments)

Color textures must be sRGB and data textures UNORM. Shaders work in linear color, and sampling an sRGB texture converts it.

enum class Backend { VULKAN, DX12, METAL, WEBGPU };

EngineConfig::preferredBackend. Only VULKAN exists today. The others log The … backend is not implemented yet., and the engine does not start (running returns false).

enum class ShaderType { VERTEX, FRAGMENT, VERTEX_FRAGMENT, COMPUTE };

A shader stage. ShaderDesc::type is VERTEX, FRAGMENT or COMPUTE. pushConstants takes VERTEX_FRAGMENT for graphics pipelines and COMPUTE for compute pipelines.

enum class PrimitiveTopology
{
    TRIANGLE_LIST,
    LINE_LIST,
    POINT_LIST,
    TRIANGLE_STRIP,
    LINE_STRIP,
};

How vertices form primitives, in PipelineDesc::topology. Engine::createPipeline always uses TRIANGLE_LIST; the others need RenderContext::createPipeline.

enum class CullMode { NONE, FRONT, BACK };

Which triangles setCullMode skips. Front faces are counter-clockwise. Each pass starts with NONE. drawScene picks one per sub-mesh: NONE for a doubleSided material, else BACK, or FRONT when the transform mirrors the mesh.

enum class SwapchainStatus { OK, SUBOPTIMAL, OUT_OF_DATE, FAILURE };

Result of acquire, present and swapchain re-creation.

OK
Done.
SUBOPTIMAL
The image was acquired or presented, but the swapchain should be re-created. The engine finishes the frame and re-creates it at the next beginFrame.
OUT_OF_DATE
The swapchain cannot be used (or the window is 0 × 0) until it is re-created. The engine skips the frame.
FAILURE
An error. When acquiring, the engine skips the frame.

3Plain structs

struct EngineConfig
{
    std::string appName               = {};

    int         windowHeight          = 0;
    bool        enableValidation      = false;
    Backend     preferredBackend      = Backend::VULKAN;

    std::string shaderDir             = {};

    uint32_t    geometryPoolIndices   = 1u << 23;
    uint32_t    geometryPoolSubMeshes = 1u << 14;
    uint32_t    maxInstances          = 1u << 16;
    bool        showStats             = false;
};

The engine's settings, given to its constructor. Every field is explained on the Engine page.

struct FrameResources
{
    CommandBufferHandle commandBuffer;
    TextureHandle       depthTexture;
    uint64_t            fenceValue = 0;
};

One frame slot's objects, from getCurrentFrameResources.

commandBuffer
The frame's command buffer. Record into it between beginFrame and endFrame.
depthTexture
The D32_SFLOAT depth of swapchain passes, swapchain-sized. Replaced when the window is resized.
fenceValue
The frame fence value that this slot's last submit signals; beginFrame waits for it.
struct RenderTargetAttachments
{
    TextureHandle color;
    TextureHandle depth;
};

struct RenderTarget
{
    RenderTargetAttachments attachments[rasm::MAX_FRAMES_IN_FLIGHT];
    uint32_t                width;
    uint32_t                height;
    Format                  colorFormat;
    Format                  depthFormat;
    glm::vec4               clearColor;
};

A render target as RenderContext::getRenderTarget returns it: the values of its RenderTargetDesc, plus one RenderTargetAttachments pair (color, depth) per frame slot. getRenderTargetTexture picks attachments[slot].color for the current slot.

struct Swapchain
{
    std::vector<TextureHandle> imageHandles;
    Format                     imageFormat;
    uint32_t                   width  = 0;
    uint32_t                   height = 0;
};

The engine's own copy of the swapchain state (images, format, size in pixels). It is not reachable from outside the engine; use getSwapchainImages, getSwapchainImageFormat and getSwapchainExtent on the RenderContext.

struct TextureRaw
{
    uint32_t       width  = 0;
    uint32_t       height = 0;
    unsigned char* data   = nullptr;
};

A decoded image: loadTexture's worker thread fills it with RGBA8 pixels from stb_image, and the main thread uploads and frees it. data is null when decoding failed. Applications do not see it.

struct Window
{
    WindowHandle handle;
    uint32_t     width;
    uint32_t     height;
    uint32_t     pixelWidth;
    uint32_t     pixelHeight;
    bool         mouseDragActive;
    bool         resized;
    bool         minimized;
    glm::vec2    lastMousePos = glm::vec2(0.0f);
};

The state of the engine's one window, read with getMainWindow. pollEvents keeps it up to date.

handle
Valid when the window exists.
width, height
Logical size, the units of mouse coordinates.
pixelWidth, pixelHeight
Drawable size in pixels. Larger than width and height on HiDPI displays. The swapchain, depth textures and camera aspect follow these. Use them for viewport math, as examples/01_render_graph does.
mouseDragActive
A mouse button is held down.
resized
The pixel size changed; beginFrame re-creates the swapchain and clears it.
minimized
The window is minimized; frames are skipped.
lastMousePos
The last drag position, in the NDC of CameraInput.
struct VRAMStats
{
    uint64_t vramBudget = 0;
    uint64_t vramUsage  = 0;
    uint64_t hostBudget = 0;
    uint64_t hostUsage  = 0;
};

GPU memory in bytes, summed over the memory heaps, from queryVRAMStats, Engine::queryMemoryStats or FrameStats::memory.

vramBudget, vramUsage
Device-local heaps (video memory): how much this process may use now, and how much it uses.
hostBudget, hostUsage
The other heaps (system memory the GPU can reach).

4Constants and limits

All are constexpr in the public headers. Exceeding a create limit logs a warning or error and returns an invalid handle. Because handle indices start at 1 and are never reused, the limits on handle indices hold one object less than their value, and a failed create uses up an index too (B13).

Mesh and instance capacity on the GPU is not a constant: it comes from EngineConfig::geometryPoolVertices, geometryPoolIndices, geometryPoolSubMeshes and maxInstances.

Known limits

The limits are fixed at compile time and spread over several headers (D15). Handles are never reused and objects cannot be destroyed (D4), so a long-running application that creates and drops objects runs into these limits.
