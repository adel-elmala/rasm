API reference

Types, handles and limits

The small shared types: the handle that names every engine object, the enums and plain structs of rasm/types.h, the window state, the memory stats, and every compile-time limit.

1Handles

template <typename Tag>
struct Handle
{
    uint64_t index      = 0;
    uint64_t generation = 0;

    [[nodiscard]] bool isValid() const { return generation != 0; }
    bool operator==(const Handle& other) const;
};

The name of an engine object. Tag is an empty struct that makes each kind a different type, so a MeshHandle cannot be passed where a TextureHandle is expected.

index
The slot in the engine's list for that kind of object. Starts at 1.
generation
1 for every object the engine creates; 0 for a default-constructed handle.
isValid()
generation != 0. Every create function returns an invalid ({}) handle on failure, so check it.
operator==
Equal when both index and generation are equal.

isValid() does not tell you that an object still exists: handles are never reused or invalidated, and the generation is always 1 (D4).

struct HandleHash
{
    template <typename Tag>
    std::size_t operator()(const Handle<Tag>& handle) const;
};

A hash for any handle, so handles can be keys: std::unordered_map<TextureHandle, uint32_t, HandleHash>. It combines the hashes of index and generation with hashCombine.

inline std::size_t hashCombine(std::size_t seed, std::size_t value);

Mixes value into seed (the Boost formula with the 64-bit golden ratio). Used by HandleHash and the desc hashes in src/rhi/resource.cpp.

enum class Format
{
    UNKNOWN,
    R8G8B8A8_UNORM, R8G8B8A8_SRGB, B8G8R8A8_SRGB, R8G8B8_UNORM,
    R16G16B16A16_SFLOAT, R32G32B32_SFLOAT, R32G32B32A32_SFLOAT,
    D24_UNORM_S8_UINT, D32_SFLOAT, D32_SFLOAT_S8_UINT,
    R32G32_SFLOAT, U16_UINT, U32_UINT,
    BC4_UNORM, BC5_UNORM, BC7_UNORM, BC7_SRGB,
    ASTC_4x4_UNORM, ASTC_4x4_SRGB,
    ETC2_R8G8B8A8_UNORM, ETC2_R8G8B8A8_SRGB,
    EAC_R11_UNORM, EAC_R11G11_UNORM,
    R16G16_SFLOAT,
};

Texture, attachment and index formats. Each maps to the Vulkan format of the same name (R8G8B8A8_UNORM → VK_FORMAT_R8G8B8A8_UNORM), except the index types.

ValueUsed for
R8G8B8A8_SRGBcolor textures: albedo, emissive. The default of loadTexture. Gets a mip chain.
R8G8B8A8_UNORMdata textures: normal, metallic-roughness, occlusion. Gets a mip chain.
B8G8R8A8_SRGBthe swapchain format RASM asks for; use getSwapchainImageFormat() for the real one
D32_SFLOATthe engine's depth format; needed by addScenePasses and createPipeline. The only depth format a pass can sample (readDepth)
D24_UNORM_S8_UINT, D32_SFLOAT_S8_UINTdepth + stencil, for pipelines you build yourself
BC7_SRGB, ASTC_4x4_SRGB, ETC2_R8G8B8A8_SRGBblock-compressed color, 16 bytes per 4 × 4 texels. loadTexture picks one for a .ktx2 file in a color slot.
BC7_UNORM, ASTC_4x4_UNORM, ETC2_R8G8B8A8_UNORMblock-compressed data, 16 bytes per 4 × 4 texels
BC5_UNORM, EAC_R11G11_UNORMtwo channels, 16 bytes per 4 × 4: a normal map's x and y (the shader computes z)
BC4_UNORM, EAC_R11_UNORMone channel, 8 bytes per 4 × 4
R16G16B16A16_SFLOATthe scene color target and environment images
R16G16_SFLOATa scene target's motion color (MOTION_FORMAT), for TAA
R8G8B8_UNORM, R32G32_SFLOAT, R32G32B32_SFLOAT, R32G32B32A32_SFLOATother texture formats; no engine path uses them.
U16_UINT, U32_UINTindex types for bindIndexBuffer only, not texture formats
UNKNOWNno format (the default in descs; compute pipelines have no attachments)

Color textures must be sRGB and data textures UNORM. Shaders work in linear color, and sampling an sRGB texture converts it. A GPU samples only some of the block-compressed formats: ask supportsTextureFormat, and see texture compression. Only RGBA8 textures get their mips made by fillTexture; the others take every level.

enum class Backend { VULKAN, DX12, METAL, WEBGPU };

EngineConfig::preferredBackend. Only VULKAN exists today. The others log The … backend is not implemented yet., and the engine does not start (running returns false).

enum class ShaderType { VERTEX, FRAGMENT, VERTEX_FRAGMENT, COMPUTE, ALL };

A shader stage. ShaderDesc::type is VERTEX, FRAGMENT or COMPUTE. pushConstants takes VERTEX_FRAGMENT for graphics pipelines and COMPUTE for compute pipelines. ALL is every stage, for descriptor set layouts: the engine's bindless layout uses it, so compute shaders can sample textures too.

enum class PrimitiveTopology
{
    TRIANGLE_LIST,
    LINE_LIST,
    POINT_LIST,
    TRIANGLE_STRIP,
    LINE_STRIP,
};

How vertices form primitives, in PipelineDesc::topology. Engine::createPipeline always uses TRIANGLE_LIST; the others need RenderContext::createPipeline.

enum class CullMode { NONE, FRONT, BACK };

Which triangles setCullMode skips. Front faces are counter-clockwise. Each pass starts with NONE. The scene's draw passes pick one per sub-mesh: NONE for a doubleSided or a BLEND material, else BACK, or FRONT when the transform mirrors the mesh.

enum class BlendMode
{
    NONE,
    PREMULTIPLIED_ALPHA,
};

How a pipeline's colors mix with what the target holds (PipelineDesc::blendMode).

NONE
The shader's color replaces the target's.
PREMULTIPLIED_ALPHA
result = source + (1 − source alpha) × target, for color and alpha. The shader outputs its color already multiplied by its alpha. This is the "over" operator of see-through (glTF BLEND) draws; see the transparency guide.
enum class SwapchainStatus { OK, SUBOPTIMAL, OUT_OF_DATE, FAILURE };

Result of acquire, present and swapchain re-creation.

OK
Done.
SUBOPTIMAL
The image was acquired or presented, but the swapchain should be re-created. The engine finishes the frame and re-creates it at the next beginFrame.
OUT_OF_DATE
The swapchain cannot be used (or the window is 0 × 0) until it is re-created. The engine skips the frame.
FAILURE
An error. When acquiring, the engine skips the frame.

enum class AntiAliasing
{
    NONE,
    MSAA_2X,
    MSAA_4X,
    MSAA_8X,
    TAA,
};

How Engine::render smooths edges (EngineConfig::antiAliasing). MSAA_nX draws the scene with n samples per pixel and resolves them in a pass of the graph (addMsaaResolvePass); a count the device does not have falls back to the most it has, with a warning. TAA jitters the view and blends the frames (addTaaPass, Temporal anti-aliasing). See MSAA and alpha-to-coverage.

struct FrameResources
{
    CommandBufferHandle commandBuffer;
    uint64_t            fenceValue          = 0;
    uint64_t            computeFenceValue   = 0;
};

One frame slot's objects, from getCurrentFrameResources.

commandBuffer
The command buffer being recorded right now. Record into it between beginFrame and endFrame. With EngineConfig::asyncCompute a frame has several, one per batch of passes on one queue, and the render graph moves this field between them as passes change queue. So fetch it inside each pass.
fenceValue
The frame fence value that this slot's last graphics submit signals; beginFrame waits for it.
computeFenceValue
The compute fence value that this slot's last compute submit signals. With async compute beginFrame waits for it too. 0 without a compute queue.
struct RenderTargetAttachments
{
    TextureHandle color[rasm::MAX_COLOR_ATTACHMENTS];
    TextureHandle depth;
};

struct RenderTarget
{
    RenderTargetAttachments attachments[rasm::MAX_FRAMES_IN_FLIGHT];
    uint32_t                width;
    uint32_t                height;
    Format                  colorFormats[rasm::MAX_COLOR_ATTACHMENTS];
    uint32_t                colorCount;
    Format                  depthFormat;
    glm::vec4               clearColor;
    bool                    history;
    uint32_t                samples = 1;
    uint32_t                storageSlots[rasm::MAX_FRAMES_IN_FLIGHT][rasm::MAX_COLOR_ATTACHMENTS] = {};
};

A render target as RenderContext::getRenderTarget returns it: the values of its RenderTargetDesc, plus one RenderTargetAttachments entry (its colors, its depth) per frame slot. Only the first colorCount colors are used. Without history every entry holds the same textures; with it each slot has its own. getRenderTargetTexture(rt, i) picks attachments[slot].color[i] for the current slot, and getPreviousRenderTargetTexture the previous slot's. samples is the desc's samples per pixel; storageSlots holds a storage target's slot per frame slot and color (UINT32_MAX for any other target; both frame slots share one without history), which getRenderTargetStorageIndex returns.

struct Swapchain
{
    std::vector<TextureHandle> imageHandles;
    Format                     imageFormat;
    uint32_t                   width  = 0;
    uint32_t                   height = 0;
};

The engine's own copy of the swapchain state (images, format, size in pixels). It is not reachable from outside the engine; use getSwapchainImages, getSwapchainImageFormat and getSwapchainExtent on the RenderContext.

struct TextureRaw
{
    uint32_t       width  = 0;
    uint32_t       height = 0;
    unsigned char* data   = nullptr;
};

A decoded image: loadTexture's worker thread fills it with RGBA8 pixels from stb_image, and the main thread uploads and frees it. data is null when decoding failed. Applications do not see it.

struct EnvironmentRaw
{
    uint32_t                width   = 0;
    uint32_t                height  = 0;
    std::vector<uint16_t>   pixels;
};

A decoded environment image: loadEnvironment's worker thread fills pixels with RGBA half floats (linear, clamped to 65504), and the main thread uploads it. pixels is empty when decoding failed. Applications do not see it.

Logical size, the units of mouse coordinates.

The last drag position, in the NDC of CameraInput.

4Constants and limits

All are constexpr in the public headers. Exceeding a create limit logs a warning or error and returns an invalid handle. Because handle indices start at 1 and are never reused, the limits on handle indices hold one object less than their value, and a failed create uses up an index too (B13).

MAX_FRAMES_IN_FLIGHT
rasm/types.h		2Frame slots. The CPU records one frame while the GPU runs the other.
MAX_COLOR_ATTACHMENTS
rasm/types.h		4Color attachments of one render target or pipeline. Vulkan guarantees at least 4.
MAX_BINDLESS_TEXTURES

Each color of a storage render target takes one of the others for the target's life; addBloomPasses takes 11. A target that does not fit logs an error that names this limit and is not made. Startup checks it against the device (Vulkan: maxDescriptorSetUpdateAfterBindStorageImages), with an error that names both numbers.

Known limits

The limits are fixed at compile time and spread over several headers (D15). Handles are never reused and objects cannot be destroyed (D4), so a long-running application that creates and drops objects runs into these limits.
