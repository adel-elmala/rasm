API reference

Types, handles and limits

The small shared types: the handle that names every engine object, the enums and plain structs of rasm/types.h, the window state, the memory stats, and every compile-time limit.

1Handles

template <typename Tag>
struct Handle
{
    uint64_t index      = 0;
    uint64_t generation = 0;

    [[nodiscard]] bool isValid() const { return generation != 0; }
    bool operator==(const Handle& other) const;
};

The name of an engine object. Tag is an empty struct that makes each kind a different type, so a MeshHandle cannot be passed where a TextureHandle is expected.

index
The slot in the engine's list for that kind of object. Starts at 1.
generation
The generation of the slot when the object was made: 1 the first time, one more each time the slot was reused. 0 for a default-constructed handle.
isValid()
generation != 0. Every create function returns an invalid ({}) handle on failure, so check it.
operator==
Equal when both index and generation are equal.

isValid() does not tell you that the object still exists. The engine does: a call with a handle whose object was destroyed logs an error and does nothing, even when a new object took its index.

struct HandleHash
{
    template <typename Tag>
    std::size_t operator()(const Handle<Tag>& handle) const;
};

A hash for any handle, so handles can be keys: std::unordered_map<TextureHandle, uint32_t, HandleHash>. It combines the hashes of index and generation with hashCombine.

inline std::size_t hashCombine(std::size_t seed, std::size_t value);

Mixes value into seed (the Boost formula with the 64-bit golden ratio). Used by HandleHash and the desc hashes in src/rhi/resource.cpp.

struct HandleSlot
{
    uint64_t    index       = 0;
    uint64_t    generation  = 0;
};

constexpr uint64_t MAX_HANDLE_GENERATION = UINT32_MAX;

class HandlePool
{
public:
                HandlePool() = default;
    explicit    HandlePool(uint64_t limit, uint64_t maxGeneration = MAX_HANDLE_GENERATION); // indices 1 .. limit - 1

    HandleSlot  allocate();                                         // {0, 0} when every index is in use
    bool        release(uint64_t index, uint64_t generation);       // false for a stale or invalid handle
    bool        isAlive(uint64_t index, uint64_t generation) const;
    uint64_t    size() const;                                       // one past the highest index handed out
    uint64_t    liveCount() const;
};

Where handles come from. Each of the engine's tables has one: the registry's entities, meshes, materials, cameras, lights, scenes, environments and readbacks, and each kind of RenderContext object. Applications never use one: the create functions do.

allocate
The index released last, if there is one (a stack), else a new index. The handle takes the slot's current generation. Index 0 means the pool is full: a pool made with a limit holds at most limit − 1 live indices, which is how the MAX_* limits work.
release
Frees the index and adds 1 to its generation, so every handle made for it before is stale. A slot whose generation reaches maxGeneration (MAX_HANDLE_GENERATION, 232 − 1) is never reused: it costs one index after four billion reuses of it, and every handle fits the C API's 64-bit id (c-api.html).
isAlive
True only for the handle the slot gave out last, while it is not released. Generation 0 is never alive.
size
One past the highest index handed out: a table indexed by handle needs this many rows. Reuse keeps it at the peak number of live objects.

The design, and why it finds a stale handle, is the guide Generational handles.

Color textures must be sRGB and data textures UNORM. Shaders work in linear color, and sampling an sRGB texture converts it. A GPU samples only some of the block-compressed formats: ask supportsTextureFormat, and see texture compression. Only RGBA8 textures get their mips made by fillTexture; the others take every level.

enum class CullMode { NONE, FRONT, BACK };

Which triangles setCullMode skips. Front faces are counter-clockwise. Each pass starts with NONE. The scene's draw passes pick one per sub-mesh: NONE for a doubleSided or a BLEND material, else BACK, or FRONT when the transform mirrors the mesh.

enum class BlendMode
{
    NONE,
    PREMULTIPLIED_ALPHA,
    ADDITIVE,
    WEIGHTED,
    WEIGHTED_MOTION,
    ADDITIVE_COLOR,
};

How a pipeline's colors mix with what the target holds (PipelineDesc::blendMode).

NONE
The shader's color replaces the target's.
PREMULTIPLIED_ALPHA
result = source + (1 − source alpha) × target, for color and alpha. The shader outputs its color already multiplied by its alpha. This is the "over" operator of see-through (glTF BLEND) draws; see the transparency guide.
ADDITIVE
result = source + target, for color and alpha. Draws that write 1 count the fragments that reach a pixel: the overdraw view does this (Debug views).
WEIGHTED
Color 1 blends as PREMULTIPLIED_ALPHA, every other color as ADDITIVE: the sums and the coverage of weighted blended transparency.
WEIGHTED_MOTION
As WEIGHTED, but color 1's color channels add and only its alpha blends as PREMULTIPLIED_ALPHA: motion sums beside the coverage, with TAA.
ADDITIVE_COLOR
Color 0 blends as ADDITIVE, every other color as PREMULTIPLIED_ALPHA: added light that lays its motion over the motion behind it by its alpha.

WEIGHTED, WEIGHTED_MOTION and ADDITIVE_COLOR blend each color differently, which needs the device's independentBlend feature (RenderContext::hasIndependentBlend).

enum class SwapchainStatus { OK, SUBOPTIMAL, OUT_OF_DATE, FAILURE };

Result of acquire, present and swapchain re-creation.

OK
Done.
SUBOPTIMAL
The image was acquired or presented, but the swapchain should be re-created. The engine finishes the frame and re-creates it at the next beginFrame.
OUT_OF_DATE
The swapchain cannot be used (or the window is 0 × 0) until it is re-created. The engine skips the frame.
FAILURE
An error. When acquiring, the engine skips the frame.

An EngineConfig in its parts. A Renderer's settings are RendererConfig: without platform, which a Renderer does not choose, and without the loading fields. With nativeWindow set it draws into that window; without one it draws into offscreen images of windowWidth × windowHeight pixels. An AssetLoader's are AssetLoaderConfig: the folder relative paths resolve against (itself relative to the executable's folder), the worker threads (0: the hardware's minus one) and the bytes of decoded loads in memory at once. All three structs stay flat, so designated initializers work. Engine's constructor splits its config with toRendererConfig and toAssetLoaderConfig, and Engine::getConfig joins it again with toEngineConfig; tests/rendererConfigTests.cpp checks that every field arrives both ways. A new field goes in EngineConfig, in its part's struct and in the conversions.

enum class PlatformType
{
    SDL,
    HEADLESS,
    NATIVE,
};

Who owns the window and the input (EngineConfig::platform). SDL: the engine opens an SDL3 window and reads its events. HEADLESS: no window and no SDL; each frame renders into an offscreen swapchain of windowWidth × windowHeight pixels, which readFrame copies back. NATIVE: the engine draws into the application's window (EngineConfig::nativeWindow), and the application runs the event loop and sends the input with addInputEvent, setWindowSize and setWindowContentScale. See Engine: your own window, Engine: headless and The platform layer.

{
    NONE,
    WINDOWS,
    X11,
    XCB,
    WAYLAND,
    METAL,

Which window system a NativeWindow comes from. WINDOWS on Windows, METAL (a CAMetalLayer) on macOS, X11, XCB or WAYLAND on Linux. A type another operating system's build has no surface for makes the engine fail to start, with an error.

enum class AntiAliasing
{
    NONE,
    MSAA_2X,
    MSAA_4X,
    MSAA_8X,
    TAA,
    DEFAULT,    // View::antiAliasing: the EngineConfig value; in EngineConfig, NONE
};

How Renderer::render smooths edges (EngineConfig::antiAliasing, or per view View::antiAliasing, where DEFAULT takes the engine's value). MSAA_nX draws the scene with n samples per pixel and resolves them in a pass of the graph (addMsaaResolvePass); a count the device does not have falls back to the most it has, with a warning. TAA jitters the view and blends the frames (addTaaPass, Temporal anti-aliasing). See MSAA and alpha-to-coverage.

enum class MeshletPath
{
    OFF,
    VERTEX_PULLING,
    MESH_SHADERS,
    AUTO,
};

How the scene passes draw a visible mesh whose LOD has 8 meshlets or more (EngineConfig::meshletPath, Renderer::setMeshletPath). OFF: the whole draw. VERTEX_PULLING: compute culls each meshlet and writes the visible ones as indirect draws, which the usual vertex shader draws. MESH_SHADERS: a task shader culls them inside the draw and mesh shaders draw the visible ones; where the GPU has no mesh shaders (RenderContext::hasMeshShaders, e.g. MoltenVK) it draws by vertex pulling. AUTO, the default: MESH_SHADERS where the GPU has them, else OFF. All draw the same triangles. See Meshlets and cluster culling.

struct FrameResources
{
    CommandBufferHandle commandBuffer;
    uint64_t            fenceValue          = 0;

};

One frame slot's objects, from getCurrentFrameResources.

commandBuffer
The command buffer being recorded right now. Record into it between beginFrame and endFrame. With EngineConfig::asyncCompute a frame has several, one per batch of passes on one queue, and the render graph moves this field between them as passes change queue. So fetch it inside each pass.
fenceValue
The frame fence value that this slot's last graphics submit signals; beginFrame waits for it.
computeFenceValue
The compute fence value that this slot's last compute submit signals. With async compute beginFrame waits for it too. 0 without a compute queue.

struct RenderTarget
{
    RenderTargetAttachments attachments[rasm::MAX_FRAMES_IN_FLIGHT];
    uint32_t                width;
    uint32_t                height;

    uint32_t                colorCount;
    Format                  depthFormat;
    glm::vec4               clearColor;
    bool                    history;

    uint32_t                version = 0;

A render target as RenderContext::getRenderTarget returns it: the values of its RenderTargetDesc, plus one RenderTargetAttachments entry (its colors, its depth) per frame slot. Only the first colorCount colors are used. Without history every entry holds the same textures; with it each slot has its own. getRenderTargetTexture(rt, i) picks attachments[slot].color[i] for the current slot, and getPreviousRenderTargetTexture the previous slot's. samples is the desc's samples per pixel; version counts the times its textures were made (a resize, a new placement): they keep their handles but not their contents, so a reader of its history starts over when it changes. storageSlots holds a storage target's slot per frame slot and color (UINT32_MAX for any other target; both frame slots share one without history), which getRenderTargetStorageIndex returns.

struct TextureRaw
{
    uint32_t                    width  = 0;
    uint32_t                    height = 0;
    Format                      format = Format::UNKNOWN;
    std::vector<unsigned char>  levels;
    std::vector<uint64_t>       levelSizes;
};

A decoded texture with every mip level, made on a worker thread: loadTexture's worker and a glTF import fill it from a PNG or JPEG (the mips made there) or a KTX2 file, and the main thread only copies it into the texture. levels holds the levels one after another, level 0 first, and levelSizes the size of each. levelSizes is empty when decoding failed. Applications do not see it. See texture uploads.

{
    uint32_t                width   = 0;
    uint32_t                height  = 0;
    std::vector<uint16_t>   pixels;
};

A decoded environment image: loadEnvironment's worker thread fills pixels with RGBA half floats (linear, clamped to 65504), and the main thread uploads it. pixels is empty when decoding failed. Applications do not see it.

The state of a window the engine draws into, read with getMainWindow or getWindow. pollEvents keeps it up to date with SDL; with NATIVE and headless, setWindowSize and setWindowContentScale do. A headless engine's window has no native handle, and its pixel size is its offscreen swapchain's. An engine draws into at most MAX_WINDOWS − 1 (7) windows at once; the main window's handle index is MAIN_WINDOW_INDEX (1).

handle
The engine's handle of the window, on every platform: what addWindow returned, or the main window's.
platformWindow
The SDL platform's SDL_Window; null for NATIVE and headless.
native
The handles the surface is made from: SDL's window's, or EngineConfig::nativeWindow. Type NONE headless.
width, height
Logical size, the units of mouse coordinates.
pixelWidth, pixelHeight
Drawable size in pixels. Larger than width and height on HiDPI displays. The swapchain, the render targets sized from it and the camera aspect follow these. Use them for viewport math, as examples/01_render_graph does.
contentScale
The display's scale setting, which sizes the UI. 1 headless.
resized
The pixel size changed; beginFrame re-creates the swapchain and clears it.
minimized
The window is minimized, or its pixel size is 0: it sits the frames out, and a frame is skipped when no window can show.
struct VRAMStats
{
    uint64_t vramBudget    = 0;
    uint64_t vramUsage     = 0;
    uint64_t vramAllocated = 0;
    uint64_t hostBudget    = 0;
    uint64_t hostUsage     = 0;
};

GPU memory in bytes, summed over the memory heaps, from queryVRAMStats, Renderer::queryMemoryStats or FrameStats::memory.

vramBudget, vramUsage
Device-local heaps (video memory): how much this process may use now, and how much it uses. The usage counts whole memory blocks, and the allocator puts many textures and buffers in one block, so it grows in steps (256 MiB on a large heap).
vramAllocated
The bytes of the resources inside those blocks: what the buffers and textures take. Use it to see what a load or a destroy changed; the stats overlay and the RASM window show it as allocated.
hostBudget, hostUsage
The other heaps (system memory the GPU can reach).
struct Viewport
{
    float x        = 0.0f;
    float y        = 0.0f;
    float width    = 0.0f;
    float height   = 0.0f;
    float minDepth = 0.0f;
    float maxDepth = 1.0f;
};

The last viewport set with setViewport, from getViewport. Pixels, with x, y at the top-left corner.

enum class ReadbackFormat
{
    RGBA8_SRGB,
    RGBA32_FLOAT,
};

What takeReadback converts the copied texels to (rasm/readback.h).

RGBA8_SRGB
4 bytes per pixel, sRGB-encoded: 8-bit sources keep their bytes (BGRA is swizzled), float sources are clamped to 0..1 and encoded. Ready for writePng.
RGBA32_FLOAT
16 bytes per pixel, linear: sRGB sources are decoded, half floats widened. The only format a depth reads as: the depth in red, then 0, 0, 1.
struct ReadbackImage
{
    uint32_t                    width       = 0;
    uint32_t                    height      = 0;
    ReadbackFormat              format      = ReadbackFormat::RGBA8_SRGB;
    std::vector<uint8_t>        pixels;
};

An image copied back by takeReadback: width × height pixels in format, rows from top to bottom, with no padding between them.

bool writePng(const std::string& path, const ReadbackImage& image);

Writes an RGBA8_SRGB image as a PNG file at a UTF-8 path. Returns false (with an error in the log) for an RGBA32_FLOAT image or when the file can't be written.

rasm::ReadbackImage image;
if (engine.takeReadback(copy, image))
    rasm::writePng("screenshot.png", image);
bool readPng(const std::string& path, ReadbackImage& image);

Reads a PNG file at a UTF-8 path into an RGBA8_SRGB image, the format writePng writes, so a frame can be compared with a stored one byte by byte (Image tests). Returns false (with an error in the log) when the file can't be opened or decoded.

rasm::ReadbackImage golden;
if (rasm::readPng("golden.png", golden) && golden.width == image.width)
    std::printf("%zu bytes to compare\n", golden.pixels.size());

4Input events in rasm/input.h

What an application that owns its window sends with Renderer::addInputEvent. RASM's SDL platform makes the same events from its window, so every input reaches the camera, Dear ImGui and the built-in keys the same way (The platform layer). The types are plain: an enum for the kind and plain fields, so a C API can copy them as they are.

struct InputEvent
{
    InputEventType  type            = InputEventType::NONE;
    WindowHandle    window;
    Key             key             = Key::NONE;
    Key             physicalKey     = Key::NONE;
    bool            down            = false;
    bool            repeat          = false;
    uint8_t         modifiers       = 0;
    MouseButton     button          = MouseButton::LEFT;
    float           x               = 0.0f;
    float           y               = 0.0f;
    uint32_t        codepoint       = 0;
    float           dx              = 0.0f;
    float           dy              = 0.0f;
};

One input event. Only the fields its type names are read:

typeFieldsGoes to
KEYkey, physicalKey, down, repeat, modifiersImGui and F1–F3 by key (ImGui by physicalKey when key is NONE); the camera's W/A/S/D by physicalKey
MOUSE_BUTTONbutton, down, x, yImGui; the camera's drag its CameraButtons map gives the button
MOUSE_MOVEx, y, dx, dyImGui by x, y; the camera's drag by dx, dy
MOUSE_WHEELx, y: steps, y > 0 away from the user, x > 0 to the rightImGui; the camera's zoom
MOUSE_LEAVEnoneImGui: no window is hovered
TEXTcodepoint: one Unicode characterImGui's text fields
FOCUSdown: gained, else lostImGui; losing it lets go of every held key and ends the camera's drag
WINDOW_CLOSEnonethe application: the user closed a window other than the main one (the SDL platform sends it; closing the main window quits). Remove it with removeWindow.

Only the main window's events (an invalid window, or the main window's handle) reach ImGui, the built-in keys and the engine's camera input; getInputEvents gives every window's.

window
The window the event happened in (addWindow). The SDL platform sets it; an application that sends another window's events sets it too. Invalid: the main window.
key
The key's meaning in the current keyboard layout: the key that types Z on an AZERTY keyboard is Key::Z.
physicalKey
Where the key is, named after the US layout: the same key is Key::W, so the camera's W/A/S/D keep their places. Key::NONE: the same as key, for an application that knows only one of the two.
x, y
Mouse positions in window points from the top-left corner, the units of EngineConfig::windowWidth.
dx, dy
A move's motion since the last move, in window points. During a mouse grab (setMouseGrab) the pointer stands still and only these move. Both 0: the camera's drag moves by the change of x and y, so a script needs only positions.
engine.addInputEvent({.type = rasm::InputEventType::KEY, .key = rasm::Key::Z, .physicalKey = rasm::Key::W, .down = true});
engine.addInputEvent({.type = rasm::InputEventType::MOUSE_BUTTON, .down = true, .button = rasm::MouseButton::LEFT, .x = 400.0f, .y = 300.0f});
engine.addInputEvent({.type = rasm::InputEventType::TEXT, .codepoint = 0x00E9});

5Constants and limits

All are constexpr in the public headers. Exceeding a create limit logs a warning or error and returns an invalid handle. Because handle indices start at 1, the limits on handle indices hold one live object less than their value. A destroyed object gives its index back; loadMesh keeps the index of a file that does not parse (B13).

Known limits

The limits are fixed at compile time and spread over several headers (D15). Every object can be destroyed, and its index, rows, ranges and slots are reused, so the limits count what is alive at once (getPoolStats).
