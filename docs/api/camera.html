API reference

Cameras and input

A camera is a projection, a controller and a transform. You create it with createCamera and refer to it by a CameraHandle. Every frame the engine reads the mouse and keyboard, moves the camera with its controller, and eases the rendered pose toward the new one. The matrices come from the rendered pose.

CPU work GPU buffer

In short

  • A new camera gets a TRACK_BALL controller that orbits a point 1 unit in front of it. Change it with setCameraController.
  • Pass the camera to render, beginFrame or RenderGraph::execute. That camera receives the mouse and keyboard input of the frame.
  • The projection is reversed-Z: near is depth 1, far is depth 0. A perspective farZ of 0 (the default when you leave it out) means an infinite far plane.
  • fovY is in degrees. Free-fly yaw and pitch are in radians.
  • An invalid handle logs Invalid camera handle. and the call does nothing (setters) or returns a default value (getters).

CameraHandle createCamera(CameraProjection projection, Transform transform);

Creates a camera at transform with the given projection. The camera looks down its local −Z axis, with +Y up. It can be used in the same frame.

projection
Perspective or orthographic, see CameraProjection. Its aspect is replaced by the swapchain aspect when the swapchain is created again (window resize), see updateCameraAspectRatio.
transform
The start pose. Only position and rotation matter for the view. Both the rendered and the target transform start here.

The camera starts with a TRACK_BALL controller: radius 1, center 1 unit in front of the camera, orbitSensitivity 1, easingSpeed 12. So the first drag does not move the camera away from its pose.

errors An invalid projection logs an error and returns an invalid handle. Past MAX_CAMERAS it logs Exceeded maximum number of cameras. and returns an invalid handle. Handle indices start at 1, so 7 cameras fit, and a refused call still uses up an index (B13).

// examples/01_render_graph: farZ is left out (0), so the far plane is infinite
rasm::CameraHandle camera = engine.createCamera(
    rasm::CameraProjection{.type = rasm::CameraProjection::Type::PERSPECTIVE,
                           .perspective{.fovY = 45.0f,
                                        .aspect = 1920.0f / 1080.0f,
                                        .nearZ = 0.1f}},
    rasm::Transform{glm::vec3(0.0f, 0.0f, -1.0f),        // position
                    glm::quat(1.0f, 0.0f, 0.0f, 0.0f),   // rotation
                    glm::vec3(1.0f)});                   // scale
engine.addCameraToScene(scene, camera);
struct CameraProjection
{
    enum class Type { PERSPECTIVE, ORTHOGRAPHIC };

    struct Perspective
    {
        float fovY;
        float aspect;
        float nearZ;
        float farZ;
    };

    struct Orthographic
    {
        float left;
        float right;
        float bottom;
        float top;
        float nearZ;
        float farZ;
    };

    Type type;
    union
    {
        Perspective     perspective;
        Orthographic    orthographic;
    };
};

The projection. type says which member of the union is used.

fovY
Vertical field of view in degrees.
aspect
Width / height. The engine sets it for every camera when the swapchain is created; drawScene uses a copy fitted to the current pass.
nearZ, farZ
Distances in front of the camera, in world units. Perspective: farZ 0 or infinity gives an infinite far plane.
left … top
Orthographic view box in world units, in camera space. A new aspect keeps the width and the center, and changes the height.

2Controllers

struct CameraController
{
    enum class Type { TRACK_BALL, FREE_FLY };

    struct TrackBall
    {
        float       radius;
        glm::vec3   center;
        float       orbitSensitivity;
    };

    struct FreeFly
    {
        float yaw;
        float pitch;
        float speed;
        float lookSensitivity;
    };

    Type type;
    union
    {
        TrackBall   trackBall;
        FreeFly     freeFly;
    };

    float easingSpeed = 12.0f;
};

How input moves the camera. type says which member of the union is used.

radius
Orbit distance from center. The wheel subtracts its steps from it (never below 0). The rendered distance eases toward it.
center
The point the camera orbits and looks at, in world space.
orbitSensitivity
Multiplies the drag rotation. 1 means the scene follows the cursor.
yaw, pitch
Radians. setCameraController overwrites them from the current view direction, so the view does not jump. Pitch stays within ±89°.
speed
World units per second for W, A, S, D.
lookSensitivity
Radians per NDC unit of mouse drag.
easingSpeed
How fast the rendered pose follows the target: each frame it moves 1 − exp(−easingSpeed × dt) of the way. Higher is snappier. 0 or less snaps at once.
void setCameraController(CameraHandle camera, CameraController controller);

Replaces the controller. The target transform is reset to the current rendered pose, so the camera does not jump. Takes effect at the next updateCamera (the next frame).

controller
For FREE_FLY, yaw and pitch are computed from the current view direction (roll is lost); the values you pass are ignored. For TRACK_BALL, choose center and radius so that the camera already sits on the orbit (see the example). Otherwise the camera moves onto the orbit sphere at the next frame.
// examples/01_render_graph: orbit the bunny at (0, 0, -10)
const glm::vec3 orbitCenter(0.0f, 0.0f, -10.0f);
const glm::vec3 position = engine.getCameraTransform(camera).position;
engine.setCameraController(camera, rasm::CameraController{
    .type = rasm::CameraController::Type::TRACK_BALL,
    .trackBall = {.radius = glm::length(orbitCenter - position),
                  .center = orbitCenter,
                  .orbitSensitivity = 1.0f},
    .easingSpeed = 6.0f});
CameraController getCameraController(CameraHandle camera);

Returns a copy of the controller, including the current radius, yaw and pitch after input. An invalid handle logs an error and returns CameraController{}.

void setCameraTransform(CameraHandle camera, Transform transform);

Moves the camera at once, with no easing: both the rendered and the target transform become transform. The next frame uses it.

With a TRACK_BALL controller the orbit center stays where it was, and the next updateCamera puts the camera back on the orbit sphere around it. To move a trackball camera, call setCameraController after this with a new center and radius.

Transform getCameraTransform(CameraHandle camera);

Returns the rendered (eased) transform, the one the view matrix uses. An invalid handle logs an error and returns Transform{}. See Transform.

void setCameraProjection(CameraHandle camera, CameraProjection projection);

Replaces the projection. The next frame uses it. An invalid projection (see the table in section 1) logs an error and keeps the old one.

CameraProjection getCameraProjection(CameraHandle camera);

Returns a copy of the stored projection. Its aspect is the one of the last swapchain creation, unless you set another one after it. An invalid handle logs an error and returns CameraProjection{}.

4Matrices and depth

glm::mat4 getViewMatrix(CameraHandle camera);

World-to-camera matrix of the rendered pose: conjugate(rotation) × translate(−position). Scale is ignored. An invalid handle logs an error and returns the identity.

glm::mat4 getProjectionMatrix(CameraHandle camera);

The projection matrix of the stored projection, with Vulkan depth range [0, 1] and reversed-Z (near = 1, far = 0). An infinite perspective far plane gives a matrix with depth = nearZ / distance. An invalid handle logs an error and returns the identity.

glm::mat4 getProjectionMatrix(CameraHandle camera, float aspect);

The same, fitted to another aspect ratio. The camera itself does not change. A perspective camera keeps its vertical field of view; an orthographic one keeps its width and center. drawScene calls this with the size of the current pass, so a render target of any shape renders without stretching.

aspect
Width / height of the image you render into.
void updateCameraAspectRatio(float aspect);

Sets the aspect of every camera. The engine calls it with the swapchain's width / height at start-up and after each swapchain re-creation (window resize). You rarely need it: drawScene fits the aspect per pass anyway.

void pollEvents(CameraHandle camera);

Reads all window events, updates the window state (size, minimized, quit), builds a CameraInput and calls updateCamera(camera, input). beginFrame calls it first thing, so render, beginFrame and RenderGraph::execute already do this. Do not call it yourself in a normal frame loop, or the camera moves twice.

camera
The camera that gets the input. It must be valid, or updateCamera logs an error every frame. Pass any valid camera if your frame does not use one (examples/04_compute does this).

main thread The frame time it measures is capped at 0.1 s, and the first frame has 0. While the window is minimized it waits up to 100 ms for an event.

struct CameraInput
{
    glm::vec2 mouseStart = glm::vec2(0.0f);
    glm::vec2 mouseEnd   = glm::vec2(0.0f);
    float     wheelDelta = 0.0f;
    float     deltaTime  = 0.0f;

    bool      forward  = false;
    bool      backward = false;
    bool      left     = false;
    bool      right    = false;
};

One frame of input for updateCamera.

mouseStart, mouseEnd
The drag of this frame, in NDC with +Y up. Both axes are divided by the smaller window side, so the short axis spans [−1, 1] and the long one is wider. Equal values mean no drag.
wheelDelta
Wheel steps this frame (positive = away from you).
deltaTime
Seconds since the last frame. Used for free-fly movement and easing.
forward … right
Held keys (W, S, A, D in pollEvents).
void updateCamera(CameraHandle camera, const CameraInput& input);

Moves the target transform with the camera's controller, then eases the rendered transform toward it. The trackball eases along the orbit sphere, so the camera does not cut inside the orbit. The next matrices use the result.

You can drive a camera with your own input this way. Note that the camera you pass to beginFrame also gets the window's input in the same frame (D7: the engine owns the event loop).

Known limits

Cameras cannot be destroyed (D4), and handles of refused calls are never reused (B13). The engine reads the window events itself, so applications do not see them (D7). For the math (coordinate system, viewport flip, depth) see the guide Camera, coordinates and depth.
